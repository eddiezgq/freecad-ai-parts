# 设计任务书：云平台对象存储的冗余方案

**用在哪**　软件公司的云平台（REL-CLOUD、订阅 SUB-CLOUD）建在计算机厂案例 C 的 20 柜机房里，其中 **4 柜是存储柜**：
64 台存储节点，每台 12 块 16 TB 机械盘，共 768 块、裸容量 12.29 PB。

| 项目 | 要求 | 出处 |
|---|---|---|
| 三年后可用容量 | ≥ 4 PB（盘最多装到 80 %） | 订阅增长预测（案例 C） |
| 数据持久性 | 一个对象一年丢失的概率 ≤ 10⁻¹¹（“11 个 9”） | 对象存储常见承诺 |
| 整柜断电 / 断网 | 数据不丢、仍可读 | 机房只有 2 路供电，柜级故障要扛住 |
| 小文件（64 KB）读延迟 p99 | ≤ 30 ms | 网页、缩略图、配置；云服务 p99 ≤ 50 ms 的一部分 |
| 大文件（16 MB）读延迟 p99 | ≤ 250 ms | 模型文件、日志包、备份 |
| 坏盘修复 | ≤ 12 小时修回完整冗余；修复限速 2 GB/s（不挤占用户带宽） | 运维规程 |

盘的年故障率取 1.2 %（大规模机房统计的常见量级，示例值）。数据里约 15 % 是“热数据”。
