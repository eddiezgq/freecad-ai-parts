# 仿真：离散事件调度

自己写的固定优先级可抢占调度仿真（脚本里 `simulate`）：

- 每个作业的执行时间在 0.55 C 到 C 之间随机，5 % 的作业正好是最坏 C；每个作业加两次上下文切换；
- 电流环由 ADC 中断启动，晚一个中断延迟——和软件公司硬件在环测试台用的是**同一个分布**（基础 3 μs + 对数正态尾巴 + 2 % 总线争用，`sim/softsim.py`）；
- 用共享缓冲的作业在执行中随机一处进 6 μs 临界区，期间按优先级天花板协议升优先级；
- 跑 1000 个超周期（100 秒，电流环 2,000,000 次）。

| 任务 | 分析 R / μs | 仿真最坏 / μs | 仿真 / 分析 | 错过截止期 | 日志超时 3 倍：最坏 | 错过 |
|---|---|---|---|---|---|---|
| 电流环（FOC） | 23.6 | 21.9 | 93 % | 0 | 21.9 | 0 |
| 速度环 | 60.8 | 44.9 | 74 % | 0 | 44.3 | 0 |
| EtherCAT 过程数据 | 314.0 | 249.2 | 79 % | 0 | 249.1 | 0 |
| 位置环与插补 | 416.8 | 382.4 | 92 % | 0 | 376.9 | 0 |
| 诊断（编码器、温度、过流） | 2673.2 | 2350.3 | 88 % | 0 | 1988.2 | 0 |
| 日志与参数服务 | 23715.2 | 15824.5 | 67 % | 0 | 43915.1 | 0 |

1. **仿真最坏都不超过分析值**：分析假设所有最坏情况同时发生，是上界；电流环仿真最坏 21.9 μs，离分析值 23.6 μs 不远（中断延迟尾巴、最坏执行时间都碰上过）。
2. **初稿也仿了 200 个超周期**：电流环最坏 26.5 μs、错过截止期 **74** 次——低优先级任务在临界区里时 ADC 中断来了，电流环被挡。
   次数不多但伺服不允许，和第 3 步的分析一致。
3. **过载隔离**：让日志任务超时跑 3 倍（参数服务卡住），比它优先的 5 个任务一个都没错过截止期——固定优先级的好处，EDF 做不到这一点。
