# 总结

|  | 项目 | 结果 | 要求 | 出处 |
|---|---|---|---|---|
| ✓ | 计算书“不通过”项 | 0  | == 0 | 功能块计算器 |
| ✓ | 电路仿真核对通过率 | 100 % | == 100 | 计算书 |
| ✓ | 固件场景判定通过率 | 100 % | == 100 | Renode 仿真 |
| ✓ | 电气规则错误 | 0  | == 0 | KiCad DRC |
| ✓ | 未连接 | 0  | == 0 | KiCad DRC |
| ✓ | 可制造性检查 | 1  | == 1 | 电路板厂工艺能力 |
| ✓ | 贴片 + 功能测试不合格 | 0  | == 0 | AOI、功能测试 |
| ✓ | 最低 Cpk | 1.42  | >= 1.33 | 常用要求 |

1. **设计描述是源头**：原理图、PCB、物料清单、计算书、贴片坐标都从一份设计描述生成，改设计只改它（第 102–104 轮）。
2. **“通过”之外还有“待核对”“未知”**：7 项待核对、6 项未知——工具诚实地告诉你哪些还没验证，投产前要一项项清掉。
3. **板子没做出来，固件已经跑过**：17 个场景在虚拟硬件上过了，硬件到手只需要验证模型和实物的差别。
4. **设计和工厂接上**：KiCad 物料清单 = 工厂物料清单，坐标文件 = 贴片程序，计算出的公差 = 功能测试公差。
