## 一、目标

1. **把整个工厂定义成一张图**：15 个领域的对象类型和链接全部写进本体。有数据的“亮”，没有数据的标“待接入”。
2. **把已有的数据全部接进来**：总线历史、ERPNext 单据、PLM、计算服务、零件库、数字孪生、任务单。同步器能实时更新，也能从头重放；每个数值都能追到原始记录。
3. **能看、能找、能顺着走**：
   - 全局搜索；
   - 任何对象的 360 页：属性、关系图、时间线、来源；
   - 全貌地图；
   - 数字主线一路点通：现场设备 → 出厂零件 → 测量 → 设备 → 砂轮 → 同批 → 客户。

本期**不做**异常、追因、推演、动作、AI 代理（分别在 17B–17D），但为它们留好接口。

## 二、决定（待确认）

| 编号 | 决定 | 理由 |
|---|---|---|
| A1 | **本体定义文件**：`digital/ontology/` 下每个领域一个 yaml（共 15 个，加一个 `_core.yaml` 放中枢对象）。每个对象类型写明：编号规则、显示名（中英）、属性（类型、单位、是否时间序列、敏感级别 0–3）、链接类型（名称、目标、基数）、**数据成熟度**（已有 / ERPNext 可启用 / 待采集 / 教学模拟）、**映射规则**（来源、触发条件、字段映射、合并方式）。启动时校验：引用的对象类型必须存在、编号规则不冲突，否则报错 | 改本体不改代码；15 个领域一次定全 |
| A2 | **第一版对象类型 95 个**（见第三节清单），其中 34 个本期就有数据。其余的只建定义、出现在全貌地图上，没有数据就不建空表 | 全貌先立起来，缺口一目了然 |
| A3 | **存储**：在现有 Postgres 里新增 4 张表 | 不引入图数据库 |
| A4 | **同步器**：枢纽里一个后台线程。按 `bus_message.seq` 游标增量读消息、按规则更新对象和链接；ERPNext 单据走同一条路（桥接已把每张单据发成 `erp.doc` 消息）。PLM、计算服务、孪生、任务单这些不在总线上的数据，由各模块写库后发一条轻量的 `ont.touch` 通知，或者定时对账（每分钟）。**重放**：清空本体后从 seq = 0 重放，结果必须和实时同步一致（测试核对） | 事件溯源；一套逻辑两用 |
| A5 | **教学 / 生产分开**：对象主键里带 mode（与历史库一致），两种模式的本体互不可见 | 与现有规矩一致 |
| A6 | **血缘**：每个对象记它的来源消息序号列表（最近 50 条加首条）；每个属性记最后一次赋值的来源序号。360 页上每个数值旁有“来源”，点开看原始消息 | 可核查 |
| A7 | **身份解析**：映射文件里统一写别名规则，例如 BRG-6207 ↔ A-BRG-DG/6207 ↔ “中间轴轴承 B（6206）”这类部位名、设备号大小写、ERPNext 单号 ↔ 总线 corr。别名表可以查，搜索任何一个别名都能找到同一个对象 | 同一个东西只有一个对象 |
| A8 | **时间回看（本期只做对象级）**：对象表存当前状态；事件表存每次变化（属性旧值 → 新值，附来源序号）。“某时刻的样子”由事件回放算出。360 页的时间线就是这些事件。全厂级的任意时刻快照放到 17C（推演要用） | 先满足 360 页，不过度设计 |
| A9 | **本体 API**：<br>· `GET /api/ont/types`（本体定义、成熟度、对象数）；<br>· `GET /api/ont/search?q=`；<br>· `GET /api/ont/obj/{type}/{key}`（属性、来源、链接摘要）；<br>· `GET /api/ont/obj/{type}/{key}/graph?depth=1..3`；<br>· `GET /api/ont/obj/{type}/{key}/timeline`；<br>· `POST /api/ont/query`（按类型、属性条件、链接条件筛选对象集，最多 5000 个）；<br>· `GET /api/ont/lineage/{seq}`（原始消息）。<br>全部按角色和敏感级别过滤 | 17B–17D 和 AI 都只用这些接口 |
| A10 | **网页**：<br>① “厂情中枢”入口（工作区新增），本期只有**全貌地图**和**搜索**；<br>② **对象 360 页** `/ont/{type}/{key}`：属性卡（数值带单位和来源）、关系图（Cytoscape.js，逐跳展开、按领域着色、双击跳转）、时间线（按时间倒序，可按事件种类筛选）、“相关对象”列表；<br>③ 现有各页上的单号、序列号、设备号变成**对象卡片链接**（鼠标停留显示摘要，点击进入 360 页）。第一批覆盖首页、车间终端、订单与计划、质量、数字孪生 | 看得见、点得通 |
| A11 | **数字主线的两段补齐**：<br>① 零件加工经历：从 `machine.event` 的 cycle_start / cycle_end 建“零件实物 —加工于→ 工序任务”的链接，带开始、结束时间；并取当时最近一条 `machine.status` 的刀具剩余寿命，记在链接上；<br>② 总成装配：孪生出厂数据里的输出轴序列号，建“零件实物（输出轴）—装入→ 零件实物（减速器总成）”和“总成 —出厂为→ 现场设备”的链接 | 让故事一能一路点通 |
| A12 | **全貌地图**：15 个领域排成工厂的价值链布局，每块显示：对象类型数、有数据的类型数、对象总数、最近 24 小时变化数。颜色表示成熟度（深 = 已有，浅 = 可启用，虚线 = 待接入）。点领域展开它的对象类型，点类型进入对象列表（可筛选） | 一眼看到全貌和缺口 |
| A13 | **性能目标**（教学工厂规模：消息约 100 万条、对象约 5 万个）：<br>· 搜索小于 300 毫秒；360 页小于 500 毫秒；三跳关系图小于 1 秒；<br>· 增量同步延迟小于 5 秒；<br>· 从头重放 100 万条消息小于 10 分钟 | 可用 |
| A14 | **权限**：沿用现有角色。敏感级别 0 公开，1 内部，2 部门（人员、财务），3 受限（事故详情、老师注入的情景）。教学模式下学生看不到级别 3 的属性；本期的人员、财务领域没有数据，先定规则 | 治理从第一天就有 |

## 五、存储（新增 4 张表）

```
ont_object (mode, type, key)  主键；props jsonb；display text；domain text；updated_at；first_seq；src_seqs bigint[]；
                              prop_src jsonb（属性 → 来源序号）；search tsvector（编号、名称、别名）
ont_link   (mode, type, src_type, src_key, dst_type, dst_key, valid_from, valid_to)；props jsonb；src_seq
ont_event  (id, mode, type, key, ts, kind, changes jsonb, src_seq)              —— 时间线和回看
ont_alias  (mode, alias, type, key)                                               —— 身份解析
ont_state  (name, value)                                                          —— 同步游标、重放进度
```

索引：`ont_link` 按起点、终点各建一个；`ont_event` 按 (mode, type, key, ts)；搜索用 Postgres 全文检索加 `pg_trgm` 模糊匹配（编号常有部分输入）。

## 六、网页设计要点

- **全貌地图**（中枢首页，本期）：
  - 价值链横排：经营 → 市场客户 → 研发 → 供应链 → 计划 → 生产 → 质量 → 仓储 → 交付 → 服务；
  - 支撑面在下方：设备维护、安全环保、人员、能源、财务；
  - 每个领域一块，显示成熟度色和数字。
- **对象 360 页**：
  - 顶部：类型图标、编号、名称、状态色、所属领域；
  - 左栏：属性（分组显示，数值带单位，旁边有“来源”小图标）；
  - 中间：关系图，默认一跳，可展开到三跳，按领域着色；
  - 右栏：时间线；
  - 底部：相关对象表，按链接类型分组，可导出 CSV。
- **对象卡片**（嵌入各页）：鼠标停留弹出摘要（3–5 个关键属性、状态、最近事件），点击进入 360 页。
- 手机宽度可用：采集应用以后要在手机上用，360 页本期先做到能看。

## 八、施工顺序

1. 本体定义（15 个 yaml）、加载与校验；4 张表；单元测试。
2. 同步器核心：游标、规则执行、合并、事件、血缘、别名；先接总线消息（设备、质量、物流、erp.doc）。重放与一致性测试。
3. 接不在总线上的来源（PLM、计算服务、孪生、任务单、零件库、提议），加 `ont.touch` 通知和定时对账；数字主线两段补齐（A11）。
4. 本体 API 与权限过滤；性能压测。
5. 网页：全貌地图、搜索、360 页、对象卡片嵌入。
6. 帮助、方案、维护文档；服务器演练（真 ERPNext 下核对订单、工单链接），然后上线。

每步完成即上线（同步器第 2 步上线后先在后台跑，网页第 5 步才露出入口）。

### 2. 与细则的偏差（已按此施工）

1. **映射规则写在代码里，不写在 yaml 里（A1）**。映射要用上下文（当前装的是第几片砂轮、哪次停机还没恢复），写成 yaml 规则难读、难测。
   - yaml 只定义“有什么”（类型、属性、链接、成熟度、来源说明）。
   - `mappers.py` 定义“从哪来”。映射函数写了 yaml 里没有的属性或链接会直接报错，测试覆盖。
2. **不在总线上的数据只做每分钟对账，没有加 `ont.touch` 通知（A4）**。这类数据（设计提交、孪生、任务单……）一分钟的延迟可以接受，也不用改各模块代码。17B 需要更快时再加。
3. **成熟度多了一档“后续各期生成”**：异常、场景、动作记录、AI 运行这 4 类，17B–17D 才会产生，标“已有”会误导。
4. **存储是 5 张表**（多了 `ont_state` 放游标和上下文）。
   - 链接表没有 valid_from / valid_to，用链接时间 ts 和链接属性（开始、结束）表达。全厂级时间回看在 17C 做。
   - 搜索用 pg_trgm（模糊加包含），没有用全文检索：编号是主要搜索对象，全文分词对编号没有帮助。
5. **“相近”匹配只在别名、编号、包含都找不到时才做**：几十万对象时它要零点几秒，平时的搜索不该等它。
6. **路由**：对象列表 `/ont/{类型}`，360 页 `/ont/{类型}/{编号}`。
7. **对象卡片对所有角色有效**（入口仍只给厂长、计划员和老师）。学生点进去看到的内容按敏感级别过滤。
8. **对象卡片没有加的地方**：
   - 首页设备卡片和孪生页设备列表，本身就是整块可点的按钮，不能再嵌链接；
   - 孪生页改为在设备详情的标题、出厂工单、输出轴上加卡片。
9. **对象缓存超过 10 万个就清空**（都已写库，只是下次从库里读），控制枢纽内存。
