# 设备、隐藏问题与 AI 巡检

## 设备

21 台设备的保养、故障模式、功率、危险源、点检项都按清单接进 [设备维护](/maint)、[能源与环境](/energy)、[安全环保](/ehs)（都是示例值）。
机房设备（构建服务器、测试机群、测试台、压测平台、云平台宿主机等）不用人一直看着；研发工位要有人。
机房的主要危险源是**带电部件**和**气体灭火释放**（听到报警马上离开）；研发工位是久坐与用眼疲劳。一台“机房巡检与搬运机器人”换硬盘、送备件。

## 老师能注入的隐藏问题

在情景导演里能注入五种问题（学生看不到注入了什么，只能从数据追）：

| 问题 | 表现 | 对症措施 |
|---|---|---|
| 3 号构建服务器时钟漂移 | 只有 bld-3 跑的版本偶发失败多，测试通过率低 | 校正时钟同步，失败用例换机复跑，把依赖本机时钟的用例改掉 |
| 一次提交带进内存泄漏 | 之后所有过长稳压测的版本内存底线一直涨 | 对比前后版本定位那次提交、回滚，补长稳回归用例 |
| 2 号硬件在环测试台缓存配置错 | 只有 hil-2 测的中断延迟高 | 按标准配置重刷被测板，用信号源复核，重测 |
| A 区 2 号宿主机被“吵闹的邻居”占满 | 只有 cl-a2 上的订阅延迟高 | 迁走租户、加资源限额，受影响的订阅重新验收 |
| 错误配置推到 A 区 | A 区两台宿主机上的订阅错误率都高 | 回滚配置，配置发布加金丝雀检查 |

另有几项看着有理但不对症：失败测试重跑就发、加宿主机 / 构建服务器、放宽门禁和验收阈值、全员培训。

## AI 巡检（厂情中枢的规则，只在软件公司出现）

| 编号 | 规则 | 提示 |
|---|---|---|
| SW1 | 测试通过率偏低（按构建服务器） | 只在一台机器上失败：查它的时钟、磁盘 |
| SW2 | 长稳压测内存一直涨 | 看回收后底线，找第一个变坏的版本 |
| SW3 | 中断延迟偏高（按测试台） | 同一版本换台就正常：查测试台配置 |
| SW4 | 服务延迟偏高（按宿主机） | 查同机租户 |
| SW5 | 服务错误率偏高（按可用区） | 查最近推到这个区的配置 |
