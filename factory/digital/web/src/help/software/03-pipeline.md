# 发布流水线

| 步骤 | 在哪 | 做什么 |
|---|---|---|
| 合并与评审 | 研发工位（三个组） | 代码评审、合并到主干 |
| 编译与单元测试 | 构建服务器 bld-1 … bld-4 | 编译、跑几千个单元测试 |
| 集成测试 | 测试机群 | 模块之间连起来测 |
| 硬件在环测试 | 测试台 hil-1 … hil-3 | 实时 OS、机器人软件烧到真的关节驱动板、工控机上，测 2 万次中断的延迟 |
| 长稳压测 | 长稳压测平台 | 操作系统、云平台、数字工厂满负荷跑 4–12 小时，每 10 分钟记内存 |
| 安全扫描 | 安全扫描服务器 | 已知漏洞、许可证、代码静态扫描 |
| 发布门禁 | 发布服务器 | 测试通过率 ≥ 99.5 %、中断延迟不超上限、内存增长 ≤ 5 MB/h，不过不发 |
| 签名发布 | 发布服务器 | 用硬件安全模块签名，放进制品库 |

## “发布流水线与服务监控”页（发布流水线）

打开 [发布流水线与服务监控](/software-ops)，左边是最近的版本，可以按产品、按构建服务器筛；上方给出**按构建服务器的测试通过率**和**按测试台的中断延迟余量**。
点一个版本看：

- 流水线各步（绿 = 过，黄 = 有失败用例但没到门禁，红 = 门禁没过）；
- 用例数、失败数，其中“和时间有关的”（超时、定时器、证书有效期）有几个；
- 实时 OS / 机器人软件：**中断延迟分布**（对数坐标）；
- 操作系统 / 云平台 / 数字工厂：**长稳压测内存曲线**，红点是每次垃圾回收后的底线。

## 三个要会看的现象

| 现象 | 说明什么 | 不要做什么 |
|---|---|---|
| 只有一台构建服务器跑的版本偶发失败，换台机器重跑就过 | 那台机器的环境问题（时钟、磁盘、缓存） | “重跑一下就发”——偶发失败被盖住，下次在客户那里出 |
| 内存底线一直往上走 | 内存泄漏：找第一个变坏的版本，回滚那次提交 | 加内存、定时重启 |
| 只有一个测试台测的中断延迟高 | 测试台被测板的配置不对，不是内核 | 改内核调度参数去“凑”测试结果 |
