# 云平台运维与服务监控

## 机房

云平台机房向计算机厂买了 4 台整机柜（每台 16 台服务器，案例 C 的那种），分两个**可用区**：A 区 cl-a1、cl-a2，B 区 cl-b1、cl-b2。
一个区整个出问题，另一个区还能顶上。监控平台 mon-1 记每份订阅的延迟、错误率、可用性，值班室 7×24 小时。

## 订阅开通与验收

客户下一张云平台（或数字工厂）订阅，就在一台宿主机上开通，然后**验收 24 小时**：

| 指标 | 怎么算 | 要求 |
|---|---|---|
| 延迟 p99 | 每分钟 99 % 的请求在多少毫秒内返回，24 小时平均 | ≤ 50 ms |
| 错误率 | 出错请求占比，24 小时平均 | ≤ 0.1 % |
| 可用性 | 好的分钟（延迟 < 200 ms 且错误 < 1 %）占比 | ≥ 99.9 % |

## “发布流水线与服务监控”页（服务监控）

[发布流水线与服务监控](/software-ops) 切到“服务监控”：左边按宿主机筛，上方给出**按宿主机的延迟**和**按可用区的错误率**；点一份订阅看 24 小时延迟和错误率曲线。

| 现象 | 说明什么 | 对症 |
|---|---|---|
| 只有一台宿主机上的订阅慢，延迟一阵一阵地冲高 | 同机有别的租户把 CPU、磁盘占满（“吵闹的邻居”） | 迁走那个租户、加资源限额 |
| 一个可用区的两台宿主机错误率一起升高 | 最近推到这个区的配置有错 | 回滚配置；以后配置发布先推一台（金丝雀）、看错误率再推全区 |

加宿主机解决不了这两种：吵闹的邻居还在那台机器上，错误配置还在那个区。
