# 人员与排班

> 设备要有人才能开。一位关键操作工请假，他那台设备这一班就停；如果那台是瓶颈，整条线和订单都受影响。

## 这一页有什么

左栏“保障 → 人员”（班组长常用）。上方五个数：这一班出勤率、24 小时内排班缺口、单点依赖的设备、本周加班小时、车间“要有人”开没开。

| 标签 | 做什么 |
| --- | --- |
| 组织与员工 | 员工、部门、岗位、班次、会开的设备（人名都是虚构的） |
| 技能矩阵 | 员工 × 设备：学（学徒，速度六成）、熟（独立操作）、师（还能带学徒）；标红的列只有一个人会开 |
| 排班 | 早班、晚班，每一格是谁开这台设备；红：没人能开，黄：学徒带着开。点格子可以换人 |
| 出勤与加班 | 这一班谁在岗；记请假、迟到、缺勤（不记原因）；每人本周加班 |

员工、部门、岗位以 ERPNext 为准；技能、排班、出勤在平台。平台按排班算出每一班每台设备有没有能开它的人，发给仿真车间。

## 谁做什么

| 角色 | 能做 |
| --- | --- |
| 所有角色 | 看排班、技能矩阵 |
| 班组长 | 记出勤、考核通过；发起并批准调班 |
| 计划员、厂长 | 发起调班、加班顶班、技能培训 |
| 厂长 | 批准加班顶班、技能培训（花钱） |

请假、迟到的明细只有厂长、班组长和老师看得到，其他人只看到“在岗 / 不在岗”。

## 厂情中枢会报什么

| 规则 | 什么时候报 |
| --- | --- |
| H1 关键资质单点依赖 | 某台设备熟练以上只有一个人 |
| H2 排班缺口 | 未来 24 小时内，有岗位的设备某一班没人能开（瓶颈设备为严重） |
| H3 技能资质到期 | 30 天内到期为提示，已过期为警告 |
| H4 加班超限 | 某人本周加班超过 12 小时 |
| H5 出勤异常 | 近 7 天某班组缺勤率超过 10% |

## 处理方案（排班缺口）

| 方案 | 做什么 |
| --- | --- |
| A 不处理（对照） | 这一班这台设备停着 |
| B 调人顶岗 | 调一个熟练工来；他原来的岗位这一天空出来，推演里一起算 |
| C 学徒带教 | 学徒在班组长带着下开，速度六成 |
| D 加班顶班 | 另一班的熟练工加班来顶，原岗位不动；付加班费 |

推荐交期最好、花费最少的；同样好时不选学徒。单点依赖（H1）的方案是“安排技能培训”或“暂不处理”。

调人以后另一个格子变红了？那是调人的代价。可以再调一个，或改用加班顶班。

## 教学模式

- **车间要有人**：老师在这一页上方开关。关着时设备不需要人，和以前一样；重载实验 7 情景后关闭。
- 模拟的班组长每班开班时随机记少数人请假、迟到；带教到时自动考核通过。
- **实验 19** 排班与技能：缺人时的决策：“实验与任务 → 实验 19”。老师在实验页让某人下一个班请假。
- **两周情景**第 4 幕：磨床的熟练工请假。
