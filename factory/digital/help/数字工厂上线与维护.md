# 数字工厂上线与维护

数字工厂和学习平台在同一台服务器上，各自独立运行、各自自动部署。

## 一、网址与登录

| 网址 | 内容 | 谁用 |
|---|---|---|
| https://factory.wenquestrobotics.com | 数字工厂工作台（运营看板、角色工作区、3D 车间、AI 工厂助手、实验 7） | 学生、老师 |
| https://erp.wenquestrobotics.com | ERPNext 减速器厂 | 所有人用问渠账号自动登录：老师可操作，学生只读 |
| https://demo.wenquestrobotics.com | 企业版演示工厂（生产模式，第 9 轮） | 老师；企业来宾由老师在“企业成员”授权 |
| https://demo-erp.wenquestrobotics.com | 演示工厂的 ERPNext（同一套程序里的 demo 站点） | 同上 |

- **工作台用问渠账号登录**：在学习平台登录过的，打开工作台选角色就能进；没登录的点“用问渠账号登录”，登录后自动回来。
- **学生**：只有教学模式，可选计划员、工艺员、操作工、质检员。
- **老师**（学习平台里能建课的账号）：另有厂长角色、生产模式和教师控制台（左侧“教学 → 情景导演”页下方：重置实验 7、改仿真倍速、注入设备故障；第 19 轮起从原“经营与成本”页搬来）。
- **所有人进同一座工厂**，看同一份实时数据；实验 7 的得分按人分开记。
- **AI 工厂助手**：每人每小时最多问 30 次。
- **ERPNext 单点登录**（第 7 轮）：点工作台左侧“ERPNext”或直接打开 erp 网址，会自动用问渠账号登录（第一次自动开账号，账号名形如 `wq123@users.wenquestrobotics.com`）。老师有制造、库存、采购、销售、质量等经理权限；学生只能查看单据，改动都在工作台里做。登出 ERPNext 会被自动重新登录，要彻底退出请退出学习平台。
- **ERPNext 管理员**：用密码登录请打开 `https://erp.wenquestrobotics.com/login?manual=1`；用户名 `Administrator`，密码在服务器 `/opt/wenquest/factory/.env` 的 `ERP_ADMIN_PASSWORD`（安装时自动生成）。
- **设计发布不用装软件**：“设计与工艺”页的“在线设计”直接改参数并发布（服务器出 STEP、零件图、G 代码）。想用桌面 FreeCAD 的，在同一页下载“我的 FreeCAD 宏包”（已填好线上地址和本人凭证，7 天有效）。
- **班级（小组）工厂**（第 10 轮）：每个班或小组一座独立的教学工厂，网址 `https://<编号>.factory.wenquestrobotics.com`，ERPNext `https://<编号>.erp.wenquestrobotics.com`。**加一个班**：在仓库 `factory/deploy/classes.yaml` 里照样子加一行（编号、名称，可选任课老师的问渠账号编号），推送即可，部署时自动建好（约 10 分钟）。删掉一行只停掉这个班的工厂，数据保留。能建课的老师账号在任何班级工厂里都是厂长。
- **演示工厂**：和教学工厂同一批程序、一起部署；数据（历史库 `wq_demo`、ERPNext 站点 `demo`）完全分开。每次部署自动检查并补齐演示工厂的配置。
- **仿真与分析**（第 11 轮）：工作台左侧“专业软件 → 仿真与分析”（有限元强度、疲劳寿命）。所有工厂（公共、演示、各班）共用一个计算服务（容器 `cae`），一次算一个任务，其余排队；每个任务最多 5 分钟、约 20 万个单元，超了提示调大网格；计算容器内存上限 2.5 GB，超了只中止这一次计算。使用说明见《仿真与分析》。第 12 轮起“运动与动力”（多体动力学，MuJoCo）也由这个容器计算；机械臂模型（Menagerie 固定提交里的 UR5e、UR10e、FR3）在镜像构建时取进镜像，要加机型改 `deploy/fetch_menagerie.sh` 和 `digital/cae/mbd_models.py`。第 13 轮起“数控编程”也在这个容器里生成程序和仿真（不排队，每次在独立进程里做、限时 2 分钟），编程记录和计算任务存在一起；机床参数表在 `digital/cae/cam_post.py`（教学示意值，要按真机床改行程、最高转速、快移速度）。CI 测试另装独立的 G 代码解析器 pygcode 核对程序格式（只在测试环境，不进镜像）。使用说明见《数控编程》。第 14 轮起这个容器还算**温度场与热应力**（CalculiX，同有限元排队）、**设计优化**（Optuna 5.0，MIT；每次优化作为一个排队任务，最多 60 次分析、15 分钟，期间别人的有限元排在后面）和**平面拓扑优化**（自写 SIMP，排队、独立进程、限时 3 分钟，一般几秒）。使用说明见《仿真与分析》第五节和《设计优化》。第 15 轮起枢纽里多了**数字孪生**：客户现场模拟器跑在枢纽进程里（只在教学模式，`WQ_FIELD_SIM`；1 分钟 = 1 个现场日，`WQ_FIELD_DAYS_PER_MIN`；30 分钟没人看自动停，`WQ_FIELD_IDLE_MIN`），孪生数据在历史库的 twin、twin_log、twin_event、field_unit、field_clock、robot_twin 几张表里；真设备接入钥匙 `WQ_TWIN_DEVICE_KEY` 部署时自动生成在 `.env`。维修单经桥接写 ERPNext 的服务工单（Issue，自定义字段 wq_serial）。使用说明见《数字孪生》。第 16 轮起计算服务里还装了 **OpenFOAM**（发行版自带的 `openfoam` 软件包 v1912 和 `openmpi-bin`）算**流体分析**：同有限元排队，每个任务独立进程、限时 20 分钟、最多 30 万单元，多核时自动并行（最多 4 核）；算完删掉 OpenFOAM 算例目录，只留结果（每次约几 MB）。这个版本的 functionObject 有毛病（一加载就报 IOstream sha1 退出），所以平台只用它的网格和求解器，后处理全部自写——升级 OpenFOAM 时先跑 `tests/test_cfd.py` 的四道标准题。使用说明见《流体分析》。
- **每次部署后自动做“线上车间检查”**：在 GitHub 的部署记录里看“线上车间检查”注释——总线是否连上、教学模式有几台仿真设备在发数据，以及服务器上各容器的状态和仿真日志。

## 二、日常维护

登录服务器：`ssh deploy@<服务器 IP>`，然后 `cd /opt/wenquest/factory`。

| 要做的事 | 怎么做 |
|---|---|
| 更新数字工厂 | 改代码推送到 GitHub（改动 `factory/` 目录），自动测试、演练、部署 |
| 看运行状态 | `deploy/status.sh`：各容器状态、内存、历史库大小、两个网址的响应 |
| 看日志 | `docker compose -p wq-factory logs --tail 100 hub`（把 `hub` 换成 `sim`、`bridge`、`bus`、`erp-backend`） |
| 重启 | `deploy/update.sh`（不带参数：用现有版本重启，改了 `.env` 后也这样生效） |
| 查 ERPNext 管理员密码 | `grep ERP_ADMIN_PASSWORD .env` |
| 手动备份 | `deploy/backup.sh`；每天 03:30 随学习平台的备份自动执行 |
| 从备份恢复 | `deploy/restore.sh backups/<时间>`（先自动再备份一次当前数据） |
| 改 AI 次数、历史保留天数 | `.env` 里加 `WQ_AI_PER_HOUR=50` 或 `WQ_HISTORY_DAYS=60`，再运行 `deploy/update.sh` |
| 看有限元计算服务 | `docker compose -p wq-factory logs --tail 100 cae`；计算记录和结果在数据卷 `cae-data`（不进每日备份，可以重算） |
| 放宽有限元限制 | `.env` 里加 `WQ_CAE_TIME_LIMIT_S=600`、`WQ_CAE_MAX_ELEMENTS=400000`、`WQ_CAE_MEM=4g`（服务器内存要够），再运行 `deploy/update.sh` |
| 看厂情中枢（工厂本体）同步 | 厂情中枢页面底部的“同步状态”；或 `docker compose -p wq-factory logs --tail 100 hub \| grep 本体`。“落后”应接近 0，“跳过”的消息会写明序号和原因 |
| 重建厂情中枢本体 | 用厂长（教师）角色打开厂情中枢，点页面底部的“从头重建本体”（重建当前模式，教学和生产各点一次）。100 万条消息约 4 分钟，期间页面数据不全；不要在服务器上另开进程重放（会和枢纽里的同步线程抢游标） |
| 改本体定义（对象类型、属性、链接） | 改仓库 `factory/digital/ontology/*.yaml` 后推送；启动时校验，写错会在 hub 日志里写明哪个文件哪一项。加了新属性、新链接后，点一次“从头重建本体” |
| 看异常检测是否正常 | 厂情中枢 → 规则目录：页面顶部显示上一轮检测用时；出错的规则在那一行写明原因（只跳过这一条，不影响其他）。日志：`docker compose -p wq-factory logs --tail 100 hub \| grep 规则` |
| 调整规则阈值、开关 | 规则目录页上用厂长（教师）角色改，改动有记录。要改默认值，改仓库 `factory/digital/ontology/rules/*.yaml` 后推送 |
| 加一条新规则 | 在 `ontology/rules/<领域>.yaml` 写目录（编号、名称、严重度、负责角色、阈值、说明、处理提示、`fn`），在 `hub/ont/rules/<领域>.py` 写检测函数（`@rule("fn 名")`），在 `tests/test_rules.py` 写“该报 / 不该报”的测试（没有测试，测试会提醒） |
| 切换车间班次 | 教学模式：“情景导演”的教师控制台 → 车间班次。枢纽每 5 分钟把班次表重发给仿真车间一次（仿真车间重启后也会恢复） |
| 看推演、快照是否正常 | 厂情中枢 → 推演工作台 → “拍新快照”：教学模式应显示“精确”；显示“近似”说明仿真车间 5 秒内没回应，看 `docker compose -p wq-factory logs --tail 50 sim` |
| 动作卡在“执行中” | 经 ERPNext 执行的动作（紧急采购、分批交货）等桥接回执。超过几分钟没变，看桥接日志（`logs bridge`），失败原因也会显示在动作的记录里 |
| 改处理方案 | 仓库 `factory/digital/ontology/rules/playbooks.yaml`（哪类异常推演哪些方案、加班默认时长、维修加急比例、外协件数），推送后生效 |
| 看 AI 代理用的是哪个模型 | 浏览器打开 `https://factory.wenquestrobotics.com/api/health`，`"ai"` 一项：`claude`、`deepseek` 或 `rules`（没配模型，用规则版） |
| 给 AI 代理接模型 | 工厂的 `.env` 里没填的话，每次部署自动沿用学习平台 `.env` 里的 `ANTHROPIC_API_KEY`（Claude）或 `DEEPSEEK_API_KEY`。要单独指定：在 `/opt/wenquest/factory/.env` 加一行 `WQ_CLAUDE_KEY=<密钥>`（美国服务器）或 `WQ_DEEPSEEK_KEY=<密钥>`（国内服务器，只能用已备案模型），再运行 `deploy/update.sh`。用哪一家由 `WQ_AI_REGION` 决定：`cn`（国内服务器）只用 DeepSeek，出错也不换 Claude；其他地区 Claude 优先，出错时换 DeepSeek。管理员也可以在工作台“AI 设置”里改（国内部署 Claude 不可选） |
| 考一遍 AI 代理 | 用厂长（教师）身份：厂情中枢 → AI 运行记录 → 评测 → “现在跑一遍”，约几分钟，分数留档 |
| 厂情提醒发邮件 | 没填的话自动沿用学习平台的 `SMTP_*` 和 `MOODLE_NOREPLY_EMAIL`。单独指定：工厂 `.env` 里加 `WQ_SMTP_HOST`、`WQ_SMTP_PORT`、`WQ_SMTP_SECURE`（tls / ssl / none）、`WQ_SMTP_USER`、`WQ_SMTP_PASSWORD`、`WQ_MAIL_FROM`，再运行 `deploy/update.sh`。每个人在“通知设置”里填自己的邮箱 |
| 群机器人 | 厂长在网页“通知设置”里加（企业微信、钉钉、飞书），地址加密存在历史库 `notify_channel` 表；换了服务器密钥 `WQ_SECRET` 后要重新填 |
| 日报周报没出 | 只在生产模式定时（07:30 日报、周一 08:00 周报，工厂时区 `WQ_TZ`）。看 `logs hub \| grep 报告`；页面上可以手动补生成 |
| 复盘没出 | 要三个条件：异常已解决、它的动作执行完、受影响的工单都做完（或已过 14 天）。厂长可以在异常详情点“现在复盘” |
| 改评测题 | 仓库 `factory/digital/ontology/evals/*.yaml`，说明见同目录 README；推送时规则版要全对 |

## 三、看 Node-RED 数据流

Node-RED 不对外开放，要看时用 SSH 隧道：

1. 在服务器上查桥接容器的内部地址：
   ```bash
   docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}} {{end}}' wq-factory-bridge-1
   ```
   会显示一两个地址，任取一个，例如 `172.19.0.7`。
2. 在自己电脑上（PowerShell 或终端）：
   ```bash
   ssh -L 1880:172.19.0.7:1880 deploy@<服务器 IP>
   ```
3. 保持这个窗口不关，浏览器打开 `http://localhost:1880`。

只想看有没有出错，直接在服务器上看桥接日志：`docker compose -p wq-factory logs --tail 100 bridge`。

## 四、服务器内存不够时

第一次部署会先检查空闲内存（至少 3 GB）。不够时部署停下，提示升级服务器，学习平台不受影响。升级方法：

1. DigitalOcean 控制台 → Droplets → 选这台服务器 → **Resize**。
2. 选 **CPU and RAM only**，选 16 GB 的规格，点 Resize（服务器会关机几分钟，数据不丢）。
3. 服务器开机后，学习平台自动恢复；到 GitHub → Actions → **Digital factory 数字工厂部署** → **Run workflow** 重新部署数字工厂。

| 历史库里的 `shift_calendar`、`sim_snapshot`、`scenario`、`action`、`action_log` 表 | 班次表、快照（每 15 分钟一张，保留 30 天）、推演场景、动作及其记录。随历史库每日备份 |
| 仓库 `.github/workflows/factory.yml` | 自动测试、演练、部署 |
| 服务器 `/opt/wenquest/factory/.env` | 全部密码与设置（只在服务器上，自己另存一份） |
| 服务器 `/opt/wenquest/factory/backups/` | 最近 7 天的本机备份；配了 Spaces 时同时传到 `wenquest-factory/` |

## 六、本地版（学校机房，第 30 轮）

学校没有外网、上不了线上数字工厂时，用本地版在机房的一台电脑（教师机）上用 Docker 起整座工厂，学生用浏览器连教师机。
给机房管理员的完整说明在仓库 `factory/local/README.md`（要什么电脑、怎么装 Docker、怎么启动、学生怎么连、停止与清空、没有外网时用 U 盘导入镜像、怎么更新）。

| 要做的 | Windows（PowerShell，在仓库根目录） | macOS / Linux |
|---|---|---|
| 启动 | `.\factory\local\start.ps1` | `factory/local/start.sh` |
| 停止（数据保留） | `.\factory\local\stop.ps1` | `factory/local/stop.sh` |
| 清空重来 | `.\factory\local\stop.ps1 -Reset` | `factory/local/stop.sh --reset` |
| 不联网、用已导入的镜像启动 | `.\factory\local\start.ps1 -Offline` | `factory/local/start.sh --offline` |
| 按工厂清单建车间 | `-Plant 清单.yaml` | `--plant 清单.yaml` |

- **缺省**：教学模式、演示工厂“问渠减速器厂”、模拟 ERPNext（端口 8091），计算服务 `cae` 一起启动；不挂 FreeCAD 零件库（那是 freecad-ai-parts 的企业功能）。
- **第一次启动**生成 `factory/digital/.env`：登录签名密钥 `WQ_SECRET` 随机生成，`WQ_EDITION=local`，并生成**老师密码** `WQ_TEACHER_PASSWORD`（只在启动时显示一次，以后看 `.env`）。
- **登录**：本地版填名字登录。学生只能选学生岗位（计划员、工艺员、操作工、质检员、售后、安全员、维修工、班组长），只有教学模式；
  勾“我是老师”并输老师密码才能当厂长、用生产模式、教师控制台和情景导演。老师密码连续输错 5 次锁 10 分钟。线上服务器（问渠账号登录）不受影响。
- **学生连接**：`http://<教师机 IP>:8100`。教师机防火墙要放行 8100、9001（浏览器的实时数据）、8091（模拟 ERPNext）。
  页面里数据总线、ERPNext 的地址会自动换成学生打开时用的 IP。登录页标题旁边显示“本地版”（`/api/config` 的 `edition` 为 `local`）。
- **CI**：工厂工作流的“本地版能起来”作业每次在 GitHub 的机器上运行 `start.sh`，检查健康、学生与老师分开登录、跑完整闭环的 1–3 段，再 `stop.sh --reset`。

## 七、帮助视频（第 30 轮）

工作台“帮助”里的操作视频由工厂工作流的“录帮助视频”作业自动录：在本地版里按 `factory/digital/tools/help_videos.py` 的剧本操作，
字幕叠在画面上，不配音。推送到 main 时发布到 GitHub Release `help-videos`（文件 `help-videos-teach.tar.gz`）；
构建数字工厂镜像时取最新的一份放进 `/app/digital/help-media`（企业版的几段取 freecad-ai-parts 的 Release）。取不到就不带，帮助照常可用。
界面改了，下次推送会重录；要立刻用上新视频，等“录帮助视频”作业发布后再到 Actions 里重跑一次部署。

本机录（要 `pip install playwright==1.55.0`、`python -m playwright install chromium`，先用本地版起工厂）：

```bash
python factory/digital/tools/help_videos.py --hub http://localhost:8100 --edition teach --out help-media \
  --teacher-password "$(sed -n 's/^WQ_TEACHER_PASSWORD=//p' factory/digital/.env)"
```
