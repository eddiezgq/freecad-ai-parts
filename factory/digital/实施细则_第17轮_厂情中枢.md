## 一、目标

现在的首页和 AI 工厂助手能告诉人“出了什么事”（外圆磨床停了、轴承库存不够），但三个问题还要靠人自己去翻：

1. **追因**：这件事牵连到谁？磨床停机 → 排在它前面的是哪几张工单 → 属于哪几张订单 → 哪张会延期、延几天、多花多少钱。
2. **推演**：如果这样处理会怎样？让精车改走数控车床 A、周六加一个班、紧急采购轴承……每种做法把车间“快进”算一遍，看交期和成本。
3. **建议**：把几种做法按“准时交付、成本、风险”排好序，说清理由；人点“采纳”后才变成提议，确认后执行，和现在的提议流程相同。

这是“AI 原生”最该体现的地方：数据全在总线上，平台主动把来龙去脉理清、把方案算好，人只做决定。生产模式下是厂长的日常工具；教学模式下学生先自己分析，再和中枢比对（实验 15）。

## 二、决定（待确认）

| 编号 | 决定 | 理由 |
|---|---|---|
| Z1 | **新页“厂情中枢”**（工作区，厂长、计划员默认可见）。三栏：左边是**异常清单**（自动从总线识别：停机、超差、缺料、交期风险、成本偏差，按严重程度排序）；中间是选中异常的**因果链**（图：事件 → 设备 → 工单 → 订单 → 交期 / 成本，每一环都能点开看原始数据）；右边是**推演与建议** | 一页看全一件事的来龙去脉 |
| Z2 | **追因用规则 + 图，不靠大模型猜**：从历史库按单号、设备、物料把消息连起来（停机事件 → 该设备排队的工序 → 工单 → 销售订单 → 交期；缺料 → MRP 净需求 → 受影响工单；超差 → 工序 → 设备 → 刀具 / 砂轮寿命 → 同批零件）。每条连线写明依据（主题、单号、消息编号）。大模型只负责把链条讲成人话（国内 DeepSeek，美国 Claude；没配就用规则文字） | 结论可核查；没有大模型也能用 |
| Z3 | **推演用仿真车间的“快进副本”**：仿真车间新增“状态快照”指令，把当前所有设备、队列、在制品、工单、AGV、班次原样发出；枢纽用同一套仿真引擎在后台起一个副本，换上不同的处理方案，用虚拟时钟快进（不影响真车间和真数据），算出每张订单的预计完工时间、设备负荷、加班工时和成本。每次推演几秒到十几秒 | 用的是车间本身的模型，不另写一套估算 |
| Z4 | **可选的处理方案（第一期）**：① 改派：工序改走同类设备（精车 B → A，磨外圆只有一台则不可选）；② 加班：某台设备或全线加班 N 小时 / 周六加班；③ 调序：某张工单插到队首；④ 紧急采购：缺料提前到货（多付加急费）；⑤ 外协：某道工序外协 N 件（多付外协费、加运输天数）；⑥ 什么都不做（作对照）。方案可以组合，每次最多比 4 个 | 覆盖车间最常用的几种应对；参数都来自工厂主数据 |
| Z5 | **建议排序**：先保准时交付（延期订单数、延期天数），再比成本（加班费、加急费、外协费、产能损失），最后看风险（设备连续满负荷、单点依赖）。每条建议附“为什么”（推演数字）和“代价”。AI 只排序和解释，不发明方案；数字全部来自推演 | 可解释、可复算 |
| Z6 | **采纳 = 起草提议**：点“采纳”生成现有的 ai.proposal（改派、调序走 MES，加班写班次，紧急采购和外协经桥接写 ERPNext 采购单），人确认后才执行。教学模式下学生的提议照常评分 | 沿用现有“人确认才执行”的规矩 |
| Z7 | **主动提醒**：后台每 5 分钟（可设）扫一遍异常，新的严重异常在首页“AI 今日简报”上方出一条“厂情中枢：××停机，影响 2 张订单，已备好 3 个方案”，点进去就是中枢页 | 让人第一时间看到 |
| Z8 | **复盘**：每次异常处理完，自动记一条“异常 → 采纳的方案 → 实际结果（真车间后来怎样）”，可以对比推演和实际的差距，用来校准（例如实际完工比推演晚，说明标准工时偏乐观） | 推演好不好，用事后数据检验 |
| Z9 | **教学：实验 15“车间异常的追因、推演与决策”**：老师在控制台注入停机 / 缺料 / 质量问题 → 学生先在首页、车间终端、订单页手工追因，写出因果链 → 在中枢里推演 3 种方案，选一种并说明理由 → 采纳、确认、看执行结果 → 和中枢的建议比较。指导书、报告模板、课程接口 | 每个工具都要能进课 |
| Z10 | **企业版**：生产模式下读真实 ERPNext 和真设备数据；推演用的仿真副本按工厂主数据（设备、工艺路线、标准工时）建，演示工厂（第 9 轮）里可演示 | 企业版的卖点之一 |

## 四、施工顺序

1. 仿真车间“状态快照”指令；枢纽里的快进副本（同一引擎、虚拟时钟），“什么都不做”推演与真车间对比测试。
2. 异常识别与追因（规则 + 历史库），因果链数据结构与测试。
3. 处理方案（改派、加班、调序、紧急采购、外协）与推演对比；建议排序。
4. “厂情中枢”网页：清单、因果链图、推演对比（表 + 甘特图）、建议、采纳 → 提议。
5. 主动提醒、复盘；AI 讲解（规则先写，有模型时改写）。
6. 实验 15、帮助、方案更新、服务器演练、验收；补拍宣传镜头 f20（厂情中枢）。

每步完成即上线。

## 五、不在这一轮

- 自动执行（无人确认就改派、下单）：始终要人确认。
- 跨工厂、多基地的排产优化；有限能力排程的数学优化（APS）——本轮只比较人提出或平台列出的几种方案，不做全局最优求解。
- 供应商侧数据（供应商的真实交期、库存）：紧急采购的到货天数按主数据和用户填写。
