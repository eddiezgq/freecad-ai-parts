# ADR-0061：典型应用全流程演练与工厂接收新产品（M13）

- 状态：已接受（2026-10-07，项目负责人要求用库里的零件做几个典型应用，机器人和缝纫机为主，试遍设计、工艺、仿真、分析、ERP、MRP、MES 与厂情中枢）
- 日期：2026-10-07
- 补充：ADR-0056、ADR-0058、ADR-0059、ADR-0060

## 背景

FreeCAD 一侧（选型、布局、校验、BOM、九个分析模块、发布到工厂）与工厂一侧（设计、工艺、计算、ERP、MRP、MES、孪生、
厂情中枢）都已能单独运行，但从没有用一个真实产品从头走到尾。摸底（2026-10-07）发现工厂只认内置演示产品 WQR-105：

- 物料、BOM、工艺路线、工序、工作站写在代码里（`factory/factory/data.py`），MRP、MES、看板、厂情中枢都查这份数据；
- 没有任何地方新建 ERP 物料（问渠第 8 轮定的是“物料不存在时提示，不自动建物料”）；
- FreeCAD 发布来的 `cad.release` 只存档，没有下游；
- MRP 只给 SH-301 开工单；模拟 ERPNext 对代码数据以外的物料做库存移动会出错。

## 决策

1. **三个典型应用**，参数取公开资料（注明出处），零件全部取自零件库：
   - 协作机器人关节（UR5e 一类：负载 5 kg、臂展 850 mm、各关节最高 180°/s）：肩、肘、腕关节选伺服电机 + 谐波减速器 + 驱动器
   - SCARA 机器人（大臂、小臂两个关节）
   - 工业直驱平缝机（JUKI DDL-9000C 一类：最高 5000 针/分、针杆行程 35 mm、主轴直联 400 W 伺服）：主轴电机选型、针杆曲柄滑块动力学、上轴临界转速
   每个应用走：需求 → 动力学 → 选型 → 布局与校验 → BOM → 有限元 / 疲劳 / 热 / 拓扑优化 / 数控编程 / 流体 / 孪生（用得上的）→ 发布到工厂
   → 转为生产物料 → 工艺规程 → MRP → 工单 → MES 车间执行 → 厂情中枢（异常、推演、动作、简报、报告）。
2. **工厂接收新产品**（经人确认，不自动建物料，与第 8 轮原则一致）：
   - 发布的方案带上自制件（定制件）清单：编号、名称、材料、数量、毛坯、工艺路线（只能用工厂现有的工序与工作站）；
   - 工厂“CAD 方案”页“转为生产物料”：先给出预览（要建的物料、供应商、BOM、工序、采购件交期），生成一条需确认的提议；
     确认后由桥接在 ERPNext 建供应商、物料、BOM（与现有提议执行同一条路），成功后产品登记进工厂的产品登记表；
   - 产品登记表（枢纽数据库）在枢纽启动和登记时并入工厂主数据，MRP、MES、看板、厂情中枢照原样使用；
   - MRP 对登记产品给全部自制件和产品本身开工单，采购件按登记的交期排；交期没给的标“待确认”，不估；
   - 模拟 ERPNext 对新物料的库存移动按物料主数据的单位处理。
3. **数据规则照旧**：零件参数只用零件库里有出处的；应用的需求参数注明公开资料出处；孪生没有现场数据时用动力学工况
   生成运行记录，标明“仿真工况，不是现场数据”。
4. **演练脚本与报告**：`examples/apps/` 每个应用一个脚本，FreeCAD 一侧不开界面也能跑（直接调核心与分析模块）；
   工厂一侧对本地工厂走 HTTP。全流程跑完生成报告；CI `factory-local` 作业对本地工厂跑一遍工厂一侧。

## 后果

- 工厂不再只认一个演示产品；企业自己的产品经确认即可进入 ERP、MRP、MES
- 新产品的工序受工厂现有工序、工作站限制（以后另议扩充）
- 演练暴露的问题按“不行就略过，关键是跑通”的原则：能修的修，修不了的写进报告
