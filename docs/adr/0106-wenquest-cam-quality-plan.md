## 背景

2026-11-18 项目负责人定：“我们要出就是精品，没有进度要求”；“对照商业版，好好先把短板补齐，好好看看界面合适否”。

## 一、逐项对照

“商业版常见水平”取上面几家的共同水平（Fusion 基础版大体是下限，NX、hyperMILL 是上限）。

### 6. 我们已有、商业版少见的（保留并做深）

- AI 起草工艺，程序逐项核对，超出刀具样本范围的不采用；
- 安全底线写死：整机仿真不通过不出程序；程序回读与仿真刀路逐段比对；程序头带仿真指纹；
- 中英对照，验证手册（每个数来自自动测试）；
- 价格与教学：免费版能学完车削和三轴编程。

## 二、界面审查

现在的面板是“一张长表单从上填到下”，像网页表单，不像工程软件。看商业 CAM 的共同做法，问题有六个：

1. **没有加工树**：工序不是文档里的对象，不能选中、改、复制、调顺序、单独算。
2. **零件只能读或手填**：不能在三维视图里点选面、边、孔。
3. **一个工序的参数没有地方改**：只有表格里的 vc、f、ap；进退刀、安全高度、余量、分层都看不到。
4. **结果只在文字里**：没有回放，不能单步看刀具怎么走、在哪一行撞。
5. **程序看不到**：存成文件才看得到程序，不能对照刀路看是哪一行。
6. **刀具、机床只是文件**：没有管理窗口，看不到刀的样子、机床的样子。

目标界面（照 FreeCAD CAM 与商业 CAM 的共同习惯，用 FreeCAD 自己的模型树和任务面板，学过任何一家 CAM 的人都能上手）：

- **模型树里的加工树**：作业 → 装夹（机床、毛坯、坐标系、夹具）→ 工序（刀具、参数、刀路），每个都是文档对象，存在 FCStd 里；右键：编辑、复制、上移下移、单独计算、隐藏刀路。
- **工序的任务面板**：分页签——几何（在视图里点选）、刀具（从刀具库选，显示外形）、切削参数（显示样本范围，超出变红）、高度与进退刀、分层与余量；改完当场重算该工序。
- **回放条**（视图下方）：播放 / 暂停 / 单步 / 速度 / 时间轴；当前程序行高亮；碰撞、过切处在时间轴和视图里标红，点一下跳过去。
- **程序窗口**：正式程序与刀路联动——点程序行，视图里刀具跳到那里；点刀路，程序跳到那一行。
- **刀具库窗口、机床窗口**：建刀、改刀，显示外形；机床显示三维模型，可点动各轴，行程到头变红。
- **检查清单**：按装夹、工序归类，点一条跳到对应工序和程序行。
- AI 起草放在作业的右键菜单里：起草出来的工序就是加工树里的对象，人逐个确认（确认前标“草稿”）。

### Q1 界面骨架：施工细则（2026-11-19）

**数据放在文档里**（`freecad_addon/fc/cam_objects.py`，FeaturePython，存进 FCStd，FreeCAD CAM 的 Job / Operation 也是这么做的）：

### Q2 仿真与回放：施工细则（2026-11-19）

**决定**
- 铣削的三维材料去除用**三向 dexel**（沿 X、Y、Z 三组平行射线，每根射线存材料区间），新模块 `analysis/cam/dexel.py`，纯 numpy。
  刀具按回转体处理（平底、球头、牛鼻、钻头），刀轴方向任意，所以 3+2、五轴的去除也能算。
  三轴竖直刀具的现有高度图仿真（`simulate_mill`）**保留不动**：它对三轴是精确的、快，已有的检查和指纹不变；
  加一道对照题：三轴程序的 dexel 结果与高度图结果在网格精度内一致。dexel 用在：五轴 / 3+2 的去除与过切、回放画面、色差图。
- 车削的半径网格对回转体是精确的，保留；车铣（C2）再接 dexel。
- 机床部件支持**三角网格**（STL，ASCII / 二进制都读）：`collide.Mesh`，三角形包围盒树粗筛，再逐个三角形用现有 GJK 精判；
  机床文件里部件写 `{"type": "mesh", "file": "xxx.stl"}`（相对机床文件所在目录）。
- 车刀刀杆按 **ISO 5608 代号**生成外形（例如 `PCLNR 2525 M 12`）：刀杆高 h、宽 b、全长 l1 都来自代号（长度字母按 ISO 5608 表）；
  刀尖到刀杆侧面的偏距 f 各家不同，来自刀具数据 `holder.f_mm`，没有就**刀头一段报“未知”**（不编数值），刀杆柄部照查。

  内孔刀方位 2）。精车刀路做刀尖圆弧补偿（在问渠CAM 里算好，不靠 G41/G42，任何系统都一样）：
  外圆、端面上假想刀尖与实际接触点重合，路径不变；倒角、锥面、圆弧上按 rε 偏置。不补偿时倒角会残留，仿真能查出来。

  并每隔若干段存一份材料状态，拖动时间轴时从最近一份往后补算。界面 `freecad_addon/gui/cam_replay.py`：视图下方停靠一条回放条
  （播放 / 暂停 / 单步前后 / 速度 / 时间轴，时间轴上事件标红，点一下跳过去），旁边程序窗口（正式程序，当前行高亮；点行跳到那一段，点视图里的刀路跳到那一行）；
  视图里刀具（刀柄 + 刀具外形）随回放移动，铣削的在制毛坯按 Z 向 dexel 画成网格面，车削的按半径网格旋成回转面。

  在公差内的是绿；在视图里给在制毛坯表面上色，旁边一条色标。结论进检查清单（过切 = 错误，残留超过精加工余量 = 提示）。

### Q3c 三维曲面：评估报告与完成记录（2026-11-19）

**怎么评**：FreeCAD 1.0.2 自带的 3D Surface（平行，OCL 投影）、Waterline（等高，OCL）出 R3 球头刀刀路，行距 2、等高层距 0.5；
高度图仿真加了球头刀，按刀路算出加工后的表面，与零件模型（弦高 0.002 三角化后按竖直方向取顶面）逐格比，网格 0.05，只看零件中间一块。
理论残留高度见 `freecad_addon/fc/cam_surface_eval.py`；数据由 `scripts/cam_surface_eval.py` 生成，存 `docs/verification/cam/surface-eval.json`。

| 零件 | 刀路 | 采样 | 量出残留（最大） | 理论 | 过切 |
| --- | --- | --- | --- | --- | --- |
| 平面 | 平行 | 0.05 | 0.163 | 0.172 | 0 |
| 斜面 20°（沿行距方向） | 平行 | 0.05 | 0.202 | 0.208 | 0.0005 |
| 斜面 20° | 等高 | 0.25 | 0.180 | 0.096 | 0 |
| 斜面 20° | 等高 | 0.10 | 0.124 | 0.096 | 0 |
| 斜面 20° | 等高 | 0.05 | 0.107 | 0.096 | 0 |
| 球冠顶部（坡度 ≤ 6°） | 平行 | 0.05 | 0.162 | ≤ 0.174 | 0.003 |
| 球冠侧面（坡度约 23°） | 等高 | 0.05 | 0.077 | 0.078 | 0.004 |
| 自由曲面 | 平行 | 0.05 | 0.173 | —（平面 0.172） | 0.002 |
| 自由曲面 | 等高 | 0.05 | 3.06 | — | 0.005 |

（量出的残留比理论小一点：网格 0.05，残留顶点落在两个格心之间。过切 ≤ 0.005，是三角化与网格的误差量级。）

**结论：够用，接进来。**
1. 平行精铣（3D Surface）各种曲面都与理论一致、不过切，直接用。
2. 等高精铣（Waterline）要两个设置：多层模式（缺省的单层模式只出 3 段，等于没加工）；采样间距要小——等高线位置按采样间距取整，
   残留约多出 采样 × tan θ（0.25 时 20° 斜面上残留 0.18，近一倍）。问渠固定用 0.05。
3. 等高不管平缓的地方（自由曲面上留了 3 mm），只用于陡面；平缓的地方用平行。问渠不自动替人判断，两种都放在“新建工序”里。
4. 慢：球冠侧面等高刀路 5 万多段，FreeCAD 算 3 分多钟；三维比对、回放都按段走，回放检查点原来每 20 段存一份毛坯，
   十几万段的曲面程序会耗尽内存——已改为最多 60 份。

**做了什么**：加工树加“曲面平行精铣”“曲面等高精铣”（新建工序；最大的球头刀，行距按目标残留高度 0.01 算 s = 2√(2Rh − h²)，
等高层距取 s·sin45°，采样 0.05）；高度图仿真支持球头刀；评估模块与报告；标准题：球头刀平面残留（CAM-47），FreeCAD 测试对理论值（平行平面、平行斜面、等高斜面）。

**与细则的偏差**：自写曲面刀路不需要另开一段（FreeCAD 的够用）。曲面零件的规则起草不自动加曲面工序（看不出哪些面要精铣、用哪种），由人在“新建工序”里加。
曲面开粗用已有的自适应开粗 / 型腔分层；残料清角对曲面不适用（只认型腔底面）。

2. 直线 `L X+.. Y+.. Z+.. R0 F..`，快移 `FMAX`（只管本段）；换刀 `TOOL CALL 号 Z S转速`（刀长补偿由刀具表自动生效，不写 G43）；
   `M3`、`M8` 跟在第一段移动上；工序结束 `L Z+安全高度 R0 FMAX M9`、`M5`；程序结束 `M140 MB MAX`（沿刀具轴退到行程尽头）、`M30`。
3. 钻孔：配置 `cycles.drill` 关（缺省）时与其他系统一样展开成直线段；打开时写 `CYCL DEF 200 DRILLING`（Q200 安全距离 2、Q201 深度、
   Q206 进给、Q202 每次进给深度（一次钻到底时等于孔深）、Q203 表面坐标 = R 平面 − 2、Q204 第二安全距离 = 安全高度 − Q203），
   每个孔 `L X Y R0 FMAX M99` 调用。攻丝一律 `CYCL DEF 207 RIGID TAPPING`（Q239 螺距），同样 `M99` 调用。
4. 配置开关：小数位、注释（ascii / utf8 / none）、冷却（flood / mist / off）、选择停（`M1`）、程序结束 M30 / M02、钻孔循环、
   子程序（每道工序一个 `LBL 号` … `LBL 0`，主程序 `CALL LBL 号`，标签放在 `M30` 之后、`END PGM` 之前）都管用；
   换刀前后动作只认对话格式回读认得的写法（`M140 MB MAX`、单独的 M 代码、`L … R0 FMAX` 直线），认不得的配置拒收、写明原因；
   `sequence`、`program.percent`、车削项对海德汉没有意义，打开就拒收。
5. 安全底线照旧：回读时把对话格式换回 ISO（`L` → G00 / G01，`TOOL CALL` → T M06 S，`CYCL DEF 200` + `M99` → G98 G81 / G83，
   `CYCL DEF 207` + `M99` → M29 + G98 G84，`CALL LBL` 展开，`M140 MB MAX` → G91 G28 Z0），与整机仿真刀路逐段比，对不上不出；
   换刀前后动作也换成 ISO 进整机仿真。程序头写“未经实机验证”。
6. 不做的（写明原因）：`CC` / `C` 圆弧——刀路中间格式里没有圆弧（FreeCAD 的圆弧在进中间格式前已按弦高 ≤ 0.002 mm 拆成直线），
   其他系统同样只写直线；以后中间格式加了圆弧，各家一起加。`CYCL DEF 203`——我们没有断屑、递减进给这些动作，200 就够。
   钻孔循环的“提前停止距离”由数控系统定，仿真按退到上次深度上方 0.5 mm 算，首件单段确认（加提示）。

**交付物**：`analysis/cam/klartext.py`（写好后按配置加工、回读换回 ISO、换刀动作检查）、内置配置 `posts/heidenhain.json`、
postproc 写海德汉铣、标准题（每个开关一题 + 内置配置一题 + 不合格配置一题）、验证手册加一题、帮助文件加一节。

**验收**：铣的标准程序（开槽、钻孔含啄钻、攻丝）在每个开关下都能出正式程序，回读与整机仿真刀路逐段一致，程序时间与 FANUC 一样

### C2 3+2 定位与车铣复合：施工细则（2026-11-19）

Q1–Q5 只差 Q5c 实机验证（等合作厂），按 ADR-0104 C2 开始。分三段，先做 C2a。

**C2a 3+2 定位铣**（摇篮式 AC：示例机床 EX-5AX-AC）
1. **倾斜面**：铣削作业里加“装夹 / 倾斜面”：在三维视图点零件上的一个平面，得到工作平面（原点、法向 = 刀轴、X 方向，工件坐标）；
   也可以输入两个角（绕 X、绕 Z）。一次装夹里可以有多个倾斜面，每个倾斜面下面挂工序。
2. **刀路**：把零件按工作平面转到“法向朝 +Z”，在平面坐标里用现有 2.5 轴刀路（FreeCAD CAM 的型腔、外轮廓、面铣、自适应；问渠自算的孔、倒角）；
   刀路中间格式的工序加 `frame`（原点、X、Z 方向，工件坐标）。
3. **仿真**：平面坐标 → 工件坐标；整机仿真按工序的刀轴方向逆解（回转轴在这道工序里不动，`kinematics.inverse` 带刀轴方向），
   查超程、碰撞；材料去除用 dexel（三方向，任意刀轴，Q2 已有）。
4. **后处理**（两种输出，配置选）：
