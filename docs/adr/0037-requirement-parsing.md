# ADR-0037：一句话需求的解析与端到端演示的可复现性

- 状态：已接受（2026-10-01，项目负责人授权先按最优方案决定，可推翻）
- 日期：2026-10-01

## 背景

M5 的验收标准是“从一句需求到 BOM 的演示可重复跑通”。现在的“一句话 → 结构化需求”这一步，由外部客户端或对话面板里的 LLM 自由完成，有两个问题：

- 不可复现：同一句话，每次解析的结果可能不同，演示无法“重复跑通”
- 没有确定性核对：LLM 可能把“峰值 50”当成连续扭矩，或者自行补出用户没说的指标

实施细则允许 `engine/` 的需求解析模块调用 LLM，但输出必须经 schema 校验才能进入下一步。

## 决策

### 1. 需求解析模块 `engine/requirement_parse.py`

分工与规格书抽取（ADR-0021）相同：LLM 只报“原文里说了什么”，代码逐项核对。

1. **LLM 的输出**（工具调用，提示词版本 `requirement/1`）：对每个识别到的指标给出
   - 字段名（取自需求 schema）
   - 数值与原文中的单位写法（如 `25`、`N·m`；枚举字段给枚举值）
   - 原文引用：需求原句中的一段连续文字
2. **代码核对**，不通过的项不采用，并在结果中列出原因：
   - 字段名必须是需求 schema 中的字段
   - 引用必须是原句的子串（忽略空白）
   - 数值必须以完整数字的形式出现在引用中
   - 单位换算到标准单位，用 `ingest.units.to_standard`（pint）。需求解析是用户数据的入口，和规格书一样经由这唯一的换算入口；引擎的校验函数仍然是纯函数
   - 枚举值（供电类型、总线协议）必须由引用中的关键词支持（如“EtherCAT”“单相”“220 V”）
3. **缺失与默认**
   - 输出连续扭矩、输出转速是必填项；缺少或核对不通过时，不猜，结果为“需要追问”，列出要问用户的问题
   - 安全系数没说时取 1.2（ADR-0008），结果中注明“按默认值”
   - 其他字段没说就不写（不写 0 或估计值）
4. **输出**：结构化需求（经 `requirement.schema.json` 校验）、每个字段的依据（引用）、被拒的项与原因、追问问题

### 2. 录制与回放

- 与规格书抽取相同的录制机制：请求哈希为键，存放在 `tests/recordings/requirement/`
- 测试只用录制回放，或标明 `simulated` 的模拟响应，不联网
- 真实录制需要密钥，由人在本地运行 `--record`

### 3. 端到端演示 `python -m mcp_server.e2e`

1. 输入一句话需求（经解析，默认用录制回放），或结构化需求 JSON
2. 经 MCP 工具依次执行：
   - `compose_chain` 选出排第一的方案
   - 按 `joint_layout` 的流程布局并消除干涉（复用 `layout_demo`）
   - `verify_system`（`use_layout`）
   - 导出 BOM（CSV、JSON）、系统 JSON、URDF；有 FreeCAD 时加截图
3. 输出写到指定目录，并附一份 `README.md` 汇总：需求依据、方案、校验结论、文件清单
4. **可复现**：同一输入、同一组件库，除截图外的输出逐字节相同。截图依赖渲染环境，只校验它是合法 PNG

### 4. 样例输出

- `examples/joint2/` 存放从 `examples/joint2-requirement.json` 生成的全部输出（不含截图）
- 测试重新生成并逐字节比对，样例过期就会失败
- 样例改变时由 PR 一并更新，评审时能看到差异

## 理由

- 解析沿用“LLM 报原文、代码核对”的模式，使得演示可复现、每个需求值都有原文依据，也不会把用户没说的指标当成需求
- 不新增 MCP 工具：外部客户端和面板里的 LLM 本身就能解析需求，架构文档的 10 个工具不变。解析模块供端到端演示和非 LLM 客户端使用；是否开放 REST 接口，等机器人学院有需要时再定
- 考虑过直接用正则解析：中文、英文、单位写法组合太多，规则会很快膨胀；LLM 加核对更稳

## 影响

- 新增 `engine/requirement_parse.py`、`tests/recordings/requirement/`、`mcp_server/e2e.py`、`examples/joint2/`
- 真实需求解析的录制，与 #31 的规格书抽取评测一起由人在本地完成
