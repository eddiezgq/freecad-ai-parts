# ADR-0030：方案解释的生成方式

- 状态：已接受（2026-10-01，项目负责人授权先按最优方案决定，可推翻）
- 日期：2026-10-01

## 背景

issue #54 要求由校验结果生成中英文说明：给出结论，以及每个 fail、warn、unknown 的原因、涉及的端口和余量。架构上，说明要可追溯、可复现；LLM 只做理解和表达，不参与判断。

## 决策

1. **确定性模板**（`engine.explain`）
   - 说明完全由校验结果生成，不调用 LLM
   - 同一份校验结果，每次生成的文字都相同
2. **结构**：中英文相同
   - 整体结论一句
   - 非 pass 项按 fail、unknown、warn 的顺序逐项列出：项目名、状态、每条对应判定的原因、端口、测量值与限值、余量
   - 最后列出通过项和不适用项（附原因）
3. **语言**
   - 中文的原因直接取自校验判定，是完整的说明
   - 英文的原因用各项校验的英文描述，加上数值和端口
   - 判定的逐字英文措辞，由 M4a 的 MCP 工具交给 LLM，在结构化结果上润色；润色不得改动结论、数值和端口
4. **候选方案**（`explain_candidates`）：每个方案先列组成，再列排序依据（ADR-0029 的各项），然后是该方案的校验说明

## 理由

模板生成的说明与校验结果一一对应，便于审计和测试。逐条维护中英两套判定措辞成本高，交给 LLM 在结构化数据上润色更合适，因为结构化数据本身已经包含了全部判断依据。

## 影响

M4a 的工具输出要同时提供结构化校验结果和模板说明，LLM 润色只针对说明文字。
