# ADR-0021：LLM 结构化抽取的流程与输出格式

- 状态：已接受（2026-10-01，项目负责人授权先按最优方案决定，可推翻）
- 日期：2026-10-01

## 背景

M2 issue #29 要从规格书中抽取参数与端口，交给复核队列（#30）和准确率评测（#31）。架构已定：LLM 负责理解与提议，凡影响“能不能用”的判断由确定性代码校验。需要先定下抽取结果的格式（新 schema）和 LLM 与代码的分工，再写代码。

抽取结果不能直接用组件 schema 表示：组件要求的端口坐标系（frame）、包络分段等是几何布置，规格书上通常没有；为了通过组件 schema 去填这些值就是编造。

## 决策

1. **新增 `schema/extraction.schema.json`（抽取结果）**，不改组件 schema。一份抽取结果对应一份来源文档，包含：
   - `document`：来源文档 id（`data/sources.yaml` 登记的 `src-…`）、文件 sha256、页数
   - `category`、`vendor`、`model`（可缺，缺了进复核）
   - `extractor`：模型名、提示词版本、响应 id
   - `items`：通过代码核对的抽取项。每项有目标位置 `target`、参数值对象 `value`（`method` 固定为 `extracted`，`reviewed` 固定为 `false`，来源须有 `doc` 与 `page`）、规格书原文 `printed`（叫法、数值文字、单位），以及 `issues`（需要复核员注意的问题，如单位换算、工况缺失）
   - `rejected`：没通过核对的提议及原因，供复核和错误分类
   - `missing_key_fields`：品类关键字段（`x-key-fields`）中没抽到的
2. **目标位置 `target`** 三种写法：
   - `params/<参数名>`：品类参数
   - `ports/<端口 id>/<规格字段>`：品类标准端口的规格
   - `dims/<尺寸>`：整体尺寸，只用于之后生成包络：`overall_length_mm`、`body_length_mm`（电机不含轴伸）、`outer_diameter_mm`、`square_mm`、`width_mm`、`height_mm`、`depth_mm`
   
   某个 target 是否属于该品类、值是否符合该字段的 schema（枚举、取值范围），由代码按品类 schema 与端口类型 schema 校验（schema 只约束写法）。
3. **LLM 与代码的分工**
   - LLM 只做理解：读 #28 提取的分页文本与表格，按给定的字段清单（target、含义、标准单位、枚举值）提议抽取项，每项给出印出的数值文字、印出的单位、页码、原文引用、工况、置信度。数值按印出的写，不换算单位；枚举值映射到给定的规范值
   - 代码逐项核对，任一不过即放入 `rejected`：target 属于该品类；页码存在；原文引用确实出现在该页（忽略空白）且包含印出的数值文字；单位能被 `ingest/units.py` 换算到 target 的标准单位；换算后的值符合该字段的 schema；同一 target 出现互相矛盾的值时全部拒绝
   - 抽取结果一律 `reviewed: false`，不直接入库；关键字段与低置信度项进复核队列（#30）
4. **包络**：由 `dims` 与端口尺寸按品类规则生成（电机：方法兰 × 机身长 + 轴伸圆柱；减速器：外径或方形壳体 × 总长；驱动器：宽 × 高 × 深；轴承：外径 × 宽），在复核阶段（#30）实现；端口坐标系按品类的约定布置，由复核员确认，不由 LLM 生成
5. **LLM 调用**：Anthropic Messages API，强制工具调用输出结构化结果，temperature 0；模型默认 `claude-sonnet-5-5`，可用环境变量 `FAP_LLM_MODEL` 覆盖；密钥只从环境变量 `ANTHROPIC_API_KEY` 或本地 `.env`（不入 git）读取。`anthropic` 作为可选依赖（`.[llm]`）
6. **录制与回放**：请求内容（模型、提示词版本、提示文本、工具定义）的规范 JSON 取 sha256 作为键，响应存为 `tests/recordings/llm/<键>.json`。测试只用回放客户端，找不到录制即失败，不联网。录制由项目负责人用本地密钥运行 `--record` 生成后提交
   - 在拿到真实录制之前，测试用由模拟规格书答案生成的**模拟响应**（文件中标明 `"simulated": true`），只用来检验代码核对流程；准确率评测（#31）必须用真实录制，模拟响应不计入
7. **提示词版本**：提示词或字段清单变化时提升 `prompt_version`，旧录制随之失效，需重新录制

## 理由

- 让 LLM 只报“印出来的是什么”，换算、范围、枚举校验都交给已测试的确定性代码，错误可定位、可复现
- 原文引用核对能挡住大部分凭空编造的数值（编造的数在原文里找不到）
- 抽取结果与组件分开：抽取阶段只记录读到的东西，缺什么就缺什么，复核阶段再补全并入库，不在任何环节编造几何数据
- 录制回放让测试稳定、免费、不需要密钥；模拟响应明确标记，避免把它当成真实准确率

## 影响

- 新增 schema 文件与样例；本 ADR 与 schema 单独成 PR，抽取代码（#29）随后另开 PR
- 复核队列（#30）的输入是抽取结果；包络生成与端口布置在 #30 实现
- 模拟规格书答案（#27）的整体尺寸行将补充对应的 `dims/` 目标，供 #31 对照
- 首次真实录制需要项目负责人的 API 密钥与一次本地运行
