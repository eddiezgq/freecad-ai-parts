# ADR-0099：企业用 AI 快速建自己的零件库（问渠 CAD 0.3，先做缝纫机企业）

- 状态：已接受（2026-11-17，项目负责人：“好，开始”）
- 日期：2026-11-17
- 补充：ADR-0040（公开目录数据）、ADR-0044（人工确认）、ADR-0055（企业私有库）、ADR-0092（外部零件库）
- 来源：问渠 CAD 仓库 `docs/细则-0.3.md` 的方向草稿（项目负责人 2026-11-17 定：零件库是问渠 CAD 下一步重点；先做缝纫机企业，机器人企业第二；在本仓库做，由有零件库修改权限的会话负责）

## 背景

- M9（ADR-0055）做完了企业私有库、就地补数据、导入规格书、新建零件向导，但验收 #238 一直没做。
- 平缝机应用例（`examples/apps/out/lockstitch/`）卡在零件库缺数据：选型上限那条路因为库里最大的驱动器 SGD7S-2R8A 带不动而失败；零件库没有轴承，数字孪生无零件可算；上轴 LS-101 等自制件不在零件库里。
- 企业手里现成的资料有三种：厂商产品目录（PDF / Excel，一份几十个型号）、ERP 导出的物料表（Excel，几百上千行）、自己的三维模型（STEP，自制件为主）。现在只能一个型号一个型号地导规格书，太慢。
- 问渠 CAD 安装时发现本仓库的三个问题（问渠 CAD `docs/细则-0.2.md` 末节）：Windows 保留文件名、带布局重新校验漏了供电条件、SGD7S-2R8A 的输入相数待核实。

### 2. 三条进料通道

共同的写入规则（沿用 ADR-0040、0044、0055）：每个值有依据——资料 id + 页码原文，或“从模型测量”+ 模型文件的 SHA-256 + 测量方法，或人工录入 + 录入人；缺数据不写字段（不写 null、0、估计值）；校验遇缺数据为“待确认”。AI 只提议，代码核对，人确认后才写入企业库；每次写入记进 `history.jsonl`。

**A. 产品目录成批抽取**（扩充现有的导入规格书）

- 现在：一次指定一个目标型号。改为：先由代码找出目录里的型号表（表头一行是型号、各行是参数），列出全部型号让人勾选，再逐型号抽取、核对。AI 调用按型号分开（与现有单型号抽取同一套提示词和核对规则），失败的型号单独列出，不影响别的型号。
- 核对：每个值要能在原文的那一列里找到（页码、行名、列名），单位按 pint 换算；同一行对所有型号的单位和叫法一致。
- 模拟目录用现有的 `ingest/synthetic_multi.py`；真实目录只用 `data/sources.yaml` 里登记过、`terms_checked: true` 的。

**B. 物料表**（新）

- 输入：Excel / CSV，表头和列序各企业不同。
- AI 做：认列（物料编码、名称、规格型号、厂商、数量、单位、类别）、给每行提议品类。
- 代码做：
  - 按认出的列读全表，规范化型号写法（全半角、空格、大小写、常见分隔符）；
  - 查重：同一厂商 + 规范化型号、或同一物料编码出现多次的，合并成一条并列出原行号；
  - 对应公共库与企业库：厂商 + 型号命中已有组件的，直接对应；
  - 品类核对：AI 提议的品类与型号的特征对不上（例如型号像轴承代号却分成电机）的，标“待人确认”；
  - 生成“待补数据”清单，交给完整度报告。
- 人做：确认列的对应、分类结果和对应关系；“未能分类”的行写明原因。
- 物料表本身不进企业库（可能含价格、供应商等商业信息），企业库只存由它建的组件和一行来源说明（文件名 + SHA-256）。

**C. 三维模型测量**（新，自制件为主）

- 先用问渠 CAD 修好的检查几何查模型有效（无效模型不测，告诉人哪里坏了）。
- 代码从几何上量：外形包络（长宽高、最大回转直径）、体积与质量（材料取材料库，按密度算；没给材料就只给体积）、回转件的轴段（共轴圆柱面按轴向位置排成段：直径、长度、起止位置）、孔位（同轴孔组的分度圆直径、孔数、孔径）。复用 `assist/features.py` 的面识别。
- AI 只做两件事：判断零件类型（轴、曲柄、凸轮、支架……）、给端口命名的建议；尺寸一律由代码量，AI 不给尺寸。
- 测量值的依据写“从模型测量”、模型文件 SHA-256、测量方法与容差。

### 3. 新品类（schema 单独 PR）

| 品类 | 用途 | 必填 | 说明 |
| --- | --- | --- | --- |
| `custom_part` 自制件 | 企业自己设计加工的轴、曲柄、凸轮、支架 | 图号 / 名称、外形包络、模型文件 SHA-256 | 参数按测量结果（轴段、孔位、质量）；材料可选，填了就按材料库算质量 |
| `purchased_part` 通用外购件 | 同步带与带轮、电磁铁、传感器、机针、旋梭等 | 厂商、型号、外形包络 | 关键参数按需填；先能进 BOM、能做干涉检查，不参加 C1–C11 的性能校验 |
| `stepper_motor` 步进电机 | 自动缝纫设备常用 | 与伺服电机同一套端口（轴、法兰、电源） | 保持转矩、额定电流、步距角、相数、法兰尺寸；与驱动器的匹配校验按现有规则扩充（相数、电流） |

- 写法（41.2 schema PR，2026-11-17）：
  - 自制件：`vendor` 写企业名、`model` 写图号、`license` 新增 `enterprise`（企业自有数据，只在企业库）；参数 `part_kind`（shaft、crank、cam、
    eccentric、gear、pulley、lever、link、bracket、housing、plate、pin、bushing、other）、`material`（材料库 id）、`mass_kg`、`volume_mm3`、
    `surface_area_mm2`、包络尺寸；回转件轴段 `segment_<n>_diameter_mm / _length_mm / _start_mm`，同轴孔组 `holes_<n>_pcd_mm / _diameter_mm / _count`。
  - 通用外购件：`part_kind` 写通用叫法，其余参数按需（名称照全仓库规则带单位后缀，值仍是带依据的参数值对象）。
  - 步进电机：`holding_torque_nm`、`rated_current_a`、`step_angle_deg`、`phases`、`rotor_inertia_kgm2`、`mass_kg` 等；端口轴、安装法兰、动力输入必有。
  - 参数值的 `method` 新增 `measured`：从企业三维模型上由代码测量，`source.doc` 是登记的模型文件（企业库 `sources.yaml`，带 SHA-256），
    `source.note` 写测量方法与容差。
  - 端口：原来每个组件至少 1 个端口；自制件、通用外购件可以没有（先能进 BOM、做干涉检查），其余品类照旧至少 1 个。
- 轴承已有品类，补数据即可。
- 新品类的组件可以只在企业库里；公共库只收登记过、核过条款的公开目录数据（ADR-0040），自制件永远不进公共库。
- 旧数据与 golden 题不受影响：新品类是新增，现有 6 个品类的 schema 不改。

### 4. 库的完整度报告（新）

- 对每个组件：缺哪些字段 → 缺了会让哪些校验变成“待确认”（例如缺法兰孔位 → C3 待确认）。“字段 ↔ 校验”的对应由代码从规则里取，不手写清单。
- 排序：按影响的校验项数和涉及的方案数排，告诉企业先补哪几个；每条带“去哪找”（规格书的哪一类表、或从模型量）。
- 在问渠 CAD 的零件库面板里看，也能导出 Excel。

### 5. 示范缝纫机企业（虚构，明确标注）

- 一份约 40 行的物料表（Excel），按工业直驱平缝机（以 JUKI DDL-9000C 一类为对象）的结构列：伺服电机、驱动器、轴承、同步带与带轮、电磁铁、传感器、机针、旋梭、上轴、曲柄、凸轮、紧固件等。表头与每一页标明“示范数据，非真实企业”；企业名虚构。
- 外购件参数只来自 `data/sources.yaml` 里登记过、`terms_checked: true` 的公开资料。轴承目录（NSK 或 NTN）先核条款再登记，条款不允许就不收，在完整度报告里列为缺数据。新登记的来源各附官方下载地址与 SHA-256，不转存文档与 CAD（ADR-0040、0092）。
- 自制件的三维模型：上轴 LS-101 用仓库里已有的 `examples/apps/out/lockstitch/LS-101.step`；其他自制件（曲柄、凸轮）按问渠《机械设计》与《缝纫机设计与制造》的示意数据在 FreeCAD 里建，同样标注“示意数据”。
- 放 `examples/enterprise-lockstitch/`：物料表、模型、建库脚本、结果（企业库目录、完整度报告、用时记录）。

### 6. 三个遗留问题（41.0）

1. **Windows 保留文件名**：`factory/designs/{ctrl-ls,drv-joint,drv-joint-b}/kicad/aux.kicad_sch`。在生成工具（`factory/designs/tools/`）里把“辅助电源”这一页的文件名从 `aux` 改为 `auxpwr`，重新生成三套 KiCad 工程与输出，查没有别处引用旧名；加一个测试：仓库里不得有 Windows 保留名（CON、PRN、AUX、NUL、COM1–9、LPT1–9，不论扩展名）。`factory/designs` 是与问渠仓库共有的路径（`factory/SYNC.md`），问渠仓库同一轮跟着改，`tools/factory_sync.py` 报 0 差异——问渠那边按它的规矩写进《实施细则》、经项目负责人确认后再改。CI 里 Windows 作业的“不检出 factory/”绕法改完后保留（防再犯），但测试会先拦住。
2. **带布局重新校验漏了供电条件**：校验用的需求由 AI 组装，AI 漏了 `supply`，“驱动器只支持三相、需求是单相”就没进校验报告。改为由代码保证：会话里记下这次选型确认过的需求；`verify_system` / `export_system` 收到的系统需求如果少了会话需求里已有的条件（供电、环境温度、外形限制、总线等），代码按会话需求补上，并在报告里注明“按原需求带入：供电”；AI 给的值与会话需求矛盾时以会话需求为准并提示。加测试：复现这次的情形（AI 的系统需求不带 `supply`），报告里必须有 C9 的结论。
3. **SGD7S-2R8A 输入相数**：库里录为 3（规格书第 62 页“Three-Phase, 200 VAC”）。对照同一本手册（已登记的 `src-yaskawa-sgd7s-ethercat-manual`，核 SHA-256）查是否有单相 200 V 适用于该型号的明文。
   有：现有 schema 的 `phases` 只能填一个值，所以加第二个供电端口（单相，电压范围与降额等条件按原文写进 `condition`，附页码原文），
   C9 按“任一供电端口满足需求即通过”判；C9 现在若只看第一个供电端口，就一并改 C9 并补测试（规则改动，先写进本 ADR 的施工记录）。
   没有：保持三相。结论写进 41.1 的验收记录。不凭“小功率型号常见单相可用”的经验补。

  3. 就地补数据：查 SGD7S-2R8A 能否单相 200 V（第 6 节第 3 条）；

- **41.6（示范缝纫机企业，项目负责人在问渠 CAD 里做）**：
  - 示范物料表导入后，每行都有分类结论（进了哪个品类，或“未能分类”及原因），查重结果正确，完整度报告列出缺的数据；

  - 企业库里每个值都能追到依据；记下建库用时；
  - 测试照旧全过（本仓库 ruff、pytest；问渠 CAD 的 `tests-wqcad.ps1`）。

## 理由

- 先验收 M9：后面三条通道都写进企业库，企业库本身要先在真实环境（Windows、问渠 CAD、真实 AI、真实规格书）里证明可用。
- 三条通道对准企业现成的资料，不要求企业先整理数据；AI 做“认”和“分”，量和核由代码做，与全仓库“凡影响能不能用的判断由确定性代码做”一致。
- 物料表不进库：价格、供应商是商业信息，企业库只需要由它建的组件。
- 自制件尺寸只从模型量：AI 读不准几何尺寸，也无从核对；从 B-rep 量出来的值可复现、可追溯。
- 先做缝纫机：台州产业对口，且平缝机例子的失败点正好是缺数据，补完有明确的前后对照。

## 影响

- schema：新增三个品类文件和对应端口（单独 PR）；现有品类不改。

- 问渠 CAD：每步验收时由问渠 CAD 那边改 `ai-wqcad.ps1` 的固定提交并在项目负责人电脑上重装工作台。

- 不做：真实企业的资料（等有试点企业）；厂商 CAD 模型的下载与转存；拍照建模（2026-11-17 讨论后项目负责人定：不做）。
