# ADR-0033：干涉检查中的轴穿过通道，以及 worker 的启动方式

- 状态：已接受（2026-10-01，项目负责人授权先按最优方案决定，可推翻）
- 日期：2026-10-01
- 补充：ADR-0032

## 背景

按 ADR-0032 实现干涉检查（#84）时，发现两个问题。

**问题一：轴穿过转接板被报为干涉。**

- golden 正确用例 `m200-adapters-*` 中，电机轴穿过转接板，进入套筒和减速器
- 转接板的包络是实心长方体，没有 `cyl_female` 端口，“减去孔”的办法覆盖不到
- 结果是每个带转接板的正确方案都会报干涉（重叠体积就是轴在板内的部分，π·5.5²·10 ≈ 950 mm³）
- 实物上，转接板中间一定有供轴穿过的孔，但包络 schema 不能表达孔，也不能编造孔径

**问题二：`freecadcmd` 不能用来跑 worker。**

- `freecadcmd` 运行脚本时会占用标准输入，worker 收不到 JSON 行请求
- 直接用 FreeCAD 内带的 Python，把 FreeCAD 模块目录加进 `PYTHONPATH`，可以正常导入 FreeCAD，也可以在 Xvfb 下截图
- 但必须先 `import FreeCAD` 再导入 `Part` 等模块，否则会段错误

## 决策

### 1. 轴的穿过通道

**定义。** 对场景中每个圆柱配合，找出轴伸段：轴所在实例的包络中，与轴端口同轴、同径、终点在轴端的圆柱段。通道是这样一个圆柱：

- 直径取轴的名义直径，再加位置容差（缺省 0.01 mm）
- 沿配合轴向，从轴伸段起点到孔口
- 找不到轴伸段时不设通道
- 孔口在轴伸段起点之前（轴全部在孔内）时也不设通道

**怎样计重叠。** 轴所在实例与同一刚性组中其他实例（配合孔所在实例除外）的重叠：

- 落在通道内的部分，不计为干涉
- 这部分单独列为 `pass_through`，内容是需要有通孔的实例、穿过它的轴、重叠体积
- 附注“V1 包络未建模通孔，请确认该零件有供轴穿过的孔”，交给人核对
- 通道外的剩余重叠超过阈值，仍然计为干涉

**例外范围只到这里。**

- 不同刚性组的实例不享受例外（例如还没摆开的驱动器）
- 配合孔所在实例也不享受例外：轴伸过长、穿出已知深度的孔底，仍然报干涉

### 2. worker 的启动方式

- worker 用 FreeCAD 内带的 Python 以 `python -m freecad_addon.fc.worker` 启动，`PYTHONPATH` 包含 FreeCAD 模块目录与本仓库
- FreeCAD 和 Qt 会向标准输出打印信息，所以回复行加前缀 `@@FAP@@ `，客户端只认带前缀的行
- 路径由 `FAP_FREECAD_PYTHON`、`FAP_FREECAD_LIB` 配置
  - 缺省用 `scripts/fetch_freecad.sh` 的解包位置
  - Linux 下没有 `DISPLAY` 时，用 `xvfb-run` 启动（24 位色深，以便着色渲染）
- `freecad_addon/fc/` 中凡是导入 `Part` 的模块，都先导入 `FreeCAD`

### 3. 截图

- 按品类着色，哑光材质：正对视线的面不被高光冲淡
- 每步操作后处理界面事件，保证视角和适配在保存前生效

## 理由

- **轴穿过通道只覆盖一种明确的情形**：轴从根部到孔口之间，穿过同一刚性组的零件。实物中这些零件必然开孔，所以这样做既不编造孔径，也把需要核对的地方明确列给人
- **按实例对整体豁免太宽**：比如把直接配合的实例对整体豁免，会漏掉轴伸过长、法兰错位等真实干涉
- **继续用 `freecadcmd` 不可行**：只能改用文件或套接字通信，复杂度更高；内带 Python 已经核实可用

## 影响

- `check_interference` 的结果新增 `pass_through` 列表
- 带转接板的方案在干涉检查中通过，同时提示核对转接板是否有通孔
- worker 不再依赖 `freecadcmd`
