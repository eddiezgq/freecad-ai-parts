# ADR-0029：链路模板与候选方案排序

- 状态：已接受（2026-10-01，项目负责人授权先按最优方案决定，可推翻）
- 日期：2026-10-01

## 背景

M3 要求从组件库中按需求组合出校验过的方案并排序（issue #53），实施细则要求把排序规则写入 ADR。

## 决策

1. **链路模板**（`engine.compose.compose_chain`）
   - 方案由电机、减速器、驱动器组成：电机轴接减速器输入孔，电机法兰接减速器电机法兰，驱动器接电机的动力与编码器
   - 轴径不同时，从组件库找一个内孔等于轴径、外圆等于孔径的轴套；分度圆不同时，找一块两侧分度圆分别匹配的适配法兰板（两种朝向都试）
   - 找不到转接件的组合直接跳过
   - 轴承暂不纳入模板：需求中还没有描述支撑方式的字段，待 M4 需求解析时再定
2. **筛选**
   - 减速器额定扭矩不够、所需电机转速超过电机最高转速的组合，先按确定会判 fail 的条件剔除
   - 其余组合全部过 11 项校验
   - 默认只保留整体为 pass 或 warn 的方案；调用方可以要求同时返回 unknown（数据缺失、待确认）的方案
   - 结果中永远没有 fail
3. **排序**（依次比较）
   1. 整体结论：pass 在前，warn 次之，unknown 最后
   2. 转接件数量少的在前：直连更可靠，装配也更简单
   3. warn 项数量少的在前
   4. 总质量（各组件 `mass_kg` 之和）轻的在前：关节越轻越好；有组件缺质量时排在后面
   5. 最小余量大的在前：只看 C4、C5、C7 中“不大于限值”类判定的余量
   6. 组件 id 的字典序：保证结果确定
4. **去重**：电机、减速器、转接件都相同的方案，只保留排序最前的驱动器，让前 N 个方案彼此有区别
5. **纯函数**：组件库由调用方传入（golden fixtures、知识库查询结果等），引擎不读数据库

## 理由

- 先看结论、再看转接件和告警，是工程上“能不能用、好不好装”的自然顺序
- 机器人关节通常对质量敏感，所以质量排在余量之前
- 余量过大意味着选型偏大，因此余量只作为后面的比较项

## 影响

- 排序规则以后可能按用户偏好调整（如成本优先），届时另写 ADR，并在需求中增加偏好字段
- 方案解释（#54）会说明每个方案排在这个位置的原因
