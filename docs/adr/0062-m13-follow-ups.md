# ADR-0062：典型应用演练暴露问题的收尾（M14）

- 状态：已接受（2026-10-07，项目负责人看完 M13 演练报告后说“继续”）
- 日期：2026-10-07
- 补充：ADR-0056、ADR-0061

## 背景

M13 演练（ADR-0061）三个应用从需求走到车间完工，但暴露了几处问题。零件库缺数据的（大驱动器、谐波减速器的分度圆、
输入侧惯量、额定寿命，采购交期与价格）按项目负责人的意见留给企业以后补，不在本阶段。其余几处是我们自己的问题：

1. **平缝机动力学的结论说得不对**。演练按“主轴恒速 5000 rpm”算出针杆机构驱动扭矩峰值 2.5 N·m、均方根 1.58 N·m，
   直接当作电机的连续 / 峰值扭矩选型，并在报告里把与实机 400 W 的差距归因于“没加平衡块”。问题有两处：
   - 恒速时往复质量的动能一转之内有增有减，惯性力矩一转做功为零。电机要不要“出”这份扭矩取决于速度环：
     速度环刚、转速几乎不变时，惯性力矩全由电机电流承担，均方根 1.58 N·m 是发热的上限；
     允许转速波动时，转子、手轮等的转动惯量吸收它（《机械原理》飞轮设计），电机只承担平均扭矩（缝制阻力等）。
     原报告只给了上限，没说明这是上限；
   - 平衡块平衡的是机座上的惯性力（振动），恒速下它的离心力过转轴，不改变驱动扭矩，“没加平衡块”的归因是错的。
   另外，模型里针杆（滑块）的质量是按杆宽、杆厚取的示意值，不是实物数据。缝纫机真正决定电机的还有缝制阻力
   （零件库与样本都没有）和每条缝线起停时的加速。
2. **方案改版进 ERP 会重复建 BOM**。桥接执行“转为生产物料”时供应商、物料已有就跳过，BOM 每次都新建；
   同一版本再执行一次就多一张 BOM，新版本也没有把旧 BOM 撤下默认。
3. **自制件的粗基准与装夹由演练脚本代写**。方案只带工艺路线，工厂 AI 评审要求第一道机加工工序写粗基准；
   演练脚本按常规写法补上，等于替工艺员做了决定，而这本该由设计（知道基准面）或工艺员给出。
4. **协作机器人只做了肩、肘关节**，ADR-0061 写的是肩、肘、腕。

## 决策

1. **平缝机动力学改正**（`examples/apps/lockstitch.py`，必要时补 `analysis/mbd`）：
   - 由恒速工况的扭矩记录求一转的最大盈亏功 ΔE，与教材近似式 ½·m·r²·ω² 对照；用候选电机的转子惯量
     （零件库 `rotor_inertia_kgm2`）加机构等效惯量求转速不均匀系数 δ = ΔE / (J·ω²)，说明要多大附加惯量（手轮）才能降到
     教材许用值；
   - 选型给出两种速度环的界限：上限（刚性速度环，连续扭矩 = 惯性力矩均方根）与下限（惯量吸收，连续扭矩 = 缝制阻力，
     无数据 → 待确认）；峰值扭矩 = 起停加速扭矩（J·α，加速时间是设计假设，写进报告并给两三档）与惯性力矩峰值之和；
     负载惯量 = 机构等效惯量（C8 惯量比）；
   - 报告与演练报告改正原来的说法（平缝机一节、发现的问题一节），并写明针杆质量是示意值。
2. **方案改版进 ERP**（桥接与模拟 ERPNext）：BOM 按“产品 + 方案版本”识别（写在 BOM 的说明里），同一版本不重建；
   新版本建新 BOM 设为默认、旧 BOM 取消默认；产品登记表照旧按最新版本并入主数据。
3. **自制件可带粗基准与装夹**：发布内容的自制件加两个可选字段 `datum`（第一道机加工工序的定位基准）、`clamping`（装夹）；
   工厂“从方案起草工艺规程”用它们，没给时留空由工艺员补（AI 评审照常提示）；演练脚本不再代写，改由三个应用的方案带上。
   这是发布内容的扩充：`cad_link.validate` 只做可选字段的类型检查；仓库 `schema/` 不涉及。
4. **协作机器人补腕关节**：参数化串联臂的 j4 做动力学与选型，结论写进报告。

## 后果

- 平缝机的选型给出上下限与起停加速的结果，并说明各自的前提；缝制阻力、针杆实际质量仍是待确认
- 工厂可以接收同一产品的多个版本，ERP 里只有一张默认 BOM
- 工艺规程的基准由懂零件的人给，脚本只做搬运
