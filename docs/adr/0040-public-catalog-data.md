# ADR-0040：用厂商公开的产品目录参数跑通真实数据

- 状态：已接受（2026-10-01，项目负责人决定）
- 日期：2026-10-01
- 取代：ADR-0015 第 2 条“真实数据须授权”；ADR-0015 的其余各条仍然有效

## 背景

V1 的开发已经全部完成，但用的都是虚构组件。ADR-0015 规定，真实厂商数据只有在取得书面授权，或经人核实条款允许后才能入库。厂商授权进展缓慢，导致真实数据迟迟无法入库。

项目负责人的意见（2026-10-01）：

- 先用公开数据把流程跑通，开发不能停
- 厂商授权不急
- 只取厂商公开发布的产品目录和规格信息。厂商本来就希望别人了解并选用自己的产品；不该取的东西不取

项目负责人授权 Claude 判断各来源能否使用，结论记在本 ADR 和 `data/sources.yaml` 中，项目负责人可随时推翻。

## 决策

1. **可以取的内容**：厂商公开发布的产品目录、规格书中的技术参数和接口尺寸。
   - 例如额定扭矩、减速比、法兰孔分布圆、轴径
   - 这些参数以 `license: params-only` 登记，`terms_checked: true`
   - `terms_note` 写明依据为本 ADR，以及条款核实日期
2. **不取、不存、不转发的内容**：
   - 规格书 PDF、图片、图纸、CAD 模型，以及成段的原文。原始 PDF 只放在本地或 CI 临时目录的 `data/raw/`，不入 git，也不作为构建产物保存
   - 需要登录、付费或签署协议才能获取的资料
   - 价格、库存等商业信息
3. **怎样取**：
   - 每份规格书逐份登记：标题、版本、厂商官方下载网址、SHA-256
   - 每份只按登记的网址下载一次，不遍历网站，不批量爬取
   - 来源只用厂商官方网站。经销商转载的副本不用
4. **标注出处**：
   - 每个参数都写明来源文档和页码；抽取结果中的原文引用只保留定位所需的短句
   - 组件记录链接回厂商官方的下载页或产品页
5. **开源硬件**：许可证明确允许再使用的开源硬件设计（Apache-2.0、MIT、BSD、LGPL 等），以 `license: open` 登记，并注明许可证与仓库提交。ShareAlike 许可（CC-BY-SA）的来源暂不收录：它会要求衍生数据以同样许可发布，须另行决定。
6. **厂商提出异议时**：删除该厂商的数据；来源的 `license` 改为 `withdrawn`、`terms_checked` 改为 `false`，并记录日期。此后该来源的数据不能再入库。
7. **复核**：真实数据的关键字段仍须对照原文复核（实施细则第八节第 3 条）。
   - 本 ADR 授权由 AI 完成复核：用与抽取不同的方式独立读取同一份原文，逐项比对。复核人记为 `claude（AI 复核）`
   - 两次读取结果不一致的项不入库，列入待人工核对清单
   - 项目负责人之后的人工抽查不阻塞开发

## 理由

- 产品目录本来就是厂商为推广产品公开发布的，选型参数是工程师选型时都要查的事实信息
- 只取参数和尺寸，不转存文档和模型，不批量爬取，注明出处并链接回厂商：这样既能把真实数据流程跑通，又不取不该取的东西
- 考虑过的替代方案：
  - 继续等书面授权：不知道要等多久，开发会停下来
  - 只用开源硬件：开源硬件几乎不公开伺服电机的额定扭矩、额定转速，也不公开减速器的额定扭矩、回差，只能补充驱动器和少量尺寸数据
- 以上是项目的工作决策，不构成法律意见。若日后取得厂商授权，相应来源改为 `license: partner`

## 影响

- 开发计划新增阶段 M6“公开数据跑通”，实施细则增加 M6 分项任务表
- `data/sources.yaml` 中厂商来源的 `license`、`terms_checked`、`terms_note` 按本 ADR 更新
- 本工作环境的命令行访问不到厂商网站，规格书的下载和真实 LLM 抽取在 GitHub Actions 或 Codespaces 中进行
  - 只把录制、抽取结果和 SHA-256 提交回仓库，不提交 PDF
  - 在 Actions 中运行真实抽取，需要在仓库的 Actions secrets 中设置 `ANTHROPIC_API_KEY`
- 风险：厂商可能对收录其数据提出异议，按第 6 条处理
