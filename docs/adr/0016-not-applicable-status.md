# ADR-0016：校验结果增加“不适用”状态

- 状态：已接受（2026-09-30）
- 日期：2026-09-30

## 背景

实施细则第七节只定义了 `pass`、`warn`、`fail`、`unknown` 四种状态。编写 golden 用例时发现，有些校验在某个方案里根本不需要做：需求没给负载惯量时的 C8、没给峰值扭矩时的 C5 峰值部分、系统里没有轴承或需求没给包络限值时的 C11、没有圆柱或法兰连接时的 C2、C3。这些项既不是“通过”，也不是“数据缺失”。

## 决策

1. 增加第五种状态 `not_applicable`：该项校验的前提在需求或系统中不存在，因此不做
2. 与 `unknown` 的区别：`not_applicable` 是“不需要这项数据”；`unknown` 是“需要但缺失”。例如需求给了负载惯量而电机缺转子惯量，C8 为 `unknown`；需求没给负载惯量，C8 为 `not_applicable`
3. 整体结论计算时忽略 `not_applicable`；全部适用项为 `pass` 即整体 `pass`
4. 校验输出中 `not_applicable` 项须写明原因（如“需求未给负载惯量”）
5. golden 用例的 `checks` 可以断言 `not_applicable`；已有用例不因本决定修改，是否补充断言由人决定

## 理由

把“不需要做”和“做不了”分开，方案说明才能如实告诉用户哪些风险没有检查、原因是什么。

## 影响

- 实施细则第七节状态表增加一行
- `tests/test_golden.py` 接受 `not_applicable` 作为断言值
- M3 实现每项校验时须先判断适用性
