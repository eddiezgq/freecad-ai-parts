
## 施工记录

- **44.0 整机方案格式（2026-11-22）**：`schema/robot-concept.schema.json`（ADR-0116），单独 PR。
- **44.1 构型初筛（2026-11-22）**：分析模块 `robot`（`analysis/robot/`）。`kinematics.py`：结构检查（schema 之外：引用、树、轴线、动作超行程、
  构型类型与轮子）、正运动学、位置雅可比、位置逆解（阻尼最小二乘、固定起点，可复现）；`screen()`：工作空间点可达、关节动作在行程内、
  直线动作沿途 20 段都有解且连续、奇异（位置雅可比秩亏才判，其余只报最小 / 最大奇异值之比）、末端负载的静力矩（下限，只计负载）。
  移动底盘这一步只查结构，结论“待确认”。标准题（`tests/test_analysis_robot.py`）：平面两杆臂的正运动学、工作空间为环形
  |l1 − l2| ≤ r ≤ l1 + l2、奇异值之积 = l1·l2·|sin θ2|、负载对肩与肘的静力矩 m·g·(l1 cos θ1 + l2 cos(θ1+θ2))、伸直位奇异、龙门逆解。
- **44.2 构型循环（2026-11-22）**：`assist/robot_design.py`。AI 列条件（每个数附原话引用，代码核对）；AI 提 1–3 个构型（robot-concept/1）并推荐一个；
  代码逐个初筛并按需求核对——自由度、安装方式、臂展点（程序按需求加：安装面上 x = 臂展，要够得着且不奇异）、关节模组复用；
  重复定位精度这一步判不了（选件后按编码器分辨率与减速器回差算），记待确认、不挡通过；“可加工”“低成本”交给人看。
  一个都没通过就把每个构型没通过的项交回 AI，最多 4 轮；有通过的就停，采用 AI 推荐的（推荐的没通过就采用第一个通过的，并写明）。
  案例 A 的需求原话：`examples/robots/teaching-arm/requirement.txt`（数字照项目负责人确认的 ADR-0115 第 1 节；“臂展”的含义写在原话里）。
  录制：`design-eval.yml` part = robot。
  第一次真实运行（design-eval 45056080995，Claude）：3 轮通过——第 1 轮两个构型的 id 用了大写（格式不通过），第 2 轮两个构型都在动作起点处于奇异位置。
  据此改了两处：提示里写明 id 的写法；奇异只在要按末端位置控制的地方判（工作空间点、直线动作沿途），关节动作的起点终点经过奇异位置不碍事，只报数
  （第 2 轮被判不通过的正是这种：待机位伸直）。改后重录。
  之后几次重录又暴露出：动作缺 type、材料写了材料库里没有的牌号、管截面把壁厚当内径写——分别在提示里写明、加材料库核对（把库里的牌号发给 AI）、
  把截面改成按形状命名的字段（ADR-0116 更新，单独 PR）。
  最终录制（design-eval 45057651041，Claude）：1 轮通过，3 个构型都通过初筛（单一模组五轴臂、大小两种模组五轴臂、升降柱加水平双关节臂），
  采用 AI 推荐的“单一模组五轴臂”：五个关节同一种模组（减速比 50），6061-T6 铝管杆件，上臂 200 mm、前臂 180 mm；
  AI 的理由是只有一种外购模组、学生好装拆、车铣就能加工。结果存 `examples/robots/teaching-arm/out/concept-result.json`，
  重放测试 `tests/test_robot_design.py::test_teaching_arm_recording_replays_to_pass`（不调用真实模型）。
