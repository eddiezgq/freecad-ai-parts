# ADR-0055：企业私有库（M9 第一步）

- 状态：已接受（2026-10-06，项目负责人同意 M9 的方向与顺序）
- 日期：2026-10-06
- 补充：ADR-0040（公开目录数据）、ADR-0044（人工确认）、ADR-0048（组件库的选择）

## 背景

项目负责人决定：零件数据以后主要由企业自己补，重点是帮企业快速建立自己的零部件与供应商库。M9 的顺序：

1. 私有库：企业自己的库叠加在公共库上，企业的数据只存在企业那边（本 ADR）
2. 就地补数据：校验中“待确认”的项旁边补数据，填值并附规格书页码与原文
3. 导入规格书：AI 抽取、代码核对，在 FreeCAD 中逐项确认后入私有库
4. 新建零件向导：按品类模板从规格书建新零件

企业的规格书、采购资料往往不能公开，也不能进入本仓库。私有库要和公共库（`data/library`）分开存放，但在选型、校验、BOM 中一起使用。

## 决策

1. **位置**：企业库是企业自己选的一个文件夹（本机或共享盘），不在本仓库内
   - 由环境变量 `FAP_ENTERPRISE_LIBRARY` 或设置文件 `~/.freecad-ai-parts/settings.json` 的 `enterprise_library` 指定；FreeCAD 中“企业库”命令选择并写入设置文件
   - 没有指定时只用公共库，行为与现在相同
2. **结构**
   - `components/<品类>/<组件 id>.json`：完整组件，与 `component.schema.json` 相同
   - `sources.yaml`：企业登记的资料（id 以 `src-ent-` 开头，符合参数来源的 id 规则、标题、文件名、SHA-256、登记人、日期）
   - `docs/`：企业的规格书原件，只在企业那边
   - `history.jsonl`：每次写入一行（时间、操作人、组件、字段、旧值、新值、依据）
3. **叠加**：`LayeredLibrary(企业库, 公共库)`
   - 按 id 取组件时企业库优先；列表为两者合并，同 id 以企业库为准
   - 可查询组件来自哪一层（企业 / 公共），面板与 BOM 中标出
4. **写入规则与公共库相同**
   - 写入前按 schema 校验，不合格不写
   - 每个新值都要有依据：企业资料的 id、页码与原文，或注明人工录入及录入人；不编造、缺数据就不写
   - 只写企业库目录，从不写公共库或本仓库
5. **隔离**：企业库的内容不上传、不入 git；本项目的测试只用临时目录

## 理由

- 数据权利问题由企业自己的资料与采购关系解决，不依赖公共来源的授权
- 叠加而不复制：公共库更新后，企业没改过的组件自动随之更新；企业改过的组件以企业为准，并可追溯
- 与公共库同一套规则，保证企业补的数据同样可查、可核

## 影响

- 新增 `kb/enterprise.py`（企业库读写、历史记录）与 `kb/library.py` 的 `LayeredLibrary`
- `freecad_addon/core/library_choice.py` 加入企业库；面板顶部说明两层的组件数
- 计划与实施细则加 M9 分项任务
