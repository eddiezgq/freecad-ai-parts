# ADR-0032：M4b FreeCAD 布局的架构、配合约定与测试方式

- 状态：已接受（2026-10-01，项目负责人授权先按最优方案决定，可推翻）
- 日期：2026-10-01

## 背景

M4b 要实现 FreeCAD 组的 4 个工具（`place_component`、`connect_ports`、`check_interference`、`snapshot`），以及包络模板、端口对齐、干涉检查和内置对话面板。验收标准是“agent 能独立完成布局并消除干涉”。

开工前要先定 4 件事：

- 布局状态由谁持有，MCP 服务端怎样与 FreeCAD 会话通信
- 两个端口“配合”在几何上是什么意思
- 干涉怎样算，才能排除轴插进孔这类设计上的重叠
- 依赖 FreeCAD 的代码怎样测试

可行性已核实：

- FreeCAD 1.0.2 的官方 AppImage（conda 构建，内带 Python 3.11 和 pip）在本项目的 Linux 容器里解包后，可以无界面运行 `freecadcmd` 并调用 `Part` 做布尔运算
- 在 Xvfb 下可以调用 `FreeCADGui` 保存视图截图

## 决策

### 1. 核心与视图分离：布局状态在 FreeCAD 之外

`freecad_addon/` 分三层：

| 子包 | 依赖 | 内容 |
| --- | --- | --- |
| `freecad_addon/core/` | 只用标准库 | 位姿（刚体变换）、配合规则、布局场景（实例、位姿、端口连接）、世界坐标下的包络描述、包络长度 |
| `freecad_addon/fc/` | FreeCAD | 由包络描述生成 `Part` 实体、干涉计算、截图、在 FreeCAD 里执行的 worker |
| `freecad_addon/gui/` 与 `InitGui.py` | FreeCAD 界面 | 工作台、零件面板、对话面板 |

规则如下：

1. **场景以服务端为准**
   - 布局场景（scene）由 MCP 服务端持有，是唯一的真实状态
   - FreeCAD 文档只是场景的视图
   - `place_component` 和 `connect_ports` 的位姿计算是纯 Python 代码，不需要 FreeCAD
2. **FreeCAD 只做几何查询与显示**
   - 服务端把整个场景发给 FreeCAD worker（JSON 行协议），worker 重建文档后，执行干涉计算或截图
   - 场景很小，每次全量同步，省去增量同步的一致性问题
3. **两种 worker 后端**，协议相同，由环境变量 `FAP_FREECAD` 选择：
   - `headless`：服务端启动 `freecadcmd` 子进程，供外部 MCP 客户端和 CI 使用
   - `gui`：FreeCAD 界面里的插件监听本机端口，服务端去连接，供内置面板使用
   - 未配置时，位姿类工具照常可用；`check_interference` 和 `snapshot` 返回“未连接 FreeCAD”的错误
4. **用户在 FreeCAD 里手动拖动不回写场景（V1）**
   - 面板会提示“以场景为准，手动移动会在下次同步时被覆盖”

### 2. 配合约定（端口坐标系）

现有数据（golden fixtures、`ingest/assemble.py` 按品类生成的坐标系）的做法如下：

- 端口坐标系的轴向沿传动链指向输出侧，即装配时零件相对移动的方向
- 相配的两个端口轴向相同，不是相对
- 法兰与安装面的原点在接触面中心
- 轴（`cyl_male`）的原点在轴端
- 孔（`cyl_female`）的原点在孔口

schema 中“指向配合方向”按“装配插入方向”理解，由此定下：

1. **面配合**：`flange ↔ flange`、`mount_face ↔ mount_face`
   - 两端口的原点在世界坐标中重合，轴向相同
   - 绕轴的转角由 `roll_deg` 指定，缺省为 0
   - 基准姿态取“把被移动件的端口轴向以最短弧转到目标轴向”的旋转，再绕该轴转 `roll_deg`
2. **圆柱配合**：`cyl_male ↔ cyl_female`
   - 两端口同轴，轴向相同
   - 如果两个实例之间还有面配合，轴向位置由面配合决定，圆柱配合只核对同轴；偏差超过容差就报错
   - 只有圆柱配合时，孔口放在“轴端减去插入深度”处
     - 插入深度取轴的 `usable_length_mm` 与孔的 `depth_mm` 中较小的一个
     - 两者都缺时，按 0 放置（孔口对齐轴端），结果中注明“插入深度未知，请用 `offset_mm` 指定”
   - `offset_mm` 让被移动件沿轴向平移，正值朝轴向方向
3. **可配合的端口对**
   - 取端口类型 schema 的 `x-connects-to`
   - 电气与信号端口没有坐标系，不参与布局，传入时报错
4. **谁动**
   - `connect_ports(a, b)` 移动 b 所在的刚性组（已通过配合连在一起的实例），a 所在的组不动
   - 如果 a 和 b 已经在同一组，就不移动，只核对是否对齐，返回位置偏差（mm）和角度偏差（°）
5. **容差**：位置 0.01 mm，角度 0.01°；场景数据可以覆盖

### 3. 干涉检查

1. **包络实体**
   - 每个实例的包络各段（圆柱、长方体）合并为一个实体
   - 有 `cyl_female` 端口的实例，在实体上减去该孔：直径取孔的名义直径，深度取 `depth_mm`；没有深度时贯穿包络
   - 这样，轴插进相配的孔不算干涉，不需要白名单
2. **计算**
   - 对每对实例先比包围盒，再用 `Part` 的布尔交集求重叠体积
   - 重叠体积大于阈值才报，阈值缺省 1 mm³，可以由参数覆盖
   - 用于吸收同径轴孔在数值上的细小残余
3. **结果**
   - 干涉对、重叠体积（mm³）、重叠区包围盒、两者之间有没有配合关系
   - 面配合的接触面体积为 0，不报
4. **不建模的特征**：止口、螺栓孔、键槽
   - 止口的凹凸配合由 C3 校验
   - 布局只看包络

### 4. 截图

- `gui` 后端：保存当前视图
- `headless` 后端：在 Xvfb 下调用 `FreeCADGui`
- 支持的视角：等轴测、前、后、左、右、上、下；返回 PNG，作为 MCP 图像内容
- 没有显示环境时返回明确的错误，不返回空图

### 5. 包络长度与 C11

- 布局后的系统长度定义：传动链实例（不含驱动器，ADR-0027）的包络在输出轴方向上的投影范围
  - 输出轴方向取减速器 `output_flange` 在世界坐标中的轴向
  - 圆柱、长方体的投影长度有解析式，在 `core/` 中计算，不需要 FreeCAD
- 引擎保持纯函数：布局结果作为系统数据的一部分输入
- 系统 schema 需要增加可选的 `layout`（各实例位姿），这是 schema 变更，单独成 PR，另附 ADR

### 6. FreeCAD 版本与测试

1. **锁定版本**
   - 开发与 CI 锁定 FreeCAD 1.0.2 官方 AppImage（`FreeCAD_1.0.2-conda-Linux-x86_64-py311.AppImage`）
   - CI 下载后核对 SHA-256：`e00be00ad9fdb12b05c5002bfd1aa2ea8126f2c1d4e2fb603eb7423b72904f61`
2. **CI 增加 `freecad` 作业**
   - 下载并缓存 AppImage，解包
   - 用其内带的 Python 安装本项目，在 Xvfb 下运行 `pytest -m freecad`
   - 这修改了实施细则第三节“FreeCAD 相关测试只在本地运行”的规定：能在 CI 跑，就不只靠本地
3. **测试分两类**
   - `core/` 的测试是普通测试，在主作业中运行
   - 需要 FreeCAD 的测试标记 `@pytest.mark.freecad`：主作业里因为导入不到 FreeCAD 而跳过；`freecad` 作业中设置 `FAP_REQUIRE_FREECAD=1`，导入失败即报错，不能静默跳过
4. **用户本机**
   - 用户本机的 FreeCAD 1.x 安装另行说明（Windows、macOS 的安装包，或 Linux 的 AppImage）
   - 用户本机不是 CI 的前提

## 理由

- **核心与视图分离**是架构文档的第二条原则
  - 位姿与配合放在纯 Python 中，可以在没有 FreeCAD 的环境里测试和使用
  - 与 ADR-0003“内置面板只是另一个 MCP 客户端”一致
- **全量同步**比增量同步简单，数据量也不是问题（一个关节只有几个实例）
- **在包络上减去孔**，用几何本身表达“轴插进孔”，比维护“允许重叠”的白名单更可靠，也能发现轴伸过长、穿出孔底这类真实问题
- **CI 跑 FreeCAD 测试**：已经核实 AppImage 可以无界面运行。只在本地跑的测试很容易长期失效
- **考虑过的替代方案**
  - 让 MCP 服务端运行在 FreeCAD 进程内：FreeCAD 会成为运行前提，外部客户端也必须先打开 FreeCAD，与“核心不依赖 FreeCAD”相悖
  - 采用现有 FreeCAD MCP 项目的“执行任意 Python”方式：架构文档已明确不提供此类工具

## 影响

- 新增 `freecad_addon/core/`、`fc/`、`gui/`
- MCP 服务端新增 4 个工具，以及会话内的场景状态
- CI 新增 `freecad` 作业，首次下载约 800 MB，之后走缓存
- 系统 schema 的 `layout` 字段另开 schema PR 与 ADR；URDF 导出依赖它
- 实施细则第三节的测试规定、第十节的 M4b 任务表同步更新
