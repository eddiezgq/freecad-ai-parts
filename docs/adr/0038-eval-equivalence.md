# ADR-0038：抽取评测的等价规则与可推出字段

- 状态：已接受（2026-10-01，项目负责人授权先按最优方案决定，可推翻）
- 日期：2026-10-01
- 补充：实施细则“准确率评测”一段

## 背景

第一次真实评测（#31、#118）的结果是：关键字段准确率 100%，全部字段错 12、多 26。逐项检查后发现：

- **错的 12 项**，没有一项是数值抽错：
  - 7 项是 `STO` 与 `["STO"]` 这类单值和列表的差异。这些字段在 schema 中是 `string_or_list`，两种写法都合法，含义也相同
  - 4 项是 `CiA 402` 与 `cia402` 的差异。这个字段是没有枚举的自由字符串，差别只在大小写与空格
  - 1 项是单个协议被写成了单元素列表
- **多的 26 项**里有 24 项，是 LLM 报了答案中列为 `implicit` 的字段（`fit_system`、直流相数等）
  - 实施细则写明这类可推出字段“评测时不计分”，但评测代码仍把它们记为“多报”
  - 另外 2 项是答案中确实没有的字段，属于真多报

评测代码与 schema 的语义、与实施细则不一致，会让精确率被低估，也会掩盖真正的错误。

## 决策

1. **`string_or_list` 字段**：单值视为单元素列表，按元素集合比较（顺序不计，元素逐个按下面的规则比较）
2. **没有枚举的字符串字段**：比较时忽略大小写、空白和标点（`CiA 402` 等于 `cia402`）。有枚举的字段仍要求与枚举值完全相同
3. **答案中列为 `implicit` 的字段**：LLM 报了这些字段时，
   - 值与组件中的推导值相同：记为“可推出”，不计入召回、精确，在报告中单独计数
   - 值不同：记为“多报”，计入精确率的分母
4. 数值字段、关键字段的判定不变（相对误差 ≤ 0.1%）

## 理由

- 判对的标准应与“入库后是否等价”一致：schema 认为等价的写法，评测也应该认为等价
- 等价规则只放宽写法，不放宽数值。数值抽错仍判错
- 可推出字段与推导值不一致时仍要计入，避免 LLM 编造的推导值被悄悄忽略

## 影响

- 修改 `ingest/evaluate.py`，补单测；报告增加“可推出”计数
- 用同一份录制重新回放，预期：错 0、多 2、漏 5，关键字段准确率不变（100%）
- 评测门槛与关键字段准确率的定义不变
