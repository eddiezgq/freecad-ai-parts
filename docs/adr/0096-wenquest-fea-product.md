# ADR-0096：问渠有限元（WenQuest FEA）——把有限元模块做成可单独安装、销售的产品

- 状态：已接受（2026-11-17 00:25，项目负责人“好，开始”；00:15 问“可以做问渠有限元软件吗”，00:18 “好”要写方案，并要求“也包括中国市场”）
- 日期：2026-11-17
- 补充：ADR-0001（开放核心）、ADR-0056（分析模块）、ADR-0060（分析只留一份）、ADR-0063（AI 两家切换）、
  ADR-0066（单机安装版与授权）、ADR-0093（有限元工业化 F1–F7）、ADR-0095（壳、梁）

## 背景

ADR-0093 的 F1–F7 已全部合进主线（最后一个是 PR #520）。有限元模块现在能做：静力（线性、塑性、大变形、接触、螺栓预紧）、
屈曲、模态、谐响应、随机振动、瞬态、附加质量；实体、壳、梁单元；可信度核查（反力平衡、网格质量、三层网格收敛，
没判“通过”就不给安全系数）；AI 一句话起草算例（真实模型 12 份算例选错面 0 次）、AI 解释结果、Word / PDF 报告；
界面在 FreeCAD 的 FEM 工作台里（三个按钮、原生约束对象、原生后处理）；50 万单元能算，算前估内存、自动选求解器。

项目负责人想把它做成一个能单独安装、单独销售的软件：“问渠有限元”。市场：美国和国际，**也包括中国**
（这一点是本 ADR 新定的，之前只做美国和国际）。

现在离“产品”还差：

- 只有中文界面和中文报告；
- 有限元的 AI（起草、解释）只接了 Claude，中国用不了；
- 对照题散在约 35 个测试里，没有一份用户能看的验证手册；
- 安装包是零件库全功能版，没有问渠有限元自己的品牌、精简版和授权；
- 计划里还剩两件没收尾：旧“有限元 · 疲劳”窗口的有限元部分退役；AI 起草不会处理壳和梁；
- 没有帮助文档、入门例子和销售方案。

## 决策

### 1. 名称与定位

- 名称：中文“问渠有限元”，英文“WenQuest FEA”。
- 用户：买不起 ANSYS、Abaqus 的中小企业设计员、结构工程师，以机器人、自动化设备的零部件为主。
- 卖点：
  1. 一句话出算例（AI 起草，程序核对，人确认后才能算）；
  2. 每个结论带可信度，给不了就直接说给不了；
  3. 直接出能交给审核人的报告（数字由程序填，带审核清单和结果指纹）；
  4. 界面就是 FreeCAD，会用 FreeCAD 就会用。

### 2. 与零件库的关系：同一份代码，另一个安装包

- 不另开仓库、不复制代码。问渠有限元与零件库共用 `analysis/fea`、`assist/fea_*`、`freecad_addon/fc/fem_*`、
  `freecad_addon/gui/fem_commands.py`（ADR-0060“分析只留一份”）。
- 问渠有限元 = 在这份代码上加一层：自己的安装包、品牌（名称、图标、启动画面、关于页）、授权。
- 安装包出两种，同一个构建脚本按参数出：
  - 全功能版（现有，零件库 + 各分析模块）；
  - **问渠有限元版**：只装 FEM 工作台的三个按钮、有限元计算与报告、疲劳；零件库面板、选型、数字工厂等不装。

### 3. 免费与收费、许可证边界

- 版权：本仓库 2026-10-09 前公开过的代码仍是 Apache-2.0，不能收回；之后新写的（包括 F1–F7、壳梁）没有公开发布过，
  版权属项目负责人，可以按商业许可发布。
- 分两档：
  - **免费版**：单个零件的静力、模态、屈曲；可信度核查；FEM 原生后处理；简要结果页（不出正式报告）。
  - **专业版**（收费，按年订阅，单机绑定或浮动席位，沿用 ADR-0066 的授权机制）：AI 一句话起草与 AI 解释；正式报告
    （Word / PDF，可加公司抬头，审核清单）；多实体（绑定、接触、螺栓）；塑性、大变形；谐响应、随机振动、瞬态；
    附加质量；壳、梁；大模型（自动选求解器）；技术支持。
- ~~收费部分做成闭源模块，放私有仓库，Nuitka 编译成二进制发布（ADR-0066 决策 2）。~~
  **偏差（2026-11-17 项目负责人定：“第一版只靠签名授权”）**：第一版不编译、不拆闭源模块。代码留在本私有仓库，
  安装包里是 Python 源码；专业版功能由 Ed25519 签名的授权文件（ADR-0066）离线开放，授权里要有功能 `fea_pro`。
  这挡得住普通用户，挡不住会改 Python 的人——第一版接受这一点；编译成二进制和下面的子进程边界放第二版。
  许可：2026-10-09 前公开过的代码仍按 Apache-2.0，之后写的按商业许可；Gmsh 与 CalculiX 按 GPL 附源码获取方式。
  第一版没有闭源二进制，上面的“闭源模块不得与 gmsh 同进程”第一版不涉及；第二版拆闭源模块时照它做。
- 签名密钥（2026-11-17 项目负责人定：“先用测试密钥”）：CI 验收时临时生成一对测试密钥，只在验收用的安装包里认
  （安装包里写 `test_build: true`，并从环境变量 `FAP_LICENSE_TEST_KEY` 读公钥）；正式发版的安装包不认测试密钥，
  `licensing/keys.py` 的正式公钥等第一个客户时由项目负责人在自己电脑上生成私钥后加入（私钥不进仓库、不进对话）。
- **GPL 边界**：CalculiX、Gmsh 是 GPL。
  - CalculiX 一直是作为独立程序调用的，随安装包附源码获取方式和许可证即可。
  - Gmsh 是被 Python 直接调用的。闭源模块**不得直接 import gmsh，也不得与调用 gmsh 的代码跑在同一个进程里**：
    网格划分和求解留在开源核心里，闭源模块只通过文件（算例 JSON 进、结果 JSON 出）和子进程调用开源核心。
  - 开源核心（Apache-2.0）与 Gmsh（GPL-2.0 或更新版本）一起分发时，按 GPL 的要求附源码获取方式（Apache-2.0 与 GPLv3 兼容）。
  - 以后若闭源部分必须直接调用网格划分，再买 Gmsh 的商业许可；第一版不需要。
- 授权校验的结果只决定“能不能用专业版功能”，不改变任何计算结果和核查结论。

### 4. 两个市场

| 方面 | 中国 | 美国与国际 |
| --- | --- | --- |
| 界面、报告、帮助、验证手册 | 中文 | 英文 |
| AI 模型 | DeepSeek（已备案模型） | Claude |
| 销售主体 | 项目负责人在浙江台州的公司 | 项目负责人在美国的公司 |
| 下载 | 官网下载，国内另放国内对象存储镜像 | 官网下载 |
| 合规 | 软件著作权登记（台州公司名义）；开发票 | 发版前按美国出口管制核一次分类，不卖给受限名单上的单位 |

- **语言**：同一套代码中英切换。缺省跟随 FreeCAD 的语言设置，问渠有限元的设置里可单独改；报告语言可以和界面不同
  （比如界面中文、报告英文）。程序生成的核查说明、局限、审核清单都要两种语言；AI 解释按报告语言写，数字照样由程序填。
- **AI**：有限元的起草和解释改走现有的模型网关 `llm_gateway`（ADR-0063）：`auto` 时中国用 DeepSeek、其他地方用 Claude，
  出错换另一家；每次记下实际用的是哪家，报告里写明。DeepSeek 不单独做真实模型验收（2026-11-17 项目负责人定：“国内用自动换就是了，
  不用验收”）：程序核对（引用、数和单位、面号、方向）对两家一样，AI 起草的算例照旧要人确认后才能算。
- **AI 服务方式**：第一版用用户自己的密钥（首次启动向导填写，存本机用户目录，ADR-0066），本机直接调用；
  我们不做托管接口（在中国做托管要生成式 AI 服务备案，在美国要做计费，都放到以后）。
- **数据**：零件模型和计算结果只在用户本机。调用 AI 时只发那句话和程序识别出的零件特征清单（编号、类型、尺寸），
  不发模型文件。这一点写进帮助和隐私说明。
- **材料**：材料库同时列中国牌号和美国牌号（如 45 钢、Q355、6061-T6、304）；数值只收能注明出处的（GB/T、ASTM、手册），
  对不上出处的不写（与现有规则相同）。
- **单位**：第一版输入、界面、报告都用公制（mm、N、MPa）。英制显示放第二版，换算仍只在入口用 pint 做。

### 5. 验证手册

- 一份自动生成的文档（中英两版，PDF）：每题写题目、示意图、出处、参考值、本软件计算值、误差、网格、可信度结论。
- 来源：现有的约 35 个对照题（悬臂梁、Lamé 厚壁圆筒、Kirsch 孔边、NAFEMS LE1、LE10、欧拉压杆、简支板屈曲、
  赫兹接触、过盈配合、螺栓、塑性、大变形、单自由度动力学、悬臂谐响应、壳、梁等），再补模态类的 NAFEMS 标准题
  （FV 系列，参考值取自能注明出处的公开文献，取不到的不收）。
- 由脚本 `scripts/fea_verification_manual.py` 跑全部题目后生成；测试和手册用同一份题目清单，手册里的数字就是测试算出来的。
  每次发版重新生成，版本号与软件一致。

### 6. 施工顺序（每步一个或几个 PR，按仓库规矩）

1. **收尾**：旧“有限元 · 疲劳”窗口去掉有限元部分，只留疲劳和热分析入口；AI 起草支持壳和梁（选面、厚度、截面只能来自
   用户的话或零件特征，不编）。验收：原有测试全过；壳、梁各一份真实模型起草录制。
2. **AI 两家**：有限元起草和解释接 `llm_gateway`。DeepSeek 不做真实模型验收（见决策 4“AI”一条），
   用模拟的 DeepSeek 接口离线测试格式转换和整条起草、核对流程。
3. **中英双语**：三个按钮、任务面板、提示、核查说明、审核清单、Word / PDF 报告。验收：同一算例出中文、英文两份报告，
   数字和结果指纹完全相同。
4. **验证手册**：脚本、补题、中英两版 PDF。验收：全部题目在注明的误差内；手册里每个数字能追到测试。
5. **问渠有限元安装包**（Windows）：品牌、精简版、免费 / 专业两档、授权（第一版不编译，见决策 3 偏差）；干净 Windows 上 CI 验收：
   装好 → 免费版算一个静力、拒绝专业版算例和报告 → 导入专业版授权（测试密钥签发）→ AI（录制回放）起草 → 出中英报告。
   设计：
   - `assist/fea_edition.py`：版本（`full` 全功能版不分档；`fea` 问渠有限元版）写在安装包的 `edition.json`；
     `pro_needs(算例)` 列出用到的专业版功能（多实体、连接、塑性、大变形、谐响应 / 随机 / 瞬态、附加质量、壳、梁、工况组合、
     超过 20 万单元）；`gate()` 在免费版遇到这些时拒绝并说明。
   - 卡口：`fem_flow` 的起草（AI）、计算前准备与计算、出正式报告；FEM 工作台按钮照常显示，点了才说明是专业版功能。
   - `freecad_addon.install --standalone --edition fea [--test-build]` 写 `edition.json`；问渠有限元版不加零件库工作台，
     在 FEM 工作台的“求解”菜单加三个按钮和热分析 · 疲劳、“帮助”菜单加授权、设置 AI 密钥、关于（见施工记录），启动默认进 FEM 工作台。
   - `installer/windows/build.ps1 -Edition fea` 用新的 `wenquest-fea.iss`（新的 AppId，产物 `WenQuest-FEA-Setup-<版本>.exe`）。
   - `installer/windows/accept_fea.py` 在装好的 FreeCAD 里无界面跑上面的验收流程；`.github/workflows/windows.yml` 加一个任务。
6. **帮助与入门**：中英帮助文档；三个入门例子（机器人关节零件为主），每个从一句话走到报告；产品介绍页内容
   （放问渠官网“企业解决方案”下，按官网仓库的规矩另做）；销售方案（定价、渠道、许可协议要点，中美各一份），
   交项目负责人定。

第二版（本 ADR 之后另写）：柔性多体动力学（多体模块做主体，有限元出柔性件、回算应力）、英制单位、Linux 与 macOS 安装包。

### 7. 不做的

- 不做网页版计算（服务器算大模型太贵）；以后只在官网做小模型演示。
- 第一版不做托管 AI 接口。
- 不改 FreeCAD 源码，只用它的 Python 接口。
- 不做电磁、流体。

### 8. 需要项目负责人做的事

- 用台州公司名义申请软件著作权登记（第 5 步之后，材料我们准备）。
- 定价和许可协议（第 6 步给出方案后定）。
- 可选：Windows 代码签名证书。没有签名时，Windows 首次运行安装包会弹“未知发布者”提示，能装但不好看。

## 理由

- 计算、核查、AI、报告、FreeCAD 结合都已经有了，做产品主要是包装、语言、验证和销售，不必另起一套。
- 共用一份代码，零件库和问渠有限元的结果永远一致，修一处两边都好。
- 免费版能让用户先信结果（验证手册 + 可信度核查），再为 AI、报告、多实体和动力学付费。
- 考虑过：
  - 另开一个问渠有限元仓库：两份代码会越走越远，不选。
  - 先做网页版：服务器算力成本高，用户的模型还要上传，不选。
  - 中国市场也用 Claude：不合规，不选。
  - 第一版就做英制单位：工作量大，而目标用户多数能接受公制，放第二版。

## 影响

- `freecad_addon/fc/fem_flow.py` 的 AI 客户端改为模型网关；`assist/fea_draft.py`、`assist/fea_report.py` 要支持两种语言，
  报告里写明用的是哪家模型。
- 安装构建（`installer/windows/`）加“问渠有限元版”参数；私有仓库里加专业版闭源模块。
- 新增验证手册脚本和文档；每次发版重新生成。
- 不改 `schema/`；第 1 步如需改算例格式，按规矩单独提 schema PR 并补 ADR。
- 柔性多体顺延到问渠有限元第二版。

## 施工记录

- **第 1 步之一（2026-11-17，旧窗口的有限元部分退役）**：
  - 原“有限元 · 疲劳”窗口改名“热分析 · 疲劳”：去掉“强度（静力）”“固有频率”，只留温度场、热应力；
    窗口里写明强度、固有频率在 FEM 工作台里用“一句话起草 / 计算并核查 / 出报告”。菜单、拓扑优化窗口、工作台说明里的指引同步改。
  - 疲劳的参考应力改为取自 FEM 分析这次“计算并核查”的结果（`fem_flow.fatigue_inputs`）：静力步的最大 von Mises 应力（避开约束面），
    参考载荷是算例里唯一的那个载荷（力、扭矩、力矩、压力或轴承载荷）的大小，材料取算例的材料。下列情况说明原因、不给寿命：
    没算过；算例在计算后改过；可信度没判“通过”（与安全系数同一规则）；不止一个实体；壳、梁、弹塑性、大变形；
    有不为零的强制位移；不止一个载荷或另有重力等（应力不再与参考载荷成正比，不能按载荷谱换算）；不止一个静力步。
  - 出报告与疲劳共用“取这次计算的算例与结果、改过就拒绝”的同一段代码（`fem_flow.last_run`）。
  - 验收：Ø35 × 100 的 45 钢轴（底面固定、顶面扭矩 350 N·m）在 FEM 里计算并核查，可信度通过，疲劳窗口取到的参考应力
    与 √3 · 16T / πd³ = 72.0 MPa 相差 < 5 %（实测 72.6 MPa），按多体动力学的关节力矩记录算出寿命；RJ-201（可信度不通过）不给寿命；
    没算过、可信度未知 / 不通过、另加重力都说明原因。原窗口的静力着色测试改为上面这个测试（原功能已退役）；温度场测试不变。
- **第 1 步之二（2026-11-17，AI 起草认壳、梁）**：
  - 特征识别（`assist.features.recognize_thin`）：STEP 只有曲面的按壳（中面），列出每个壳面（平面的法向、圆柱面的轴线、面积）和每条边
    （边界边只属于一个面；折边 / 交线属于两个以上），写中点和两端坐标；STEP 只有曲线的按梁（轴线），列出每根杆件（长度、方向、两端）
    和每个顶点（只连一根杆件的是端点，连几根的是节点）。
  - 起草（提示词版本 fea-draft/2）：壳的厚度、梁的截面（矩形实心宽 × 高与宽度方向、实心圆直径、圆管外径 × 壁厚）只用原话里的数，
    数紧跟单位；截面形状要与原话的说法一致（矩形管 / 方管本版不支持，说明后改成追问）；矩形截面的宽度方向要按零件坐标写明、
    且垂直于每根杆件。原话没给就追问，不猜。
  - 壳只能用固定、简支、力、压力、重力，梁只能用固定、简支、力、重力；“简支 / 铰支 / pinned”= 三个平动为零、转动不限（强制位移为零），
    实体零件不用简支。一项里的特征要同一类（都是面、都是边或都是顶点）；压力只加在壳面上。
