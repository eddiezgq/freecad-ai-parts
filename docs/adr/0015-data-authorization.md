# ADR-0015：数据获取路线——先用虚构组件开发，真实厂商数据须取得书面授权

- 状态：已接受（2026-09-30）
- 日期：2026-09-30
- 补充：ADR-0005

## 背景

issue #6 初查首批候选厂商的网站使用条款（见 `data/sources.yaml`）：Harmonic Drive、安川（美国、日本）的条款均禁止未经书面许可复制网站内容、禁止自动采集，并限制商业使用；绿的谐波、汇川的条款尚未取得。ADR-0005 设想的“从公开规格书提取参数入库”，对这些厂商在取得书面许可前不可行。以上为条款字面理解，不构成法律意见。

## 决策

1. **开发不等数据**：M1–M3 的 golden 用例、配置引擎开发与测试，全部使用虚构测试组件（id 以 `test.` 开头，放在 `tests/golden/fixtures/`，永不进入正式库）。
2. **真实数据须授权**：厂商数据只有在取得书面授权（`license: partner`）或经人核实条款允许（`terms_checked: true`）后才能入库。
3. **同步开展授权**：现在起向候选厂商发送授权请求，说明用途：只提取公开规格参数、逐项标注来源、链接回原厂下载页、不转载文档与 CAD 模型。进展记录在 `data/sources.yaml`。
4. **计划调整**
   - issue #7（种子数据）移至 M2，在取得首批授权后进行；不再作为 M1 验收条件
   - M1 验收中“用手工数据表达一套完整关节”改为用虚构测试组件
   - M2 的规格书抽取若到 10/26 仍无授权数据，先用由虚构组件生成的合成规格书（PDF）开发和测量抽取流程，取得授权后再在真实规格书上验收

## 理由

引擎和校验规则的正确性不依赖真实数据，用虚构组件能按计划推进；授权是开放核心商业路线（ADR-0001）本来就需要的，越早开始越好。

## 影响

- 风险表新增“厂商授权迟迟未到”：M2 的真实数据验收可能延后，演示（M5）可能只能使用虚构或已授权的少量组件
- `data/sources.yaml` 增加 `license: pending` 状态，取得授权后改为 `partner`
