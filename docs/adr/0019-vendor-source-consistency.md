# ADR-0019：组件引用的来源文档必须属于组件厂商

- 状态：已接受（2026-10-01，项目负责人授权按最优方案决定）
- 日期：2026-10-01

## 背景

PR #33 的独立评审指出：入库时只检查来源文档已登记且已授权，没有核对文档属于哪个厂商。甲厂商授权的规格书，可以被用来给乙厂商的组件填参数，授权就形同虚设（issue #34）。

## 决策

1. 组件引用的每个来源文档，所属来源必须**覆盖**该组件的厂商，否则拒绝入库
2. 来源覆盖的厂商 = 来源的 `vendor`，加上 `data/sources.yaml` 中可选的 `covers_vendors` 列表
3. 经销商目录、第三方手册、行业标准等涵盖多个厂商的来源，须在 `covers_vendors` 中逐一列出；未列出的厂商不能用该来源
4. 厂商名比较时忽略大小写与多余空白；不做其他模糊匹配，名称写法不同（如中英文名）也须在 `covers_vendors` 中列出
5. 测试专用文档 `src-test-fixture` 不受此限

## 理由

授权是按厂商取得的，入库把关必须按厂商核对才有意义；显式列出例外，既允许经销商目录等合理用法，又让每一个例外都留在登记文件中可审查。

## 影响

- `kb.sources.Source` 增加 `vendor_names`；`check_document` 增加 `vendor` 参数
- 登记来源时须写准 `vendor`，必要时填 `covers_vendors`
