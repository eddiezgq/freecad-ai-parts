# ADR-0027：电气、信号与包络校验（C9–C11）的实现约定

- 状态：已接受（2026-10-01，项目负责人授权先按最优方案决定，可推翻）
- 日期：2026-10-01
- 补充：ADR-0020 第 2 条“系统外径取所有组件各段中的最大值”

## 背景

实现 C9–C11（issue #51）时，有几处实施细则和 ADR-0020 没有说清：
- 驱动器算不算在关节外径里
- 私有编码器协议的“同一厂商”比较的是什么
- 需求没给供电或总线时怎么办

## 决策

1. **连接**
   - C9 要求驱动器 `motor_out` 与电机 `power_in` 之间有一条通过 C1 的直接连接；C10 对电机 `encoder` 与驱动器 `encoder_in` 同样要求
   - 连接缺失或接错（C1 不通过）都判 fail（ADR-0020）
   - 按此规则，golden 用例 `invalid/c1-swapped-wiring` 中的 C9、C10 实际结果为 fail；该用例的预期目前是 `any`，是否改为 `fail` 由人决定
2. **供电**
   - 需求给了 `supply` 才校验供电类型、电压范围和相数，没给时这几项不做
   - 电压按驱动器输入范围的两端闭区间判定
3. **电流**：额定电流不足判 fail，峰值电流不足判 warn（峰值扭矩受限）
4. **私有编码器协议**
   - 电机编码器端口的 `vendor` 与驱动器编码器输入端口的 `vendor` 比较，忽略大小写与符号
   - 任一方缺少该字段时判 unknown
5. **总线**：需求给了 `fieldbus_protocol` 才校验，须在驱动器总线端口的协议列表内
6. **包络外径**
   - 驱动器装在电控柜中，不属于关节机械包络，计算系统外径时不计入驱动器
   - 其余组件（电机、减速器、轴承、转接件）各段按外接圆计算（ADR-0020），取最大值
   - 某段缺尺寸时判 unknown
7. **包络长度**：需求给了长度上限时，C11 中这一子项标为不适用，原因写明“须 FreeCAD 布局后计算”（ADR-0020）；只给了长度上限时，C11 整体为不适用
8. **轴承转速**：系统中每个轴承都校验，转速取需求的输出转速（ADR-0020）

## 理由

关节外径约束的是关节本体能否装进外壳。驱动器若计入外径，几乎所有方案都会因为驱动器的长边被判失败，这不符合实际安装方式。

## 影响

- 今后若出现驱动器与电机集成的一体化关节，应作为电机的一部分建模（包络含驱动器），本约定不变
- golden `invalid/c1-swapped-wiring` 的 C9、C10 是否从 `any` 改为 `fail`，由人决定
