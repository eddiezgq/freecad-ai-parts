# ADR-0090：工厂清单加 `eto` 一节（按单设计：估算、报价、分期开票）

- 状态：已接受（2026-11-10，项目负责人确认问渠第 139 轮细则 139h 第 4 条）
- 日期：2026-11-10
- 补充：ADR-0064（工厂清单）、ADR-0068（共用一份代码）、ADR-0087（清单加字段的先例）

## 背景

问渠第 139 轮给数字工厂加了按单设计（Engineer to Order, ETO）全流程：估算、报价、接单、设计发布、作业算料、倒排计划、
车间执行与作业成本、检验计划与终检、发货、按里程碑分期开票。估算和开票要用到每家工厂不同的经营参数
（风险预留、加价率、设计费率、付款计划……）。按 ADR-0068 两边共用 `factory/`，这些参数写进工厂清单，
格式在这里定下来，再同步代码。

## 决策

1. 工厂清单加可选的顶层一节 `eto`，全部字段可不写：

   | 字段 | 类型与范围 | 用途 | 没写时 |
   | --- | --- | --- | --- |
   | `prefix` | 字母开头，字母数字和 `-`，≤ 10 位 | 作业号前缀，作业号 = 前缀 + 年 + 4 位序号 | `JOB-` |
   | `contingency_pct` | 0–100 | 风险预留（%） | 报价“未知”，不能报价 |
   | `markup_pct` | 0–500 | 加价率（%） | 报价“未知”，不能报价 |
   | `engineering_rate_per_h` | ≥ 0 | 设计每小时费率 | 设计行与设计实际成本“未知” |
   | `valid_days` | 整数 1–365 | 报价有效天数 | 30 |
   | `long_lead_days` | 整数 1–365 | 提前期达到多少天算长周期件（可在设计发布前提前采购） | 15 |
   | `ship_days` | 整数 0–30 | 倒排时发货预留的工作日 | 1 |
   | `accept_days` | 整数 0–365 | 交货后多少天验收（验收那一期的计划付款日） | 10 |
   | `milestones` | `[{key, name, pct, on}]` | 分期开票的付款计划 | 不分期（没有可开的期） |

2. `milestones` 每一期：`key` 代号不重复；`name` 显示名；`pct` 0–100，各期加起来等于 100；
   `on` 是里程碑，取 `order`（接单）、`design`（设计发布）、`ship`（发货）、`accept`（客户验收）之一。
   里程碑到了（按事实，不按日期）那一期才能开票，每期只开一次；金额按报价算，最后一期补分位差。
3. 校验在 `factory/plant.py` 的 `_validate_eto`；载入后是 `factory.data.ETO`（没写为 `None`）。
4. 缺数据不填缺省数：风险预留、加价率、设计费率没写时，对应金额是“未知”，估算不能报价，作业成本、毛利也是“未知”。
5. 不改 `schema/`（零件库的 JSON Schema）、`engine/`，不碰 `tests/golden/`。

## 后果

- 演示减速器厂清单 `wenquest-gearbox.yaml` 写了示例值（风险预留 10%、加价率 30%、设计 65 美元/小时；订金 30% / 发货 60% / 验收 10%），页面标“演示工厂：费率与比例是示例值”。
- 企业工厂清单不写 `eto` 时，估算不能报价，并提示缺哪一项配置（工厂清单 `eto.contingency_pct` 等）。
- 测试：`factory/digital/tests/test_eto.py::test_plant_manifest_eto_section`。
- 代码同步（`hub/eto*.py`、`bridge/lib/erp_eto.js`、页面、测试）另提 PR，按 `factory/SYNC.md` 比对到 0 差异。
