# ADR-0023：人工复核队列与组件组装

- 状态：已接受（2026-10-01，项目负责人授权先按最优方案决定，可推翻）
- 日期：2026-10-01

## 背景

LLM 抽取结果（ADR-0021）一律未复核，不直接入库。issue #30 要求：关键字段与低置信度字段进入人工复核，复核结果写回知识库并留历史，错误分类可统计。复核后还要把抽取项组装成完整组件（端口、包络），ADR-0021 第 4 条把这一步留给了复核阶段。

## 决策

1. **存储**（迁移 `kb/migrations/0002_review.sql`）
   - `extractions`：一份抽取结果一行（来源文档、sha256、品类、厂商、型号、完整结果 JSON、状态 open / committed、组装出的组件 id）。同一文档、同一文件、同一模型与提示词版本只能入队一次
   - `review_items`：每个抽取项、每个被拒提议、每个缺失的关键字段各一行；记录进入复核的原因
   - `review_decisions`：复核决定；一项的当前决定是它最新的一条，改判就是追加新决定，历史全部保留
   - 复核项与决定只增不改：触发器禁止修改、删除与清空；抽取只允许从 open 提交为 committed（记下组件 id、提交人、时间），其余字段不可改、不可删除
   - 模拟响应（`simulated`）只能配测试专用来源入队，不得写入正式库
2. **哪些进复核**（`needs_review`）
   - 关键字段（品类 schema 的 `x-key-fields`）
   - 置信度低于 0.9
   - 带有 `issues`（单位换算、枚举映射、单位或工况不在同一行等）
   - 全部被拒提议、全部缺失的关键字段
   - 其余抽取项自动采纳，但仍是 `reviewed: false`
3. **复核动作与错误分类**
   - 抽取项：`accept`（读对了，分类 `none`）、`correct`（给出正确值，须选错误分类）、`reject`（该值不该有，须选错误分类）
   - 被拒提议：`dismiss`（核对拒得对，记录 LLM 的错误分类）、`correct`（其实读对了或另给正确值，分类 `false_reject` 等）
   - 缺失关键字段：`absent`（规格书确实没有，分类 `none`）、`correct`（补上，分类 `missed`）
   - 复核员还可以 `add` 任何没被抽到的字段（分类 `missed`）；撤回自己补的值记为 `withdrawn`，不计入 LLM 错误统计
   - 错误分类：`none`、`wrong_value`、`wrong_unit`、`wrong_target`、`wrong_page`、`wrong_condition`、`enum_mapping`、`hallucinated`、`missed`、`false_reject`、`withdrawn`、`other`；每种复核项、每种动作允许的分类由代码表限定（如抽取项改值不能选 `false_reject`）
   - 人工给出的值记为 `method: manual`、`confidence: 1`、`reviewed: true`，须给出该文档范围内的来源页码，数值用标准单位；`accept` 的值保留 `method: extracted`，标为 `reviewed: true`
4. **组装与写回**（`commit`）
   - 所有需复核项都有决定后才能组装
   - 参数与端口规格取当前有效值；整体尺寸（`dims/`）按品类规则生成包络：电机为方法兰 × 机身长的长方体加轴伸圆柱，减速器为外径或方形壳体 × 总长，驱动器为宽 × 高 × 深，轴承为外径 × 宽
   - 端口 id、类型、方向、运动方式取自品类 schema；端口坐标系按品类约定布置（安装面在 z = 0，输出侧在总长处，电机轴端在轴伸长度处），端口备注写明“按品类约定生成，布局时核对”。组装前把计划的坐标系列给复核员确认
   - 由已有字段推出的值（如印有螺纹规格即为螺纹孔、轴承内外圈的公差体系）记为 `method: computed` 并写明依据，只在该字段没有抽到时补；复核状态取所依据字段的“与”，按约定推出的（如轴承内外圈为光面）记为未复核并在计划中列出。不为满足 schema 编造字段（轴承内圈的紧固方式见 ADR-0024）
   - 端口类型有多种可能而判断不了、电机缺轴伸长度等，列为缺项，不用默认值
   - 组装出的组件须通过入库检查，缺什么就列出来，由复核员 `add` 后再组装
   - 先生成计划（组件、坐标系、需确认事项）与指纹；复核员核对后带指纹确认才写入，复核内容有变化则指纹不符，须重新查看
   - 写入用 `kb.store.import_component`，变更人是复核员，原因写明来自哪一份抽取，参数修改历史照常记录。整个提交在一个事务里，锁住该抽取，与复核决定互斥
   - 组件已在库中时须显式更新（`--update`），且厂商、型号须与原组件一致（防止 id 冲突把另一型号覆盖）；以原组件为底合并，只替换本次涉及的字段，本次没有整体尺寸时沿用原包络与坐标系；未复核的新值不得改动已复核的旧值
   - 提交后发现错误：对同一型号的新抽取（或人工录入）走同样的复核并 `--update`，修改历史记在组件上
5. **统计**：按错误分类、按 target、按品类统计当前决定，供 #31 准确率评测与提示词改进使用
6. **命令行**：`python -m kb.review enqueue / list / show / decide / add / commit / stats`，连接读 `DATABASE_URL`

## 理由

- 复核决定只增不改，保证错误分类统计和审计都能追溯
- 自动采纳的项保留 `reviewed: false`，入库后仍可查出哪些值没人看过
- 坐标系与包络属于几何布置，规格书上没有；按品类约定生成并要求确认，比让 LLM 生成更可控，也不冒充规格书数据

## 影响

- 新增数据库迁移 0002，以及 `kb/review.py`、`ingest/assemble.py`
- 低置信度阈值 0.9 与错误分类表是初始值，#31 评测后可调整（新 ADR）
