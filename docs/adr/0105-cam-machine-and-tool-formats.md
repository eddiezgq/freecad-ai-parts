# ADR-0105：问渠CAM 的数据格式——机床模型 cam-machine/1、刀具库 cam-tool/1

- 状态：已接受（2026-11-18，按 ADR-0104 第 7 节“本 ADR 接受后立刻写”；项目负责人 21:33 确认问渠CAM 方案）
- 日期：2026-11-18
- 补充：ADR-0104（问渠CAM）、ADR-0059（数控编程模块与示例机床）

## 背景

ADR-0104 要做 3+2、车铣复合、五轴联动和整台机床仿真，后处理与仿真都要知道机床的结构。现在的机床参数（`analysis/cam/machines_example.yaml`）只有行程、转速、功率、快移，只够三轴车铣：
没有回转轴、没有轴链、没有部件外形。刀具现在写在每次计算的设置里，只有种类和直径，没有刀柄外形（查碰撞要），也没有切削参数的出处。

## 决策

### 1. 机床模型 `schema/cam-machine.schema.json`（cam-machine/1）

一台机床一个 JSON 文件，后处理和整机仿真共用：

- 基本：`id`、`name`、`example`（虚构示例为 true）、`source`（数据出处，必填）、`kind`（lathe / mill / mill_turn）。
- 数控系统 `controller`：`family`（fanuc / siemens / heidenhain / gsk / hnc / knd / other，必填）、`model`、`version`（知道就写；旧格式转换过来的没有这两项）；
  已开通的功能 `features`：RTCP、倾斜面坐标系、极坐标插补、圆柱插补（没写的按没有，后处理就不用）。
- 主轴 `spindle`：最高转速（必填）、功率、传动效率、扭矩。
- 轴 `axes`：每个轴写 `type`（直线 / 回转）、`carrier`（带刀具一侧还是带工件一侧）、`direction`、回转轴的 `point_mm`、行程（回转轴可写 `continuous`）、快移速度、车床 X 的直径编程。
  - **轴链**：同一 carrier 的轴按“从机床底座往外”的顺序写。摇篮式 AC：工件一侧先 A 后 C；摆头 BC：刀具一侧先 C 后 B。运动学就按这个顺序串起来。
  - **方向约定**：`direction` 是正向指令时被带动部件的**实际**运动方向（回转轴是右手定则的转轴）。工作台带工件的 X 轴照实写 [-1, 0, 0]。
    这样运动学不必另记“工件轴取反”的规则，厂家资料或现场测出来的方向直接填。
- 刀具零位 `tool`（铣床、车铣中心必填）：所有轴零位时的刀具方向（从刀尖指向主轴）与主轴端面基准点（刀长从这里量）。
- 车床换刀点 `lathe_home_mm`、换刀时间 `tool_change_s`。
- 碰撞部件 `components`：每个部件写跟着哪个轴动（或 base、spindle），外形三选一：长方体、圆柱、三角网格文件（相对机床文件的路径）。

### 2. 刀具库 `schema/cam-tool.schema.json`（cam-tool/1）

一个刀具库一个 JSON 文件，`tools` 列表，每把刀：

- `id`、刀号 `number`、`kind`：铣削类 9 种（平底、球头、圆鼻立铣刀，钻头、中心钻、倒角刀、面铣刀、丝锥、铰刀），车削类 4 种（外圆、切槽、螺纹、镗孔）。
- 几何：直径、刀尖圆角、刃数、刃长、总长、伸出长、柄径、钻尖角、螺距；车刀写刀片 `insert`（ISO 代号、刀尖圆角、主偏角、内切圆、槽宽）。
  按种类必填：铣削类要直径、不写刀片；车削类要刀片；圆鼻刀要刀尖圆角；丝锥和螺纹车刀要螺距。
- 刀柄外形 `holder.profile_mm`：绕刀轴的回转轮廓 [[半径, 离刀尖的距离], ...]，整机碰撞检查用。
- 推荐切削参数 `cutting`：按 ISO 材料组（P M K N S H）给切削速度范围，和每齿进给或每转进给范围、最大切深与切宽；可对到 Kienzle 表的材料行。
  **AI 和程序给的参数不得超出这个范围。**
- 出处 `source`（必填）：厂家样本（`data/sources.yaml` 的 id，须登记并核过条款）、企业自己的数据、测量值，或虚构示例。

### 3. 规则

- 缺的数据不写；检查遇缺数据为“未知”，不当“通过”（同全项目规矩）。
- 示例机床、示例刀具一律 `example: true` 并在名称里写“（虚构）”。
- 现有的 `machines.yaml`（ADR-0059 的简单格式）在实现 PR 里转换成新格式，并保留读旧格式的兼容（企业已填的文件不作废）。

## 理由

- 一个文件同时供后处理和仿真用：程序里的轴、行程、回转中心与仿真里的一致，不会出现“仿真过了、机床上撞”的不一致。
- 方向照实写，比记“工件侧取反”的约定少一层出错的地方；ISO 841 的命名（刀具相对工件的正向）由后处理按 carrier 换算。
- 刀柄外形用回转轮廓，足够查碰撞，又比三维模型容易从样本里取到数。
- 考虑过：直接用 FreeCAD CAM 的刀具格式（`.fctb` / `.fctl`）。它没有刀柄外形和切削参数出处，也没有车刀刀片；实现时提供它到 cam-tool/1 的导入，不用它当主格式。
