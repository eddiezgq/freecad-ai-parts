# ADR-0046：真实关节样例的待确认方案与订货选项

- 状态：已接受（2026-10-04，Claude 决定，项目负责人可推翻）
- 日期：2026-10-04
- 补充：ADR-0037（端到端演示）、ADR-0040（公开目录数据）、ADR-0044、ADR-0045

## 背景

三个真实零件入库后（#176），用 `examples/joint2-requirement.json` 的需求组合电机 SGM7J-02A、减速器 CSF-25-100-2UH、驱动器 SGD7S-1R6A，校验结果如下：

| 检查 | 结果 | 原因 |
| --- | --- | --- |
| C2 轴孔配合 | fail | 入库的电机是光轴（轴端代码 2），CSF-2UH 输入孔要键连接（第 11 页 W Js9） |
| C3 法兰配合 | unknown | 减速器电机侧法兰按所配电机定制，目录不规定孔位（ADR-0045） |
| C4–C6 扭矩 | unknown | 效率只以曲线给出（HD 目录第 134–135 页），没有可照抄的数 |
| C7 转速 | unknown | 减速器最高输入转速未入库；它印在额定表中（第 127 页） |
| C9 供电 | fail | 驱动器电压只记了 200 V，原文是“200 VAC to 240 VAC”；相数只记了三相 |

另外，组合程序找不到法兰连接方式时会丢弃整个组合，因此端到端演示直接报告“没有候选方案”。

## 决策

1. **可配置电机法兰直连**
   - 减速器的 `motor_flange` 标为 configurable（ADR-0045）时，电机法兰直接连到它，不在库中找转接板，也不生成转接板
   - C3 为 unknown，复核结论写明“按所配电机设计输入法兰”
2. **待确认方案可以输出**
   - 端到端演示加选项 `--include-unknown`；真实组件样例使用它
   - 有任一检查 fail 的方案仍然不输出
   - 方案整体为 unknown 时，README 写“可用性：待确认”，逐条列出 unknown 的检查和缺的数据
   - 布局、BOM、URDF 照常生成
3. **只以曲线给出的参数不录入**（已由 ADR-0047 修订：效率曲线按网格读点录入，按环境温度查表）
   - 效率等只有曲线、没有印出数值的参数，保持 unknown，不按曲线估读
4. **订货选项变体**
   - 同一基本型号因订货选项（轴端、编码器等）不同、端口属性随之不同时，每个选项建一个组件
   - 型号写成基本型号加所选选项，如 `SGM7J-02A（轴端代码 6）`；组件 id 由型号转写，如 `…sgm7j-02a-6`
   - 变体在 `data/extract_jobs.yaml` 的 `variants` 中登记（`of`、`model`、`basis`），沿用基本型号的确认，变体自己的确认按字段覆盖
   - 公共尺寸取自外形尺寸表；随选项变化的属性取自型号说明表中该选项的行，以及该选项的图（如键槽尺寸）
   - 按 ADR-0044 第 4 条核对后入库
5. **确认文件支持范围值**
   - `data/review/confirmed.yaml` 中的条目可以写 `min`、`max`，代替 `value`，用于原文印的是范围的项，如“200 VAC to 240 VAC”
6. **样例需求**
   - `examples/joint-real-requirement.json` 使用 joint2 的扭矩与转速，供电写 200 V 三相
   - 端口 schema 的相数只收一个值。SGD7S-1R6A 另有单相 200 V 版本（第 63 页），这次不录；允许多个相数需要改 schema，另开 issue
7. **M6 验收口径**（2026-10-05，项目负责人决定）
   - “通过全部校验”指：没有 fail；除下列情况外没有 unknown
   - 例外：厂商目录按设计不规定、由人标为 configurable 的端口（ADR-0045），其配合校验为 unknown，不计为未通过。复核结论照常列出，并写明须按所配零件设计
   - 其他 unknown（缺数据）仍须补齐

## 后果

- 真实样例能从需求走到布局、BOM、URDF，结论如实为“待确认”，并列出缺什么
- 效率缺失使 C4–C6 保持 unknown，直到厂商给出数值，或项目负责人另行决定取值规则
- 带键轴的电机需要 SGM7J 目录原页（型号说明与键槽图）核对后才能入库
