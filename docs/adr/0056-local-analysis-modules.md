# ADR-0056：CAD 与数字工厂集成——本地运行的分析模块（M10）

- 状态：已接受（2026-10-06，项目负责人确定运行形式、第一批模块与代码归属）
- 日期：2026-10-06
- 补充：ADR-0055（企业私有库）、ADR-0029（候选求解）、ADR-0036（FreeCAD 工作台）

## 背景

问渠数字工厂（私有仓库 wenquest 的 `factory/digital`）已做成并验证了一批计算：多体动力学（MuJoCo）、有限元强度与模态
（gmsh + CalculiX）、疲劳寿命（雨流计数、S-N、Miner）、热分析与热—结构耦合、设计优化（optuna）、拓扑优化、
流体（OpenFOAM）、数控编程、数字孪生。每项都有与教材公式或解析解对照的标准题。它们现在跑在 Linux 服务器的
Docker 里，通过网页使用。

项目负责人决定：先把 CAD（本项目的 FreeCAD 选型、布局、校验、BOM）与数字工厂的这些功能集成，**每个功能是单独的
模块**，给企业提供**本地运行版**。决定：

1. 运行形式：两者都做——分析模块做成 FreeCAD 内置模块，装好 FreeCAD 就能在本机算；工厂部分（ERP、车间、孪生的
   现场数据）用本地 Docker 接入
2. 第一批模块及顺序：运动学 · 多体动力学 → 有限元强度 + 疲劳寿命 → 热分析 + 设计优化 → 数字孪生 · 预测性维护
3. 代码归属：数字工厂的计算代码搬进本仓库（Apache-2.0 开源）

## 决策

1. **新包 `analysis/`，每个功能一个子包**：`analysis/mbd`、`analysis/fea`、`analysis/fatigue`、`analysis/thermal`、
   `analysis/optimize`、`analysis/twin`，共用 `analysis/common`（材料库、网格、求解器查找）。
   - 每个模块对外只有一个约定：`MODULE`（id、名称、依赖）、`available()`（依赖是否齐全及缺什么）、
     `run(setup) -> result`（输入输出为 JSON 可序列化的字典，有 JSON schema）
   - 结果外壳统一为 `schema/analysis-result.schema.json`（设置、数据、核对、局限、提示）；`data` 的结构由各模块说明并由测试检查
   - 材料性能统一为 `schema/material.schema.json`（标准单位、每条注明出处，没有出处的性能不写）
   - 模块之间只通过结果字典衔接（如动力学的关节力矩记录 → 疲劳的载荷谱），不互相导入内部函数
   - 依赖分开装：`pip install -e ".[mbd]"`（mujoco）、`".[fea]"`（gmsh）、`".[optimize]"`（optuna）；缺依赖时
     模块显示“不可用”及安装方法，其余模块照常可用
2. **求解器在本机运行，不联网**
   - CalculiX（ccx）与 gmsh：优先用 FreeCAD 自带的（Windows、Linux 都随 FreeCAD 安装），也可用环境变量
     `FAP_CCX`、`FAP_GMSH` 指定
   - 每次计算在子进程中运行，有时限；结果写在企业指定的工作目录，不上传
3. **与选型的衔接（本集成的价值所在）**
   - 多体动力学 → 选型：关节力矩、转速记录算出峰值、均方根、最高转速，直接生成需求（`requirement.schema.json`），
     交给现有的候选求解与 11 项校验，选的是库里真实的电机、减速器、驱动器（替代数字工厂里的“典型值参数表”）
   - 布局 → 有限元：FreeCAD 场景中的零件形状（STEP）作为几何，载荷取自需求或动力学结果
   - 动力学 / 现场记录 → 疲劳；温度场 → 热应力；有限元 → 设计优化
   - BOM → 数字孪生：按 BOM 中零件的样本参数（额定寿命、额定转矩、轴承额定动载荷）建孪生，缺参数的项显示“待确认”
4. **可信规则**
   - 每个模块带标准题（与教材公式或解析解对照，误差门槛沿用数字工厂各轮的验收值），进自动测试；先证明算得对再用
   - 分析结果是计算，不是样本数据：**不写入零件参数**，只作为报告、需求或校验的输入；结果中注明方法、网格、
     求解器版本与局限（如线弹性、尖角奇异点）
   - 材料性能每条注明出处（沿用数字工厂材料库的出处）；缺的性能不估，模块报“缺数据”
   - 动力学选型用的电机、减速器参数一律来自零件库（公共库或企业库），不再用典型值表
   - `engine/` 仍是纯函数；`analysis/` 可以启动本机求解器子进程，但不联网、不调用 LLM
5. **FreeCAD 界面**：工作台菜单“分析”列出各模块及可用状态；每个模块一个停靠窗口（设置 → 计算 → 结果云图 / 曲线 →
   报告），结果着色显示在 FreeCAD 三维视图中。AI 对话可通过 MCP 工具调用同一批模块
6. **本地工厂（Docker）**：第一批模块完成后另写 ADR，确定本地版包含哪些服务（数据总线、历史库、孪生现场数据、
   ERP 接口）以及 FreeCAD 与本地工厂之间传什么（设计发布、BOM、工艺）

## 理由

- 中小企业要的是“装上就能算”，不愿意也不会维护服务器；FreeCAD 已自带 CalculiX 与 gmsh，分析模块随插件安装即可
- 单独的模块便于按需安装、分别验收、分别给企业开通；依赖缺失只影响该模块
- 多体动力学接选型，把“算出要多大的力矩”与“库里哪个型号满足、装得上”连成一条线，这是本项目区别于通用 CAE 的地方
- 代码开源，商业价值放在企业数据、服务与定制上

## 后果

- CI 需要安装 CalculiX（apt `calculix-ccx`）、gmsh、mujoco、optuna；求解器相关测试在 CI 中必须运行，本地缺求解器时跳过
- 流体（OpenFOAM）、数控编程、拓扑优化暂不在第一批：OpenFOAM 在 Windows 上没有随 FreeCAD 安装的版本，留待本地
  Docker 版
- 搬入的代码按本仓库的约定改写：标准单位与单位后缀、ruff、测试不联网；不原样复制网页和服务端代码
