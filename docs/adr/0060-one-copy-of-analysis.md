# ADR-0060：工厂计算服务与 analysis/ 合并为一份（M12）

- 状态：已接受（2026-10-07，项目负责人同意按计划继续；落实 ADR-0058 第 4 条“计算重复以后另写 ADR”）
- 日期：2026-10-07
- 补充：ADR-0056、ADR-0058、ADR-0059

## 背景

M10、M11 把数字工厂的计算搬进 `analysis/`，做成 FreeCAD 里本机运行的模块；同时 `factory/` 整套搬入（ADR-0058），
工厂网页的“仿真与分析”“运动与动力”“流体”“数控编程”“设计优化”仍由 `factory/digital/cae/` 自己的一份代码算。
同一个算法两份代码：改一处、漏一处，标准题也要两边各跑。逐文件比对（2026-10-07）：

| 层 | 文件 | 与 analysis 的相似度 |
| --- | --- | --- |
| 求解内核 | cfd_heat、mbd、cam_sim、solve、modal、thermal、foam、geometry、cfd | 0.75–0.95（同源，改动小） |
| 上层编排 | topo、cam、fatigue、optimize、materials | 0.06–0.35（接口已分开演化） |

## 决策

1. **求解内核只留 `analysis/` 一份**。工厂 `cae/` 里同源的内核文件改成薄转接层：保留工厂原来的函数名和参数，内部调用
   `analysis` 的实现（例如工厂按机床编号、`analysis` 按机床参数字典，转接层查表后传入）。工厂的 HTTP 服务、实验指导书、
   报告生成、网页特有的输出照旧在 `cae/`。
2. **工厂需要而 `analysis` 没有的功能，补进 `analysis`**，作为可选输出或可选参数（例如流体的表面云图、速度截面、流线），
   不改变 FreeCAD 一侧现有结果。
3. **上层编排（topo、cam 刀路、fatigue、optimize）不强行合并**：只把其中的计算核心（SIMP 迭代、刀路与后处理的公共部分、
   雨流计数、S-N）改为调用 `analysis`；工厂网页的流程、教学用的接口保留。
4. **材料数据本期不合并**：`analysis` 的材料库只收印出的值（ADR-0056），工厂的教学材料表含标明“估算”的值，规则不同；
   工厂继续用自己的表，以后另议。
5. **镜像与测试**：工厂镜像的构建上下文改为仓库根目录（根目录 `.dockerignore` 用白名单，只放进 `factory/`、`analysis/`、
   `kb/`、`schema/`），镜像内 `PYTHONPATH` 含 `analysis` 所在目录；CI 的 `factory` 作业先 `pip install -e .` 再跑工厂测试。
6. **验收的底线**：每一步合并后，工厂自己的测试（不改断言，只允许改导入位置）与 `analysis` 的标准题都要通过，
   CI `factory-local` 真起一次本地工厂。
7. **顺序**：镜像与测试接通 + 流体内核 → 有限元与热分析内核 → 多体动力学内核 → 数控编程内核 → 拓扑优化、疲劳、优化的计算核心。

## 后果

- 以后修一个算法只改 `analysis/`，FreeCAD 与工厂网页同时生效；标准题只维护一份
- 工厂镜像依赖仓库根目录的代码，构建上下文变大，用白名单控制
- 工厂测试的导入位置会有少量改动（被测函数搬家时），断言不改
