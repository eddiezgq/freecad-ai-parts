# ADR-0049：方案存进 .FCStd、拖动回写、AI 改动先成提案（M8 第二步）

- 状态：已接受（2026-10-05，项目负责人选定三项）
- 日期：2026-10-05
- 补充：ADR-0048、ADR-0042（操作录制）、ADR-0036（主线程执行器）

## 背景

M8 第一步（ADR-0048）让人和 AI 在 FreeCAD 中共用一个场景，但有三处不足：

- **方案不随文件保存**：场景只在服务端内存里；布局文档每次改动都被关掉重建，用户另存的文件名也会丢
- **手动拖动不回写**：在 FreeCAD 中移动零件不改变场景，下一次刷新就被覆盖
- **AI 改动直接生效**：AI 放置、连接零件后，人只能事后手动改回

项目负责人选定这三项为第二步。

## 决策

1. **布局文档就地更新**
   - 场景改动后，在同一个 `FapLayout` 文档中删除并重建 AI Parts 的对象，不再关闭重建文档
   - 用户另存后的文件名、视角、其他对象保留
2. **方案存进 .FCStd**
   - 文档中有一个方案记录对象 `FapProject`（隐藏），以 JSON 字符串属性保存：
     - 格式版本 `fap-project/1`
     - 需求（若有）
     - 场景：各实例的组件 id 与位姿，连接（含 roll、offset）
     - 最近一次校验的结论与报告
     - 所用组件数据的快照（便于别人打开文件时知道用的是什么数据）
     - 组件库说明、保存时间
   - 每次场景改动或校验后更新；随用户保存 .FCStd 一起保存
   - “恢复方案”命令：读当前文档中的 `FapProject`，清空场景，依次调用 `place_component`（按记录的位姿）与 `connect_ports`（按记录的顺序）重建
     - 组件库中缺某个组件时报告，不用快照替代（快照只供查看）
   - 记录的读写、由记录得出重建调用序列，都是纯函数（`freecad_addon/core/project.py`）
3. **拖动回写**
   - 文档观察者监视 AI Parts 零件对象的 `Placement`；用户改动（不是同步造成的）停止 0.4 秒后，按新位置调用 `place_component`（位置与转轴、转角）
   - 已连接的零件按刚性组整体移动（`place_component` 已如此）；随后照常同步显示与校验
   - 拖动接口标记不回写（标记跟随零件）
   - 回写调用记为 `user`
4. **AI 改动先成提案**
   - 对话面板加开关“AI 改动先审阅”，默认开
   - AI 每一轮开始前记下场景快照；这一轮中 AI 照常调用工具（可做干涉检查、截图自查）
   - 一轮结束后，若场景有变化，校验窗口列出提案：增加、删除、移动的实例，新增、删除的连接，AI 本轮最后的文字说明，以及校验结论
   - “接受”保留；“拒绝”按快照恢复：删除全部实例，再按快照重建
   - 提案未处理时，新的手动改动或对话视为接受
   - 场景差异的计算是纯函数
   - 录制中记下提案的接受或拒绝
5. **这一步不做**
   - 不改 schema，不改引擎
   - 不支持多个布局文档同时存在（仍只有 `FapLayout`）

## 后果

- 方案能保存、交给别人、再打开接着改
- 人可以直接拖动零件，AI 与校验看到的是同一个位置
- AI 的改动可以审阅、撤回
