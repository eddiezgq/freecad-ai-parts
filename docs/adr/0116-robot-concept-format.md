# ADR-0116：整机方案格式 `robot-concept/1`（M44 第 0 步）

- 状态：已接受（2026-11-22，按 ADR-0115 第 4 节第 1 步施工；ADR-0115 项目负责人 2026-11-22 确认“好，继续”）
- 日期：2026-11-22
- 补充：ADR-0097（多体动力学模型 `mbd-model/1`）、ADR-0100（AI 自主设计零件）、ADR-0115（原创机器人案例）

## 背景

ADR-0115 要 AI 从一句需求提出整机构型，再由代码初筛工作空间与奇异、算载荷、选件、仿真。AI 的提议和代码之间需要一个结构化的格式：
AI 照它填，代码照它核、照它建多体模型。现有格式都不合适——`system/1` 是“选好的组件 + 端口连接”，没有运动学；`mbd-model/1` 是构件、
质量、惯量都给全的仿真模型，质量这时还不知道（要选件、设计自制件之后才有）。

## 决策

新 schema `schema/robot-concept.schema.json`，格式名 `robot-concept/1`，描述“还没选件的整机构型”：

| 字段 | 内容 |
|---|---|
| `kind` | `serial_arm`（串联臂）、`gantry`（直角坐标 / 龙门）、`mobile_base`（移动底盘）、`other` |
| `reason` | AI 提这个构型的理由（给人看，代码不用） |
| `base` | 安装方式：`floor`、`table`、`ceiling`、`wall`、`mobile`；底座高度 |
| `links` | 杆件：id、长度、外形（`tube`、`box`、`plate`、`profile`、`custom`）、截面（按外形写带名字的尺寸：圆管外径 `od_mm`、内径 `id_mm`；方管 / 方块宽 `width_mm`、高 `height_mm`、壁厚 `wall_mm`；板宽、厚 `thickness_mm`；型材宽、高）、材料 id（可选）。**不写质量**——质量在选件、设计自制件之后由代码算 |
| `joints` | 关节：id、类型（`revolute`、`prismatic`、`wheel`）、父件（`base` 或杆件 id）、子件、零位时在父件坐标系里的原点与轴线、行程、轮子半径；传动（`direct`、`reducer`、`belt`、`ballscrew`、`rack_pinion`、`belt_linear`）与传动比 / 导程；`module_group`：同一组的关节用同一种关节模组 |
| `end_effector` | 末端：类型（`gripper`、`vacuum`、`needle`、`tray`、`none`、`custom`）、相对最后一根杆末端的偏移、说明 |
| `tasks` | 典型动作：`joint_move`（各关节从哪到哪、用时、停顿）、`cartesian_move`（末端从哪点到哪点）、`drive`（移动底盘：速度、加速度、坡度、门槛高度） |
| `workspace` | 需求要求够得着的点（mm） |

约定：

- 单位只用 mm、°、s、kg、m/s、m/s²（字段名带单位后缀）；位置、轴线写零位时在父件坐标系里的值，坐标系右手、z 向上；
  每根杆件的坐标系原点在带动它的关节处、零位时与父件同向；工具点写在末端所在杆件的坐标系里；杆件长度只用于外形与质量；
- 只写构型与设计取值，不写零件数据：电机、减速器、轴承由选件得到，杆件质量由材料与外形算；AI 填的数都是设计提议，代码逐项核对；
- 结构上的一致性（id 唯一、父子都存在、构成一棵以 `base` 为根的树、`revolute` 有角度行程、`prismatic` 有直线行程、`wheel` 有半径、
  传动比与导程只在对应的传动方式下出现）由 schema 能表达的部分在 schema 里检查，其余在代码 `analysis/robot/concept.py` 里检查；
- 代码把它变成 `mbd-model/1`（质量、惯量在那时填）做仿真；构型初筛（工作空间、奇异、粗载荷）直接用它的运动学。

## 理由

- 构型与零件数据分开：AI 擅长提结构，零件数据必须来自库；分开后各自可核。
- 用“父件—子件树 + 每个关节的原点与轴线”而不是 DH 参数：AI 写起来不易错、人看得懂，龙门、底盘、串联臂一种写法；
  需要 DH 时由代码换算。

## 影响

- schema 单独成 PR（本 ADR）；样例放 `tests/fixtures/robot-concept/`，合法、非法各几份；
- 下一步 44.1 的 `analysis/robot/` 读这个格式。

补充（2026-11-22，合并前）：截面原写成数组 `section_mm`（圆管 [外径, 内径]），真实 AI 运行（design-eval 45057334760）把圆管写成 [外径, 壁厚]、板写了三个数；
改成按外形写带名字的字段，不会再看错。
