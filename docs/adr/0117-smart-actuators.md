# ADR-0117：一体化关节模组（小型机器人用的总线舵机）进零件库

- 状态：已接受（2026-11-22 17:53，项目负责人：“好”）
- 日期：2026-11-22
- 补充：ADR-0115（原创机器人案例，44.3 “缺什么先列出，再整本导入公开目录”）、ADR-0040（公开目录数据）、ADR-0099（品类）

## 背景：案例 A 跑出来的缺口

案例 A（教学用桌面机械臂，负载 0.5 kg、臂展 350 mm）走完“构型 → 载荷 → 选件”（ADR-0115 44.3 之一）：

- 零件库里能选的只有工业伺服一条链：安川 SGM7J（最小 50 W，0.3 kg）+ 哈默纳科 CSF（最小 CSF-14）+ 安川 SGD7S 驱动器。
- CSF-14 的输入孔 Ø6，SGM7J 最小的电机轴 Ø8，引擎判装不上；所以每个关节最轻也是 SGM7J + CSF-17 ≈ 1 kg。
- 结果：五个模组 5.4 kg，是负载的 10 倍多；肩部力矩大半来自扛着后面的模组；AI 给的“大小两种模组”方案也只轻 0.2 kg，因为库里没有更小的。
  外加 200 V 交流供电、一个关节一台驱动器，放在教学桌面上不合适，“外购件成本尽量低”也做不到。

这正是这类产品真正用的东西缺了：教学臂、桌面臂普遍用**一体化关节模组**（电机、减速器、驱动器、编码器做在一个壳里，12 V 左右直流、总线串联），
比如 ROBOTIS Dynamixel。它不是“电机 + 减速器 + 驱动器”三件，现有品类装不下。

## 决策

1. **新品类 `smart_actuator`（一体化关节模组）**，单独的 schema PR。参数（单位按项目规定）：
   峰值（堵转）力矩 `stall_torque_nm` 与对应电压、空载转速 `no_load_speed_rpm`、连续额定力矩 `rated_torque_nm`（厂商给才写）、
   质量、减速比、回差 `backlash_arcmin`、编码器分辨率、工作电压范围、通信总线；端口：输出法兰、安装面、电源与总线接口；包络按外形尺寸。
2. **第一个来源：ROBOTIS e-Manual**（Dynamixel X 系列整个系列一次导入，约 20 个型号）。内容在 GitHub 公开、MIT 许可；
   导入前在 `data/sources.yaml` 登记并核实条款（`terms_checked: true`），照 ADR-0040 只取规格表里的数。
3. **选型规则（engine，纯函数）**：峰值需求 × 安全系数 ≤ 堵转力矩；转速按直流电机的直线力矩—转速关系 n(T) = n₀(1 − T/Tₛ) 核对；
   连续力矩：厂商给了连续额定就比，**没给就判待确认**（Dynamixel 的规格页明说堵转力矩不是连续额定，不拿它当连续值）；
   回差进重复定位精度的核算（选件后那一项不再全是待确认）。
4. **整机选件**（`assist/robot_build.py`）：每个模组组在两条链里选——工业伺服三件套、一体化模组——按质量取轻的；
   报告并列两条链的结果，让人看到代价差在哪里。
5. 成本仍然判不了：e-Manual 没有价格；价格要等有公开价格表、条款允许的来源再说。

## 后果

- 案例 A 的模组质量预计从约 1 kg 降到 0.1–0.3 kg 一个，肩部力矩随之大降；连续力矩会是“待确认”（厂商没给），这一点如实报。
- 之后的案例 B（裁片上下料）、C（送物机器人）也会用到同类模组（ROBOTIS 也有 Y 系列、P 系列较大的型号）。
