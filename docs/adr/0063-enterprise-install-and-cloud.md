# ADR-0063：企业安装版、云服务器远程部署与 AI 模型切换（M15）

- 状态：已接受（2026-10-07，项目负责人：“按建议”；“AI 接口要 Claude 和 DeepSeek 可以切换，国内自动选 DeepSeek，其他地方选 Claude”；
  “我们提要求，企业都会满足”）
- 日期：2026-10-07
- 补充：ADR-0058（本地版）

## 背景

数字工厂现在有两种跑法，都不能直接交给企业：

- **本地版**（`factory/local/`，ADR-0058）：Docker 一条命令启动，但登录是“填名字进入”、人人按老师权限，只能在内网或自己电脑上用；
  第一次要在现场构建镜像（10–20 分钟）；默认接模拟 ERPNext。
- **服务器部署**（`factory/deploy/`）：问渠平台自己的服务器用，有安装、升级、备份、真 ERPNext；但域名、登录都依赖问渠学习平台
  （统一登录 `learn.<域名>`），镜像由另一个仓库的流程构建。企业的云服务器上没有学习平台，跑不起来。

AI 方面，工厂的模型网关（`factory/digital/hub/llm.py`）已能调 Claude 与 DeepSeek（OpenAI 兼容接口），但只要配了 Claude 密钥就用 Claude，
没有按地区选择、没有出错换另一家；FreeCAD 一侧（对话面板、需求解析）只接 Claude。

## 决策

1. **一个 AI 模型网关，两家可切换**：
   - 选择：`WQ_AI_PROVIDER` = `auto`（缺省）| `claude` | `deepseek`。`auto` 时看 `WQ_AI_REGION`：`cn` 用 DeepSeek，其他用 Claude；
     安装脚本按服务器所在地区写好 `WQ_AI_REGION`（问一次，或按云厂商区域、时区推断后让人确认）。
   - 回退：选中的一家没配密钥、调用出错或超时，换另一家；两家都不可用时照现在的规则回答，不报错。每次回答记下实际用的是哪家。
   - 管理员可在工作台“系统设置”里切换（写库，优先于环境变量），并能看到两家的密钥是否配好、最近一次调用结果。
   - FreeCAD 一侧（对话面板、需求解析）同一套规则：`FAP_AI_PROVIDER`、`FAP_AI_REGION`、`ANTHROPIC_API_KEY`、`DEEPSEEK_API_KEY`；
     放在新包 `llm_gateway/`（Anthropic + OpenAI 兼容两个实现、同一个工具调用接口），`engine/` 仍只接收注入的客户端（不直接联网）。
   - 规格书抽取（`ingest/`）不在此列：它要把规格书页图交给模型看，仍只用 Claude（数据入库还要人核对）。
   - 密钥只从环境变量 / 配置读，不入仓库；测试不调真实模型，两家都用录好的回答。
2. **企业账号**（`WQ_AUTH=enterprise`）：用户名 + 密码（加盐慢哈希）；管理员在工作台“账号与角色”加人、分配角色、重置密码、停用；
   安装时建第一个管理员；登录失败限速。“填名字进入”（`local`）只留给演示与内网试用；问渠线上（`wenquest`）不变。
3. **预构建镜像**：合并到 main 时 CI 构建工厂、桥接两个镜像，推到 GitHub 容器仓库（`ghcr.io/eddiezgq/...`，带版本号与 `latest`）；
   企业安装直接拉取，不在现场构建。镜像不含任何密钥与企业数据。
4. **企业安装包**（`factory/enterprise/`）：一个 compose 文件 + 安装 / 升级 / 备份 / 恢复 / 状态脚本，与问渠学习平台无关：
   - 服务：枢纽与网页、数据总线、历史库、桥接、计算服务、真 ERPNext（`frappe/erpnext`，与 `factory/deploy` 同一版本）、Caddy（自动 HTTPS）；
     仿真车间只在演示模式启动；
   - 对外只开 80/443（网页、ERPNext 走子路径或子域名）与 8883（现场网关的 MQTT over TLS，账号密码）；Node-RED 编辑器、数据库不对外；
   - `install.sh`（Linux 云服务器）、`install.ps1`（Windows 本地）：检查环境与资源 → 拉镜像 → 生成密钥 → 初始化 ERPNext 与桥接钥匙 →
     建管理员 → 设 AI 地区 → 首次备份；可重复运行；
   - `deploy.sh 用户@服务器 --domain 工厂域名`：从我们这边经 SSH 把安装包传过去并运行安装；以后 `--upgrade` 升级、`--status` 看状态。
5. **现场网关**（`factory/gateway/`）：工厂里一台小工控机跑 Mosquitto 桥接，把现场设备与采集器的 MQTT 主题经 TLS 转到云上；
   断网时本地缓存、恢复后补发（Mosquitto 桥接的持久队列）。设备本身的接入（PLC 地址表等）仍按现场配置。
6. **企业上线清单**（`docs/enterprise-onboarding.md`）：我们对企业的要求——服务器配置（4 核 16 GB 100 GB 起，Ubuntu 22.04/24.04）、
   域名与 DNS、开放端口、SSH 账号、现场网关、ERPNext 管理员、设备清单与通讯方式、主数据导入表、AI 密钥（Claude 或 DeepSeek）；
   以及安装后的验收步骤。
7. **验收**：CI 新作业在干净机器上用企业安装包（本机域名、内部证书）一条命令装好，建账号登录，跑平缝机的工厂一侧全流程；
   AI 网关用两家的录制回答分别测通并测回退。项目负责人有云服务器时照上线清单远程部署一次。

## 后果

- 企业可选本地安装或云服务器部署，两者同一套镜像与脚本；问渠线上与教学用法不受影响
- AI 在国内外都能用；换模型是改设置，不改代码
- 我们在本会话里连不上企业服务器：远程部署由团队或企业授权的运维执行，脚本与清单由这里写好、测好
