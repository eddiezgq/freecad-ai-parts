# ADR-0067：私有仓库的 CI 预算——按改动范围跑重作业，每晚全量

- 状态：已接受（2026-10-09，项目负责人：仓库转私有，“好”）
- 日期：2026-10-09
- 补充：ADR-0063（企业安装版）、ADR-0065（帮助视频）、ADR-0066（Windows 安装包）

## 背景

项目负责人为保护思路，2026-10-09 把仓库改为私有，开通 GitHub Pro（每月 3000 分钟 Actions、2 GB 镜像存储）。
公开时 CI 免费，每个 PR 跑全部作业：单元测试 7 分钟、FreeCAD 测试 2 分钟、数字工厂 9 分钟、本地版加录视频 11 分钟、
企业版加录视频 11 分钟、Windows 安装包与验收 12 分钟（按 2 倍计费）。一个 PR 连同推送几次和合并后，约 250 分钟；
按近两周的节奏（每月约 40 个 PR）约 1 万分钟，远超额度。

## 决策

1. 每次 CI 先由 `scope` 作业（`.github/scripts/ci_scope.sh`）决定跑哪些作业：
   - **单元测试（含数据库）与 FreeCAD 测试：每次都跑**（规则要求数据库测试在 CI 里运行）；
   - **数字工厂测试**：改了 `factory/`、`analysis/`、`kb/`、`schema/`、`licensing/` 或 CI 本身时跑；
   - **本地版启动、企业版安装、录帮助视频**：改了 `factory/`、`licensing/` 或 CI 本身时跑；
   - **Windows 安装包与验收**：改了 `installer/`、`freecad_addon/install.py`、`freecad_addon/bundle.py`、`pyproject.toml`
     或其工作流时跑。
2. **每晚定时全量**（UTC 7 点多）：main 自上次成功的定时运行以来有新提交才跑，否则什么都不跑。帮助视频与 Windows
   安装包在 main 上的定时、手动、推送运行里发布。
3. **随时全量**：Actions 页面手动运行，或给 PR 加 `full-ci` 标签。
4. 同一个 PR 再次推送时，取消还在跑的上一次。
5. 镜像随仓库变为私有，按存储计费：镜像工作流构建后每个镜像只留最近 10 个版本（`latest` 与版本号标签不删）；
   `licensing/` 改动也触发镜像构建（工厂镜像里有席位服务）。
6. 预算由项目负责人在 GitHub 账单里设上限（Actions、Packages 超出部分），到上限即停，不超支。

## 后果

- 预计每月 3000–4000 分钟，超出部分每月十几美元
- **取舍**：没删任何测试，但没改到相关目录的 PR 不跑重作业；若改动间接影响工厂、安装包，要到当晚全量才发现，
  不会在合并前拦下。合并前拿不准时加 `full-ci` 标签
- 私有镜像与 Release 附件（Windows 安装包、帮助视频）要登录或令牌才能拉取下载：企业安装用 `--registry-token`，
  试点企业的安装包由项目负责人下载后转交
