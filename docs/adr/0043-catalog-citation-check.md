# ADR-0043：多型号目录的引用核对规则

- 状态：已接受（2026-10-03，Claude 决定，项目负责人可推翻）
- 日期：2026-10-03
- 补充：ADR-0021（引用核对）、ADR-0040（公开目录数据）

## 背景

第一次云端真实抽取（运行 37085373625，#157）覆盖 3 份规格书、23 个型号。核对程序拒收了大部分数值，没有一个组件通过入库把关。

排查（#160）发现，问题出在核对程序不认识真实目录的排版，而不是模型读错：

- 多型号目录的正文行把各型号的值排成一行，例如 `Rated Output*1 W 50 100 150 200 400 600 750`，且带脚注标记
- 表格有纵向合并的单元格，表头分多层，型号前缀写在表头、各列只写后缀
- 外形尺寸表的型号代码印在表格外，续页没有边框，表格识别不出来
- 符号字体的私用区字形：U+F09E 是 N·m 中的点，U+F06F 是型号中的占位框
- 格子里名义值后面带着公差（`30 0 -0.021`），或者括号里另有带制动器型号的值（`85.5(125.5)`）

## 决策

核心要求不变：

- 每个值都要在规格书上找到依据
- 多型号目录中，值必须出自目标型号所在的列或行

在此要求下，核对程序按下列排版定位型号和叫法。每一种都要求有印出的依据，找不到依据时拒收，不猜。

1. **合并单元格**：表格行首的空格子取上一行同列的文字（表头前两行不补）。
2. **型号的位置**
   - 型号整格印出，或表头写前缀、各列写后缀（`Model SGM7J-` ¦ `A5A` ¦ `02A`）
   - 按尺寸、减速比分行：行首的数字键须与型号的数字分段一致（CSF-14-50 对应 `14 ¦ 50`）
   - 按尺寸分列：表头以 `Size` 开头，取尺寸所在的列
   - 另一系列的行（如并列的 `CSG Series` 与 `CSF Series`）不算
   - 型号格为空时，用表格外的正文行确定型号：该行首词是型号代码，其余内容与这一表格行逐格相同
3. **型号是否印出**：型号未整串印出也算，只要按目录的编排分开印出：前缀加列后缀，或数字分段作行键、其余分段都印在所选页上。
4. **正文中的逐型号数值行**
   - 先去掉脚注标记与单位，再按表头的型号列序取第 k 个数
   - 整行只有一个数时，按各型号共用的合并格处理，并注明
   - 数的个数与型号列数对不上时拒收
   - 夹着文字的规格行（如 `200 VAC to 240 VAC`）按共用的规格行核对
5. **叫法在表头**
   - 数值须在叫法所在的列（含向右合并的空格）
   - 叫法末尾的词在下一层表头时，按前面的词定位
   - 单位写在该列表头里也算印出
6. **同表另一行**：仅限按尺寸、减速比分行的表。引用的是同表另一行，但目标型号所在行同一列印着同一个数时，接受并注明。
7. **格子中的附加内容**：名义值后的公差、括号里另一规格的值，取名义值并注明。
8. **字形与空白**
   - `∗`、`＊` 视同 `*`
   - 私用区字形 U+F09E、U+F06F 在比较时去掉
   - 单位比较不要求空白一致
   - 本页写明 `Unit: mm` 时，mm 不与本页其他长度单位混淆
9. **没有边框的表**
   - 另用 pdfplumber 的“文字”策略按对齐切出版面行（`Page.layout_rows`）
   - 版面行只用于核对，不交给 LLM，因此请求不变，录制照常回放
   - 原有的行核对不通过时，再用版面行核对一次。这一次必须确认型号所在的行或列，判断不了的不收

## 后果

- 回放同一批录制（不调用模型），通过核对的值从约 120 项增加到约 340 项。电机与减速器的额定参数已能通过 AI 复核
- 仍未入库的原因如下：
  - 外形尺寸只有一个模型报出，或印在图纸上（驱动器的宽、高、深）
  - 部分续页的版面切分仍不完整
- 规则都有单元测试（`tests/test_synthetic_multi.py`），用安川、Harmonic Drive 的真实排版构造
- `python -m ingest.jobs diagnose` 与工作流的 `diagnose` / `report_issue` 选项用于继续排查。输出只含参数表的行，与已提交的引用同类
