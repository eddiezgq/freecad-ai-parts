# ADR-0125：有限元算例的面引用加“面签名”和 STEP 散列

- 状态：已接受（问渠 CAD 0.3.6 细则 B3，Eddie 2026-11-24 确认）
- 日期：2026-11-24

## 背景

算例（`fea-study/1`）的支承、载荷只按“面编号”指定面。面编号是 gmsh 读 STEP 时排出来的，几何一改（开孔、倒角、加长、开槽、倒圆）编号就可能变，
算例照算，载荷和约束静默落到别的面上，没有任何提示。《有限元》书第 47 章做了五种常见改动，复现了这个问题，并用“面签名”的原型 5 / 5 认对
（`fem-ai-textbook/docs/给问渠有限元的线索.md` 第 40 条）。

## 决策

1. 实体（`bodies[]`）加两个可选字段：
   - `step_sha256`：写算例时 STEP 文件的 SHA-256；
   - `face_signatures`：被支承、载荷引用的每个面的签名，键是面编号，值是类型、面积、中心，平面另有法向、柱面另有轴线。
2. 计算时：
   - 有 `step_sha256` 且和文件一致：照面号算；
   - 散列变了：对每个被引用的面，在新几何里找类型相同、法向（或轴线）夹角 < 1°、中心最近的面（距离按包围盒对角线归一）；
     面积比在 [0.5, 2] 以内、且第二近的候选明显更远时算认准，按新面号算并在结果里记下“旧面号 → 新面号”；
     认不准（找不到、不唯一、面积差太多）就**拒绝计算**，列出哪几个面认不准，请人确认；
   - 没有签名的旧算例照旧计算，结果里标“面引用未核对”。
3. 起草算例的程序（AI 起草、面板保存）写算例时顺手填上散列和签名。

## 理由

- 只存面号省事，但几何一改就静默出错；这类错误反力平衡等核查都查不出来（载荷照样平衡，只是落在别的面上）。
- 签名只用几何量（类型、法向、面积、中心），不依赖 gmsh 的编号规则；书里的原型对五种常见改动全部认对。
- 认不准时拒绝而不是猜，符合“缺数据判 unknown、不判 pass”的规矩。
- 考虑过用 OCC 的拓扑命名（TNaming）：要接 FreeCAD 内部，跨进程不可用，代价大，暂不采用。

## 影响

- schema 只加可选字段，旧算例不受影响。
- 实现另一个 PR：`analysis/fea/study.py` 计算前核对与重认；起草程序写签名；回归题为书中五种改动。
