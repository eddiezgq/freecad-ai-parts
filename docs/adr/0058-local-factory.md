# ADR-0058：本地工厂——数字工厂整套搬入，做成企业本地运行版（M10 第六步）

- 状态：已接受（2026-10-06，项目负责人选择“整套搬过来”）
- 日期：2026-10-06
- 补充：ADR-0056（本地分析模块）、ADR-0057（数字孪生）

## 背景

问渠数字工厂（私有仓库 wenquest 的 `factory/`，约 500 个文件、5 MB）是一套用 Docker 运行的虚拟工厂：数据总线
（Mosquitto）、历史库（PostgreSQL）、枢纽服务（看板、AI 工厂助手、MES、厂情中枢、工作台网页）、仿真车间、虚拟 PLC、
Node-RED 桥接、计算服务（有限元、流体、数控、优化），ERP 用 ERPNext。它原来部署在服务器上，供教学和演示。

项目负责人决定：把数字工厂**整套搬进本仓库**，做成企业在自己电脑或内网服务器上运行的本地版，并与本仓库的 CAD
（FreeCAD 选型、布局、校验、BOM、分析模块）连起来。

## 决策

1. **位置与来源**：仓库根目录 `factory/`，内容为 wenquest 仓库 `factory/` 在提交 `8710ae0c` 时的全部受版本管理文件，
   原样搬入（一个 PR），`factory/README.md` 开头注明来源与提交号。之后在本仓库维护，不再与 wenquest 同步
   - 不搬：任何 `.env`（只有 `.env.example`）、构建产物、`node_modules`；密钥一律从环境变量读取（原代码已如此）
2. **独立的子项目**：`factory/` 有自己的依赖（`factory/digital/requirements.txt`）、Dockerfile、compose 与测试；
   本仓库根目录的 ruff 与 pytest 不覆盖它（`extend-exclude` / `testpaths`），另设 CI 作业 `factory` 跑它自己的单元测试与
   网页打包（沿用 wenquest 的 factory 工作流中的测试作业；真 ERPNext 演练作业后续再加）
3. **本地运行版**（第二个 PR）
   - 一条命令启动：`factory/local/start.sh` / `start.ps1`（Windows 上用 Docker Desktop），缺省用模拟 ERPNext，
     想接真 ERPNext 按说明另起
   - 缺省“演示”（仿真车间在跑、看板有数据；生产模式在没有接入真实设备时是空的），`--prod` 启动生产模式；工作台显示“本地版”
     （2026-10-06 实施时修订：原写缺省生产模式）
   - 去掉对 wenquest 服务器部署的依赖（域名、Caddy、远程备份）：这些脚本保留在 `factory/deploy/`，本地版不用
4. **CAD ↔ 工厂衔接**（第三个 PR 起）
   - FreeCAD“发布到工厂”：把当前方案的 BOM（零件来自公共库或企业库，带来源）和零件 STEP 发到本地工厂枢纽，
     在工厂里成为物料与设计版本（原 `wq_publish.py` 宏的做法：经数据总线发布）
   - 工厂的零件选型用本仓库的零件库（公共库 + 企业库）：本地版把 `data/library` 与企业库文件夹只读挂进枢纽，
     “选型零件库”页与 `/api/fap/components` 列出，企业库同 id 覆盖公共库；参数照原样（值、条件、出处），不换算、不补缺。
     （2026-10-06 实施时修订：原写“替换 `WQ_LIBRARY_DIR`”。那份是标准件与机器人库，内容不同，保留并列；企业库文件夹
     取 `FAP_ENTERPRISE_LIBRARY` 或 FreeCAD 设置里选的，与 FreeCAD 同一个）
   - 数字孪生的现场数据：`/api/twin/units/<序列号>/records.csv` 把设备每天的运行摘要导出为 `analysis/twin` 的运行记录 CSV
     （运行小时、输出平均 / 最大扭矩、输入转速）；`analysis/twin` 相应接受 `input_speed_rpm`，有就直接用，不再由输出转速乘减速比
   - 计算重复：工厂计算服务（cae）与 `analysis/` 的同类模块以后合并为一份（另写 ADR）；在此之前两份都保留，
     各自有标准题
5. **规则适用范围**：本仓库的数据规则（不编造参数、来源登记）对进入零件库的数据照常适用；工厂里的演示工厂数据
   （问渠减速器厂、WQR-105）是虚构的演示数据，界面与文档标明“演示”

## 理由

- 整套搬入能最快给企业一套完整的“设计—工艺—生产—运维”本地环境，原代码已在服务器上跑通、有测试
- 原样搬入再逐步改，改动可追溯；先改接口（发布、零件库、孪生数据），不重写

## 后果

- 本仓库体积增加约 5 MB；CI 多一个作业（求解器、OpenFOAM、网页打包，较慢）
- 工厂代码的风格（单位、中文注释、测试方式）与本仓库主体不同，按子项目对待
- ERPNext 是 GPL 软件，本地版以独立容器运行官方镜像，不改其代码
