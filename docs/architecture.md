- 版本：V0.1（2026-09-30 定稿的讨论稿），2026-10-01 由在线版转存
- 作者：Guoqing (Eddie) Zhang
- 转存说明：内容与在线版一致；自转存起以本文件为准，在线版不再维护。实现中的补充决定见 `docs/adr/`，本文只在末尾“实现进展”一节列出索引

## 定位与设计原则

系统的核心是一个**组件知识库加系统配置引擎**，FreeCAD 是它的空间视图。AI 的任务不是画零件，而是把厂商零件当作黑箱，选型、组合、校验并装配成系统。

1. **零件即黑箱**：每个零件只描述端口（输入/输出）、性能参数和包络几何，不存厂商的精细模型。
2. **核心与视图分离**：选型推理和校验都在 FreeCAD 之外；FreeCAD 负责摆放、对齐和干涉检查。将来可接入其他 CAD、仿真工具或 ERP。
3. **LLM 提议，确定性程序校验**：LLM 负责理解需求、检索候选和解释结果；接口匹配和性能计算由规则引擎完成，结果可复现。
4. **V1 只做静态匹配**：接口尺寸、扭矩/转速链、电气与协议一致性；schema 预留动态参数字段，供后续接入仿真。
5. **数据合规**：参数和元数据入库，包络几何自己生成，原厂模型只保留链接；每条数据记录来源和许可。
6. **对齐现有标准**：端口类型库用自定义轻量 JSON schema，概念上对应 SysML v2 并提供导出，机器人可导出 URDF，仿真预留 FMI 接口。
7. **领域顺序**：机器人先行；航空只做标准件（AN/MS/NAS）；汽车后置。

## 五层架构总览

系统分五层，数据自下而上流动，调用自上而下。中间的知识库和配置引擎是核心，不依赖 FreeCAD。

| 层 | 名称 | 内容 | 仓库目录 |
| --- | --- | --- | --- |
| L5 | 应用与视图 | FreeCAD 工作台（对话面板、包络装配、干涉检查）；外部 MCP 客户端 | `freecad_addon/` |
| L4 | 服务接口 | MCP 工具 + REST | `mcp_server/` |
| L3 | 系统配置引擎 | 需求解析、候选求解、性能链计算、规则校验、方案解释 | `engine/` |
| L2 | 组件知识库 | 组件、参数、端口类型、连接规则、向量索引 | `kb/` |
| L1 | 数据采集 | 来源登记、规格书解析、归一化、人工复核 | `ingest/` |

上层只通过 MCP 工具访问核心；换一个 CAD 或接入 ERP，只需新增视图层，核心不动。

## 核心数据模型：组件 = 端口 + 参数 + 包络

全系统围绕四个对象：组件、端口、连接规则、系统。端口是关键，它把“能不能装在一起”变成可计算的问题。

| 对象 | 主要字段 | 说明 |
| --- | --- | --- |
| 组件 Component | 品类、厂商、型号、参数表、端口列表、包络、来源与许可、原厂链接 | 一个厂商型号或一个标准件规格 |
| 参数 Parameter | 名称、数值或范围、单位、来源、置信度、静态/动态标记 | 如额定扭矩、减速比、质量、转动惯量 |
| 端口 Port | 类型（机械/电气/信号/流体/热）、方向（输入/输出/双向）、坐标系（位置+朝向）、接口规格 | 如法兰：分度圆直径、孔数、孔径；轴：直径、键槽 |
| 包络 Envelope | 基本体（圆柱/长方体/组合）参数、各端口在包络上的安装坐标系 | 用于 FreeCAD 布局和干涉检查 |
| 连接规则 Rule | 端口类型对 → 兼容性检查函数 | 如“轴 ↔ 孔”比较直径与公差，“协议 ↔ 协议”比较名称与版本 |
| 系统 System | 组件实例、连接关系、需求指标、校验结果 | 一个关节模组、一台机器人的设计方案 |

字段级定义见 `schema/` 与实施细则第四至六节。端口类型库是整个项目最值得投入的资产：类型定义得越准，自动匹配就越可靠。

## AI 在各层的角色：什么是 AI 原生

AI 原生指每一层都为 agent 设计：数据是 agent 能读的结构，操作是 agent 能调的工具，结果能回馈给 agent 自查。聊天窗口只是入口之一。

| 层 | AI 做什么 | 确定性程序做什么 |
| --- | --- | --- |
| 数据采集 | 从 PDF 规格书抽取参数和端口，标注置信度，归入品类 | 单位换算、范围校验、去重 |
| 组件知识库 | 语义检索、同类替代推荐 | 结构化查询、端口兼容索引 |
| 配置引擎 | 把自然语言需求变成约束，提议候选组合，解释取舍 | 约束求解、性能链计算、接口校验 |
| FreeCAD 视图 | 决定摆放顺序，读干涉结果和截图后调整 | 包络生成、按端口坐标系对齐、干涉检测 |
| 输出 | 生成方案说明和选型理由 | BOM、URDF、校验报告 |

分工的底线：凡是影响“能不能用”的判断，都必须有确定性校验兜底，LLM 不单独拍板。

## MCP 工具清单（V1）

V1 对 agent 暴露 10 个工具，分两组：知识库与配置引擎组不依赖 FreeCAD，FreeCAD 组需要运行中的 FreeCAD 会话。

| 工具 | 组 | 输入 | 输出 |
| --- | --- | --- | --- |
| `search_components` | 知识库 | 自然语言或结构化筛选 | 候选组件列表 |
| `get_component` | 知识库 | 组件 id | 完整参数、端口、包络 |
| `find_compatible` | 知识库 | 组件 id + 端口 id | 能连到该端口的组件 |
| `compose_chain` | 配置引擎 | 需求指标（扭矩、转速、尺寸限制等）+ 链路模板 | 排序后的候选组合 |
| `verify_system` | 配置引擎 | 系统定义 | 逐项校验结果与失败原因 |
| `place_component` | FreeCAD | 组件 id + 位姿 | 文档中的包络对象 |
| `connect_ports` | FreeCAD | 两个端口 | 对齐后的装配约束 |
| `check_interference` | FreeCAD | 当前文档或对象列表 | 干涉对与重叠体积 |
| `snapshot` | FreeCAD | 视角 | 截图，供 agent 自查 |
| `export_system` | 输出 | 格式（BOM / URDF / JSON） | 文件 |

在 V1 里刻意不提供“执行任意 Python”的工具。现有 FreeCAD MCP 项目大多依赖它，灵活但不可控；类型明确的工具更容易校验和审计。

## 典型流程：机器人关节模组选型与装配

用户在 FreeCAD 里说：“给六轴机械臂的第 2 关节选一套驱动，输出转速和扭矩要求如下，外径不超过某值。”一次完整的流程是：

1. **需求解析**：agent 把话转成约束（输出扭矩、转速、外径、电压、总线协议），缺失的关键指标先问用户。
2. **链路模板**：选用“电机 → 减速器 → 输出法兰 + 驱动器 + 编码器”模板。
3. **候选组合**：`compose_chain` 在知识库里求解，按质量、尺寸、裕度排序，返回前几套。
4. **校验**：`verify_system` 逐项检查轴孔匹配、法兰孔位、扭矩 × 减速比 × 效率、转速范围、电压和协议；不通过则回到第 3 步。
5. **布局**：用户选定一套后，`place_component` 和 `connect_ports` 在 FreeCAD 里按端口坐标系摆好包络。
6. **空间检查**：`check_interference` 和 `snapshot` 把结果回传给 agent；有干涉则调整位姿或换候选。
7. **输出**：`export_system` 生成 BOM 和选型说明，附各零件原厂模型链接。

## 初步技术选型

全栈以 Python 为主，和 FreeCAD 的脚本环境一致；存储先用一个 PostgreSQL 解决结构化、关系和向量三种需求，避免过早引入图数据库。

| 组件 | 建议 | 备注 |
| --- | --- | --- |
| FreeCAD 插件 | FreeCAD 1.x Workbench（Python + Qt） | 含 AI 对话面板、零件面板；装配用 1.0 起的内置 Assembly 工作台 |
| MCP 服务端 | FastMCP | 同时提供 REST，供非 MCP 客户端使用 |
| 存储 | PostgreSQL + pgvector | 参数表用 JSONB；端口兼容先用关系表，需要时再评估图扩展 |
| 单位处理 | pint | 所有参数入库前归一化 |
| 约束求解 | V1 筛选 + 排序；必要时 OR-Tools CP-SAT | 链路短时筛选即足够 |
| 规格书解析 | PDF 文本/表格提取 + Claude API 结构化输出 | 按品类定义抽取 schema，低置信度进人工队列 |
| 包络生成 | FreeCAD Part 脚本，每品类一个参数化模板 | 输出包络 + 端口坐标系 |
| 导出 | BOM（CSV/Excel）、URDF、系统 JSON | 后续可加 SysML v2 导出 |

## V1 范围与里程碑

V1 的目标是跑通一个端到端演示：在 FreeCAD 里用自然语言完成机器人关节模组的选型、校验、布局和 BOM 输出。

**V1 范围**

- 品类：伺服电机、减速器（谐波/行星）、驱动器、轴承，每类 30–50 个型号、覆盖 3–5 家厂商；编码器作为电机端口处理；紧固件按 ISO/DIN 参数化生成；减速器只收录整机型；品牌间转接用 adapter 组件（轴套、适配法兰）
- 端口类型：轴、孔、法兰、安装面、电源、总线/编码器信号
- 校验：静态匹配（接口尺寸、扭矩转速链、电气与协议）
- 不在 V1：动态仿真、航空/汽车品类、多用户协作、ERP 对接

**里程碑**（按顺序，每步有验收标准）

1. **M1 模型定稿**：组件/端口/规则 schema 和端口类型库定稿；手工录入每类少量型号验证模型。验收：手工数据能表达一套完整关节。
2. **M2 数据流水线**：来源登记、规格书解析、归一化、人工复核队列。验收：抽样核对准确率达到设定门槛。
3. **M3 配置引擎**：链路模板、候选求解、校验器。验收：对已知正确的组合全部通过，对故意错配的组合全部拒绝。
4. **M4 MCP + FreeCAD 插件**：10 个工具先接外部 MCP 客户端验证，再做 FreeCAD 内置对话面板；包络模板、端口对齐、干涉检查。验收：agent 能独立完成布局并消除干涉。
5. **M5 端到端演示**：从一句需求到 BOM。验收：关节模组演示可重复跑通。

## 已定决策

六个待定问题已于 2026-09-30 全部定稿。

| 问题 | 决定 | 要点 |
| --- | --- | --- |
| 开源还是商业 | 开放核心 | schema、端口类型库、FreeCAD 插件、MCP 服务端开源；校验过的厂商数据服务和企业功能（私有零件库、选型审计、ERP 对接）商业化 |
| 端口类型库 | 自定义轻量 JSON schema | 概念上对应 SysML v2（端口定义、端口用法、接口）并提供导出，不直接采用其文本语法 |
| 用户入口 | 两者都要，先外后内 | 先用外部 MCP 客户端（如 Claude Desktop）验证工具设计，工具稳定后再做 FreeCAD 内置对话面板 |
| V1 品类与数量 | 4 类核心链路 | 伺服电机、减速器（谐波/行星）、驱动器、轴承；每类 30–50 个型号，覆盖 3–5 家厂商；编码器作为电机端口；紧固件按 ISO/DIN 参数化生成 |
| 首批数据来源 | 规格书规范、参数公开的厂商，国际与国产兼顾 | 候选：Harmonic Drive、绿的谐波、安川、汇川；入库前逐家核实使用条款；商业路线下直接联系厂商合作 |
| 与机器人学院的关系 | 共用组件库 | 学院作为独立使用方，通过 MCP/REST 接入，不左右 V1 范围 |

确认实施细则时（2026-09-30）另定三项，全部规则见 [实施细则](implementation-rules.md)。

| 问题 | 决定 | 要点 |
| --- | --- | --- |
| 减速器形态与转接 | 只收录整机型；新增 `adapter` 品类 | 不收录谐波减速器零件型；轴套、适配法兰作为独立组件（ADR-0007） |
| 校验默认值 | 安全系数 1.2，惯量比告警阈值 10 | 安全系数用户可改；惯量比只告警不判失败（ADR-0008） |
| 开发流程与进度 | `main` 受保护，全部改动走 PR；M1 提前至 10 月 5 日 | 实施细则入库为 `docs/implementation-rules.md`，AI 规则写入 `CLAUDE.md`（ADR-0009） |

**数据获取路线调整**（2026-09-30，ADR-0015）：候选厂商网站条款禁止未经书面许可复制和自动采集，因此真实厂商数据须先取得书面授权（或经人核实条款允许）才能入库；M1–M3 用虚构测试组件开发，同时向厂商请求授权。

**数据获取路线再调整**（2026-10-01，ADR-0040）：厂商公开发布的产品目录参数与接口尺寸可以收录，逐项注明出处、链接回厂商，不转存文档与模型，不批量爬取；许可明确的开源硬件设计同样收录。书面授权不再是入库前提。
